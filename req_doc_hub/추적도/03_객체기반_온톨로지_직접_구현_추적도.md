## 3. 구현 추적

### 3.1 기본 모델

`src_codex`:
- `src_codex/backend/models.py`
- `PropertyDefinition`
- `ObjectType`
- `ObjectInstance`

`src_anti`:
- `src_anti/backend/models.py`
- `Customer`
- `Order`
- `Product`
- `Document`

판단:
- `src_codex`: 구현됨
- `src_anti`: 부분 구현

### 3.2 관계 모델

`src_codex`:
- `RelationshipDefinition`
- `RelationshipInstance`

`src_anti`:
- 별도 관계 모델 없음
- `Order.customerId`, `Order.productIds` 필드로 관계 표현

판단:
- `src_codex`: 구현됨
- `src_anti`: 부분 구현

### 3.3 액션 모델

`src_codex`:
- `ActionDefinition`
- `WorkflowTransition`
- `WorkflowEvent`

`src_anti`:
- 별도 액션 모델 없음
- 문자열 액션 이름과 `WorkflowService.TRANSITIONS`로 처리

판단:
- `src_codex`: 구현됨
- `src_anti`: 부분 구현

### 3.4 레지스트리

`src_codex`:
- `src_codex/backend/ontology.py`
- `OntologyRegistry`
- `register_object_type()`
- `create_object()`
- `register_relationship_type()`
- `link()`
- `find_related()`

`src_anti`:
- 별도 온톨로지 레지스트리 없음
- `data.py`의 전역 Repository가 데이터 저장 역할

판단:
- `src_codex`: 구현됨
- `src_anti`: 미구현에 가까운 부분 구현

### 3.5 관계 탐색

`src_codex`:
- `OntologyRegistry.find_related()`
- `OntologyService.get_order_context()`

`src_anti`:
- `OntologyService.get_order_context()`

판단:
- `src_codex`: 구현됨
- `src_anti`: 부분 구현

## 4. 요약

`03` 문서의 직접 구현 요구는 `src_codex`에 거의 그대로 반영되어 있습니다. `src_anti`는 Pydantic DTO와 컨텍스트 조립으로 일부 개념을 대체하지만, 온톨로지 레지스트리 구조는 없습니다.
