# 팔란티어 온톨로지 개념

## 1. 온톨로지란 무엇인가

팔란티어에서 말하는 온톨로지는 기업의 데이터를 현실 세계의 업무 객체와 행동으로 연결하는 의미 계층입니다. 단순히 데이터베이스 테이블을 정리하는 것이 아니라, 조직이 실제로 사용하는 개념인 고객, 주문, 설비, 재고, 작업지시, 운송, 승인 같은 객체를 중심으로 데이터를 이해하고 실행할 수 있게 만듭니다.

전통적인 데이터 플랫폼은 데이터를 저장하고 분석하는 데 초점이 있습니다. 반면 온톨로지는 데이터를 업무 사용자가 이해할 수 있는 객체 모델로 바꾸고, 그 객체 위에서 권한, 정책, 워크플로, 애플리케이션, 자동화가 동작하도록 합니다.

## 2. 핵심 구성 요소

### 객체

객체는 현실 세계의 업무 단위를 표현합니다.

예시:

- 고객
- 제품
- 공장
- 장비
- 항공기
- 부품
- 계약
- 배송
- 작업지시

객체는 여러 데이터 소스에 흩어진 정보를 하나의 의미 있는 단위로 묶습니다.

### 속성

속성은 객체가 가진 데이터입니다.

예시:

- 고객 이름
- 주문 금액
- 장비 상태
- 재고 수량
- 납기일
- 위험 등급

속성은 원천 데이터의 컬럼에서 올 수도 있고, 계산 로직이나 규칙에 의해 만들어질 수도 있습니다.

### 관계

관계는 객체 간 연결을 표현합니다.

예시:

- 고객은 주문을 생성한다
- 주문은 제품을 포함한다
- 제품은 부품으로 구성된다
- 장비는 공장에 설치되어 있다
- 작업지시는 장비를 대상으로 한다

관계가 생기면 사용자는 데이터 테이블 조인 대신 업무 언어로 탐색할 수 있습니다.

### 액션

팔란티어 온톨로지의 중요한 특징은 객체 위에서 행동을 정의할 수 있다는 점입니다.

예시:

- 주문 승인
- 재고 보충 요청
- 장비 점검 예약
- 위험 고객 플래그 지정
- 배송 우선순위 변경

액션은 단순한 버튼이 아니라 권한, 검증 규칙, 승인 흐름, 외부 시스템 연동을 포함할 수 있습니다.

## 3. 온톨로지가 해결하는 문제

### 데이터와 업무의 간극

많은 기업은 데이터를 많이 가지고 있지만, 실제 업무자는 데이터베이스 구조를 알기 어렵습니다. 온톨로지는 데이터 구조를 업무 언어로 번역합니다.

### 분석과 실행의 분리

분석 결과가 나와도 실제 업무 시스템에 반영하려면 별도 절차가 필요합니다. 온톨로지는 분석, 의사결정, 실행을 같은 객체 모델 위에 올립니다.

### 사일로 문제

ERP, CRM, MES, SCM, 데이터웨어하우스 등 여러 시스템에 나뉜 데이터를 객체 중심으로 연결합니다.

### 권한과 거버넌스

온톨로지 계층에서 객체, 속성, 액션 단위로 권한을 관리할 수 있습니다. 사용자는 필요한 업무 맥락만 보고 실행할 수 있습니다.

## 4. 일반 데이터 모델과의 차이

| 구분 | 일반 데이터 모델 | 온톨로지 |
| --- | --- | --- |
| 중심 단위 | 테이블, 컬럼 | 객체, 관계, 액션 |
| 사용자 | 데이터 엔지니어, 분석가 | 업무 사용자, 분석가, 개발자 |
| 목적 | 저장, 조회, 분석 | 이해, 실행, 자동화 |
| 표현 방식 | 기술적 스키마 | 업무 의미 모델 |
| 실행성 | 낮음 | 높음 |

## 5. 간단한 예시

제조 기업의 장비 관리 온톨로지를 생각해 볼 수 있습니다.

객체:

- 장비
- 공장
- 센서
- 작업지시
- 부품

관계:

- 장비는 공장에 속한다
- 장비는 센서를 가진다
- 작업지시는 장비를 대상으로 한다
- 장비는 부품으로 구성된다

속성:

- 장비 상태
- 최근 점검일
- 온도
- 진동 수치
- 고장 위험 점수

액션:

- 점검 요청 생성
- 부품 교체 지시
- 장비 가동 중지
- 담당자에게 알림 발송

이 구조가 만들어지면 사용자는 "고장 위험이 높은 장비 중 핵심 생산 라인에 있는 장비를 찾아 점검 요청을 생성"하는 업무를 하나의 흐름으로 처리할 수 있습니다.

## 6. 설계 시 고려 사항

온톨로지를 설계할 때는 먼저 데이터가 아니라 업무 객체를 식별해야 합니다.

좋은 질문:

- 조직이 매일 다루는 핵심 명사는 무엇인가?
- 의사결정은 어떤 객체를 기준으로 이루어지는가?
- 객체 사이의 중요한 관계는 무엇인가?
- 사용자가 실제로 실행해야 하는 행동은 무엇인가?
- 어떤 속성은 원천 데이터이고, 어떤 속성은 계산되어야 하는가?
- 객체와 액션별 권한은 어떻게 달라져야 하는가?

## 7. 요약

팔란티어 온톨로지는 데이터를 현실 업무의 객체, 관계, 속성, 액션으로 재구성하는 의미 계층입니다. 핵심은 데이터를 보기 좋게 정리하는 것이 아니라, 데이터 위에서 업무를 이해하고 실행할 수 있게 만드는 것입니다.
