# 온톨로지 AI 업무화면 기획

## 1. 목표

이 문서는 온톨로지, BM25/RAG, 워크플로우를 하나의 업무 화면으로 구성하기 위한 기획안입니다.

목표는 단순한 챗봇 화면이 아니라, 사용자가 다음을 한 번에 확인하고 실행할 수 있는 업무형 AI 애플리케이션을 설계하는 것입니다.

- 업무 객체
- 객체 간 관계
- 문서 검색 근거
- AI 답변
- 승인/반려 같은 워크플로우 액션
- 실행 이력

## 2. 제품 컨셉

제품명 예시:

```text
Ontology Workbench
```

한 줄 설명:

```text
객체, 문서, AI 답변, 워크플로우를 연결하는 업무 의사결정 화면
```

핵심 사용자는 데이터 분석가보다 실제 업무 담당자에 가깝습니다.

- 영업 운영 담당자
- 주문 승인 담당자
- 고객 지원 담당자
- 리스크 검토 담당자
- 데이터/AI 플랫폼 운영자

## 3. 핵심 사용자 시나리오

### 시나리오 1: 주문 승인 판단

사용자가 질문합니다.

```text
C001 고객의 O001 주문을 승인해도 될까?
```

시스템은 다음을 수행합니다.

1. 질문에서 `C001`, `O001` 객체 식별
2. 온톨로지에서 고객과 주문 객체 조회
3. 고객과 주문의 관계 검증
4. 관련 정책/계약/지원 문서 검색
5. RAG 컨텍스트 생성
6. 승인 가능 여부 답변
7. 가능한 워크플로우 액션 표시

### 시나리오 2: 객체 중심 탐색

사용자가 `Customer C001`을 선택합니다.

화면은 다음 정보를 보여줍니다.

- 고객 기본 정보
- 연결된 주문
- 연결된 문서
- 위험 등급
- 최근 워크플로우 이벤트
- 실행 가능한 액션

### 시나리오 3: 문서 근거 확인

AI가 답변을 생성한 뒤, 사용자는 근거 문서를 확인합니다.

화면은 다음을 보여줍니다.

- 검색된 문서 제목
- BM25 점수
- 관련 문장
- 연결된 객체
- 답변에 사용된 근거 여부

## 4. 정보 구조

추천 메뉴 구성은 다음과 같습니다.

```text
대시보드
객체 탐색
AI 질의
문서 검색
승인 워크플로우
온톨로지 관리
설정
```

## 5. 메뉴별 기능

| 메뉴 | 주요 기능 |
| --- | --- |
| 대시보드 | 승인 대기, 위험 고객, 최근 이벤트, 검색 사용 현황 |
| 객체 탐색 | Customer, Order, Product 객체 조회와 관계 탐색 |
| AI 질의 | 자연어 질문, 객체 식별, RAG 답변, 근거 확인 |
| 문서 검색 | BM25 검색, 문서 상세, 객체 연결 |
| 승인 워크플로우 | 승인 대기 큐, 승인/반려/보류 액션, 이력 |
| 온톨로지 관리 | 객체 타입, 속성, 관계, 액션 정의 |
| 설정 | 검색 파라미터, 프롬프트, 역할/권한 |

## 6. 화면 레이아웃

기본 레이아웃은 업무형 애플리케이션 구조를 사용합니다.

```text
┌──────────────────────────────────────────────┐
│ 상단 바: 현재 업무 컨텍스트, 사용자, 상태     │
├──────────────┬─────────────────┬─────────────┤
│ 좌측 메뉴    │ 중앙 작업 영역  │ 우측 패널   │
│              │                 │             │
│ 대시보드     │ 목록/상세/질의  │ 객체 컨텍스트│
│ 객체 탐색    │                 │ 문서 근거   │
│ AI 질의      │                 │ 액션        │
│ 문서 검색    │                 │ 이벤트      │
└──────────────┴─────────────────┴─────────────┘
```

우측 패널은 고정된 보조 영역으로 둡니다. 사용자가 어떤 화면에 있든 선택된 객체, 문서 근거, 가능한 액션을 빠르게 확인할 수 있어야 합니다.

## 7. 대시보드 화면

목적:

- 오늘 처리해야 할 업무를 빠르게 파악
- AI와 온톨로지 시스템의 상태 확인

구성:

- 승인 대기 주문 수
- 고위험 고객 수
- 오늘 실행된 워크플로우 액션 수
- 최근 AI 질의
- 승인 대기 큐
- 최근 이벤트 타임라인

카드 예시:

```text
승인 대기 주문: 12
고위험 고객: 3
오늘 AI 질의: 48
처리 완료 액션: 21
```

## 8. 객체 탐색 화면

목적:

- 객체 중심으로 업무 데이터를 탐색

구성:

- 객체 타입 탭: Customer, Order, Product
- 객체 목록
- 객체 상세 속성
- 연결 관계
- 연결 문서
- 최근 이벤트

객체 상세 예시:

```text
Customer C001
Name: Alpha Manufacturing
Segment: Enterprise
Region: Seoul
Risk Tier: Low

Related Orders:
- O001 Submitted 3200
- O003 Approved 1200
```

## 9. AI 질의 화면

목적:

- 자연어 질문을 업무 의사결정으로 연결

구성:

- 질문 입력창
- 식별된 객체
- 온톨로지 컨텍스트
- 검색된 문서
- 생성된 답변
- 가능한 액션

화면 흐름:

```text
질문 입력
  -> 객체 식별
  -> 관계 검증
  -> 문서 검색
  -> 답변 생성
  -> 액션 선택
```

AI 답변 화면에는 답변만 표시하지 않고 반드시 근거 영역을 함께 보여주는 것이 좋습니다.

## 10. 문서 검색 화면

목적:

- 정책, 계약, 매뉴얼 문서를 검색하고 객체와 연결

구성:

- 검색어 입력
- BM25 검색 결과
- 문서 상세
- 관련 객체
- 답변 근거 표시

검색 결과 항목:

```text
Order Approval Policy
Score: 3.812
Related Objects: Order, Customer
```

## 11. 승인 워크플로우 화면

목적:

- 승인 대기 주문을 검토하고 상태를 변경

구성:

- 승인 대기 큐
- 주문 상세
- 고객 리스크 정보
- 관련 문서 근거
- 승인/반려/보류 버튼
- 실행 이력

액션:

- ApproveOrder
- RejectOrder
- HoldOrder
- RequestMoreInfo

버튼은 상태에 따라 활성/비활성 처리합니다.

## 12. 온톨로지 관리 화면

목적:

- 운영자가 객체 모델을 관리

구성:

- 객체 타입 목록
- 속성 정의
- 관계 타입 정의
- 액션 정의
- 워크플로우 전이 정의

초기 구현에서는 읽기 전용으로 시작하고, 이후 편집 기능을 추가하는 것이 좋습니다.

## 13. 우측 컨텍스트 패널

우측 패널은 이 애플리케이션의 핵심입니다.

표시 항목:

- 선택된 객체
- 연결 객체
- 검색 근거 문서
- 가능한 액션
- 최근 이벤트

예시:

```text
Selected Object
Order O001
Status: Submitted
Amount: 3200

Available Actions
- Approve
- Reject
- Hold

Evidence
- Order Approval Policy
- Enterprise Customer Contract Policy
```

## 15. 데이터 모델

프론트엔드 목 데이터는 다음 구조로 시작합니다.

```typescript
type Customer = {
  id: string;
  name: string;
  segment: string;
  region: string;
  riskTier: "Low" | "Medium" | "High";
};

type Order = {
  id: string;
  customerId: string;
  status: "Submitted" | "Approved" | "Rejected" | "Fulfilled" | "Closed";
  amount: number;
  productIds: string[];
};

type Document = {
  id: string;
  title: string;
  score?: number;
  text: string;
};

type WorkflowEvent = {
  id: string;
  objectId: string;
  action: string;
  fromStatus: string;
  toStatus: string;
  actor: string;
  occurredAt: string;
};
```

## 16. API 설계

Next.js 구현 시 다음 API를 생각할 수 있습니다.

| API | 설명 |
| --- | --- |
| `GET /api/objects/customers` | 고객 목록 |
| `GET /api/objects/orders` | 주문 목록 |
| `GET /api/objects/orders/:id` | 주문 상세 |
| `POST /api/ask` | AI 질의 처리 |
| `POST /api/search` | 문서 검색 |
| `POST /api/workflow/execute` | 워크플로우 액션 실행 |

초기 핸즈온에서는 API 없이 목 데이터를 사용하고, 이후 API Route로 확장합니다.

## 17. Next.js 사용 이유

Next.js는 이 화면에 잘 맞습니다.

- App Router로 화면 구조가 명확함
- API Route를 같은 프로젝트에 둘 수 있음
- React 컴포넌트로 업무 화면을 나누기 쉬움
- Tailwind CSS와 함께 빠르게 구현 가능
- 이후 실제 BM25/RAG API와 연결하기 좋음

## 18. MVP 범위

`07` 구현의 MVP는 다음 범위로 제한합니다.

- 대시보드
- 객체 탐색
- AI 질의
- 승인 워크플로우
- 우측 컨텍스트 패널
- 목 데이터 기반 동작

문서 검색과 온톨로지 관리는 첫 구현에서는 일부만 보여주고, 후속 확장으로 넘겨도 좋습니다.

## 19. 요약

온톨로지 AI 업무화면은 챗봇이 아니라 업무 의사결정 도구로 설계해야 합니다. 객체, 문서, AI 답변, 워크플로우 액션이 같은 화면에서 연결될 때 사용자는 답변의 근거를 확인하고 바로 실행까지 이어갈 수 있습니다.
