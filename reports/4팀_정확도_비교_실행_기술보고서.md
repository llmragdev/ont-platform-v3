최종 산출물:

- `E:\ai_lab_SIT\reports\4팀_정확도_비교.xlsx`

동일 24문항 기준 전체 정확도:

| 팀 | 정확도 | 순위 |
|---|---:|---:|
| Team1 | 71.77% | 1위 |
| Team4 (ont_platform v4) | 67.50% | 2위 |
| Team2 | 65.21% | 3위 |
| Team0 | 60.42% | 4위 |

중요: 이전에 산출된 `ont_platform v4 76.30%`는 기존 3팀 엑셀과 동일 문항 비교가 아니었다. 이번 보고서의 기준값은 동일 24문항 재평가 결과인 `67.50%`이다.

## 6. 평가 방식

### 6.1 질의 실행

`build_exact_4team_workbook.py`는 다음 순서로 실행된다.

1. `3팀_정확도_비교.xlsx`의 `문항별 비교 상세`에서 24개 질문과 예상 답변을 읽는다.
2. `E:\ai_lab_SIT\target_doc`의 PDF 8개를 ont_platform v4 프로젝트에 업로드한다.
3. FastAPI `TestClient`로 `/api/hybrid/ask`에 동일 24개 질문을 호출한다.
4. 각 응답의 답변, 응답시간, 검색 근거, vector hits를 저장한다.
5. Team4 답변을 예상 답변과 비교해 정확도 점수를 산출한다.
6. 기존 Team0~2 답변/점수와 Team4 결과를 합쳐 새 엑셀을 생성한다.

### 6.2 Team4 채점

Team4 정확도는 다음 방식으로 산출했다.

- 기본 채점자: Gemini LLM judge
- 입력:
  - 질문
  - 예상 답변
  - ont_platform v4 답변
- 출력:
  - `score`: 0~100점
  - `rationale`: 채점 근거
  - `missing`: 누락 또는 약점

Gemini judge가 JSON 파싱에 실패할 경우 fallback으로 예상 답변의 핵심어 포함률을 사용하도록 구현했다. 이번 결과 파일의 각 문항에는 `채점방식`이 함께 기록되어 있다.

주의: Team4 점수는 자동 채점값이다. 최종 승인 전에는 `문항별 비교 상세`에서 낮은 점수 또는 순위에 영향을 주는 문항을 표본 수동 검토하는 것이 좋다.

## 8. 76.30% 결과와의 관계

이전에 생성된 `ont_platform v4 정확도 76.30%`는 다음 경로의 30문항 단독 평가 결과였다.

- `E:\ontology_edu\X_ont_std\validation\ont_platform_v4_eval\results`

해당 평가는 기존 `3팀_정확도_비교.xlsx`의 24문항과 동일하지 않았다. 또한 자동 산식에서 검색 연관성 항목이 전 문항 높게 잡혀 점수가 낙관적으로 산출될 가능성이 있었다.

따라서 최종 4팀 비교에는 `76.30%`를 사용하지 않고, 동일 24문항 재평가 결과인 `67.50%`를 사용했다.

## 9. 주의사항

1. `3팀_정확도_비교.xlsx` 내부의 `팀별 요약` 평균과 `문항별 비교 상세` 점수 평균이 약간 다르다.
2. 이번 `4팀_정확도_비교.xlsx`는 사용자가 핵심으로 지정한 `문항별 비교 상세` 탭을 기준으로 평균을 재계산했다.
3. Team4는 `Team3`으로 명명하지 않았다. 사용자가 기존 Team3이 따로 있다고 했으므로 `Team4 (ont_platform v4)`로 표기했다.
4. 재실행 시 Gemini API 키가 필요하다. 스크립트는 `ont_platform\v3\.env`에서 `GEMINI_API_KEY` 또는 `GEMINI_API_KEY1~4`를 읽는다.
5. 재실행하면 `same24_team4_results.json`과 `4팀_정확도_비교.xlsx`가 새 결과로 덮어써진다.
