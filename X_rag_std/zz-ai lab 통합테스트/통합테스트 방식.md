## 3. 테스트 방식

### 3.1 테스트 데이터 매핑

```
tenant_id: "company_abc" (고정)

org_id (조직 계층):
  - 0100: 영업부 전체
  - 0101: 영업부 1팀
  - 0102: 영업부 2팀
  - 0200: HR부 전체
  - 0201: HR부 1팀
  - "": 전사 공유

project_code & category:
  - HR001 (인사/채용) → NLP 문서 일부
  - POLICY001 (규정/취업규칙) → 국방 문서
  - TECH001 (기술/ontology) → NLP 문서 대부분
```

### 3.2 테스트 단계

**Step 1) 환경 준비**
```bash
set VECTOR_DB_ENGINE=local_json
uvicorn app.main:app --port 8000 --reload
```

**Step 2) 단위 테스트**
```bash
pytest tests/ -v
```
→ 멀티테넌트, org_id 계층, 라우팅, 검색, 문서 관리 검증

**Step 3) 통합테스트**
```bash
python integration_test_ailab.py
```
→ 실제 PDF 업로드 및 RAG 검색 수행

**Step 4) 성능 비교** (향후)
```
- 온톨로지 기반: 의미 관계 파악 능력
- 전통 RAG: 검색 정확도, 속도
- BM25: 정확한 용어 매칭
- 스노우플레이크: 대규모 데이터 처리
```

### 3.3 성공 기준

| 항목 | 기준 | 현황 |
|------|------|------|
| 멀티테넌트 격리 | 다른 테넌트 데이터 보이지 않음 | ✅ 통과 |
| org_id 검색 | 권한 범위 내 문서만 조회 | ✅ 통과 |
| 문서 업로드 | 8개 PDF 모두 업로드 가능 | ✅ 준비됨 |
| 검색 정확도 | 관련 청크 상위 3개 이내 | ⚠️ 튜닝 필요 |
| 응답 시간 | 1초 이내 | ⚠️ 측정 필요 |
| 라우팅 | category_mid → 올바른 vector_db | ❌ 4개 실패 |
