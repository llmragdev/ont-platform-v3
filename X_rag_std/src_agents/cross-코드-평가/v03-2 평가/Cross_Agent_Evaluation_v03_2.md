## 🔍 2. 에이전트별 코드 평가

### 🌌 Antigravity: "운영 완성도의 정점"
- **평가**: 이론적인 RAG 구조를 넘어, 기업용 솔루션의 핵심인 **무중단 운영(Index Swap)**과 **실시간성(Streaming)**을 완벽히 결합했습니다.
- **핵심 강점**:
    - `AdminService`를 통한 `Index Swap` 패턴: 대규모 재색인 시 서비스 중단 없는 전환 가능.
    - SSE(Server-Sent Events) 기반 스트리밍: 사용자 체감 성능 극대화.
    - `asyncio.to_thread` 기반의 철저한 스레드 안전성 확보.

### 🤖 Claude: "표준 준수와 테스트의 모범"
- **평가**: RAG 표준 v1.3을 가장 교과서적으로 구현했으며, 특히 테스트 환경의 자동화와 격리도가 매우 뛰어납니다.
- **핵심 강점**:
    - `conftest.py`를 활용한 완벽한 Mocking 환경: 외부 의존성 없이 100% 테스트 가능.
    - 멀티테넌트 계층 구조(`org_id` Sentinel 등)의 정밀한 처리.
- **한계**: 상용 운영 시 필요한 인덱스 관리 유틸리티가 부족합니다.

### 💻 Codex: "설계 지향적 아키텍처"
- **평가**: 깔끔한 폴더 구조와 상세한 설계 문서를 보유하고 있으나, 실제 구현체에서 일부 표준 요건(X-Tenant-ID 필수화 등)이 여전히 과도기적 상태입니다.
- **핵심 강점**:
    - `RequestContext`를 통한 일관된 테넌트 정보 전달.
    - 벡터 라우팅 로직의 명확한 분리.
- **한계**: `Index Swap` 등 고급 운영 기능의 구현이 누락되어 있거나 설계 수준에 머물러 있습니다.

## 🚀 3. 개선 권고안 (Action Plan)

### ✅ Antigravity (나의 소스) — "운영 고도화"
1. **테스트 격리 (Mock Gateway)**: 현재 테스트가 실제 Gateway `/api/v1/embed`에 의존하고 있어 외부 장애 시 테스트가 실패합니다. `pytest-mock`을 도입하여 임베딩 호출을 stub화해야 합니다.
2. **벡터 어댑터 경계 정립**: 어댑터 내부에서 직접 임베딩을 호출하는 대신, `Pipeline` 레이어에서 임베딩을 생성하여 `embeddings=` 파라미터로 전달하는 표준 방식을 강화해야 합니다.
3. **ChromaDB 정식 지원**: 현재 `LocalJson` 위주인 저장소를 실제 대규모 운영을 위한 `Chroma` 어댑터로 확장 구현해야 합니다.

### 🛠️ Claude 개선안 — "운영 가용성 확보"
1. **Index Swap Utility 도입**: Antigravity의 `AdminService` 로직을 벤치마킹하여 무중단 인덱스 갱신 기능을 추가해야 합니다.
2. **Deprecation 관리**: 코드 내 산재한 `datetime.utcnow()`를 `datetime.now(timezone.utc)`로 교체하여 Python 최신 버전 호환성을 확보해야 합니다.
3. **Alembic 도입**: `create_all()` 방식에서 벗어나 실제 운영 환경용 마이그레이션 체계를 구축해야 합니다.

### 🛠️ Codex 개선안 — "구현 완성도 및 표준 동기화"
1. **표준 명칭 통일**: `X-Company-ID`를 표준인 `X-Tenant-ID`로 전면 교체하고 필수 헤더 검증(400 Error)을 강화해야 합니다.
2. **Async I/O 최적화**: 모든 파이프라인 구간에 `asyncio.to_thread`를 적용하여 FastAPI 이벤트 루프 블로킹을 원천 차단해야 합니다.
3. **SSE 스트리밍 강화**: 설계 단계의 스트리밍 기능을 Antigravity 수준으로 고도화하여 UX를 개선해야 합니다.
