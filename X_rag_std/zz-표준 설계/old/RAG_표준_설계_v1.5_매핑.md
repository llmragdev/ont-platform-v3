## 주요 구조 변경 이유

| 변경 | 이유 |
|------|------|
| §2.8 RAG 검색 → §4로 통합 | 검색(Retrieval)은 임베딩 유사도 매칭 과업이므로 §4 범주에 속함 |
| §2.9 Index Swap → §3으로 통합 | Index Swap은 벡터 DB 컬렉션 교체 운영 패턴 — 벡터DB 관리(§3)의 하위 |
| §2.5 + §2.10 → §5로 통합 | 메타데이터 스키마 정의(§2.5)와 메타데이터 CRUD API(§2.10)는 동일 도메인 |
| §2.6 분산 | OR 검색 정책은 §4(검색 동작 규칙), 헤더 검증은 §6(접근 통제)로 성격 분리 |
| §6 보류 처리 | 현재 구현은 테넌트/조직 격리까지; RBAC·RLS 등 세부 정책은 추후 설계 |
| §8 신설 (보류) | LLM 에이전트/오케스트레이션 연동 표준의 필요성을 선제적으로 섹션 예약 |
