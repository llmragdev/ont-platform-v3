# AI 에이전트 표준 아키텍처 설계 - 기초 가이드 (v1.0)

## 1. 개요
본 문서는 엔터프라이즈 AI 에이전트 구축 시 데이터의 일관성, 확장성, 추적 가능성을 보장하기 위한 표준 아키텍처의 기초 설계 방침을 정의합니다. 임베딩 파이프라인부터 벡터 데이터 관리, 메타데이터 표준화까지의 핵심 요소를 다룹니다.

## 2. 임베딩 대상 문서 관리 (Document Management)
데이터의 소스부터 가공 단계까지의 생명 주기를 체계적으로 관리합니다.

*   **물리적 격리**: 원본(Raw) 데이터와 임베딩을 위해 정제/청크된(Processed) 데이터를 분리 보관합니다.
*   **상태 추적**: 인덱싱 파이프라인 상의 상태(`PENDING`, `PROCESSING`, `COMPLETED`, `FAILED`)를 관리하여 대량 문서 처리의 안정성을 확보합니다.
*   **갱신 정책**: 원천 문서 수정 시 관련 벡터를 식별하여 교체하거나 버전을 상향하는 증분 업데이트(Incremental Update) 방식을 기본으로 합니다.

## 3. 벡터 DB 관리 체계 (Vector DB Governance)
모델과 용도에 따른 최적화된 벡터 저장 전략을 수립합니다.

*   **엔진 이중화 대응**:
    *   **ChromaDB**: 메타데이터 기반의 정밀한 필터링과 영구적인 지식 베이스 관리에 사용합니다.
    *   **FAISS**: 대규모 벡터셋의 고속 유사도 검색 또는 휘발성 세션 컨텍스트 관리에 활용합니다.
*   **컬렉션(Collection) 분리 방침**:
    *   **모델별 분리**: 임베딩 모델(예: OpenAI, Solar 등)의 차원이 다르므로 모델별 전용 컬렉션을 구성합니다.
    *   **테넌트별 분리**: 보안 및 멀티테넌트 지원을 위해 프로젝트/사용자 그룹 단위로 물리적 컬렉션을 분리합니다.

## 4. 벡터-문서 매칭 및 추적 (Mapping & Traceability)
AI 답변의 근거를 명확히 제시하기 위해 벡터와 원천 문서 간의 연결성을 유지합니다.

*   **고유 ID 체계**: `Document_ID`와 `Chunk_Index`를 결합한 고유 식별자를 통해 검색된 벡터의 원문 위치를 즉시 파악합니다.
*   **역매핑(Reverse Mapping)**: 벡터 검색 결과(Score 포함)에서 원문 텍스트와 주변 컨텍스트를 즉시 추출할 수 있는 매핑 레이어를 구축합니다.

## 5. 표준 메타데이터 포맷 (Standard Metadata Schema)
RAG(Retrieval-Augmented Generation) 성능 향상을 위한 필수 메타데이터 구조를 정의합니다.

| 필드명 | 데이터 타입 | 필수 여부 | 설명 |
| :--- | :--- | :--- | :--- |
| `doc_id` | UUID/String | 필수 | 원천 문서의 고유 식별자 |
| `source_url` | String | 필수 | 파일 경로 또는 원본 URL |
| `created_at` | DateTime | 필수 | 문서 등록/최종 수정 시각 |
| `page_no` | Integer | 권장 | PDF/도서 내 페이지 번호 |
| `chunk_type` | String | 선택 | 텍스트, 표, 이미지 설명 등 청크 유형 |
| `tags` | Array | 선택 | 특정 업무/도메인 필터링용 태그 |

## 6. 오류 및 예외 처리 (Error & Exception Management)
시스템 안정성과 사용자 피드백을 위해 표준화된 오류 메시지 체계를 사용합니다.

*   **표준 오류 코드**:
    *   `ERR_PARSING`: 문서 로드 및 텍스트 추출 실패 시 발생.
    *   `ERR_EMBEDDING`: 외부/내부 임베딩 모델 API 호출 실패 시 발생.
    *   `ERR_VECTOR_SEARCH`: DB 연결 실패 또는 검색 시간 초과 시 발생.
*   **사용자 안내 가이드**: 시스템 장애와 데이터 부족(No-hits)을 명확히 구분하여 안내 메시지를 전달합니다.
