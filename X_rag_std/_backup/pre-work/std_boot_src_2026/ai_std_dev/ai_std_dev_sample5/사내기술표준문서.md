# HNIX 사내 기술 표준 및 운영 가이드라인

본 문서는 사내 개발 및 운영 환경의 일관성을 유지하고 보안 사고를 방지하기 위한 표준 규정입니다. 모든 임직원은 본 가이드를 준수해야 합니다.

---

## 1. 인프라 보안 표준 (Infrastructure Security)

사내 서버 및 내부 망 접근에 대한 기본 원칙은 '최소 권한 부여'입니다.

* **접근 제어:** 사내 서버에 접근하기 위해서는 반드시 2단계 인증(2FA)을 거쳐야 합니다.
* **승인 절차:** 단순 계정 생성이 아닌, 실제 접속 권한은 보안팀의 사전 승인이 필수입니다.
* **운영 방침:** 승인되지 않은 외부 IP에서의 접근은 원천 차단되며, 모든 접속 기록은 실시간으로 모니터링됩니다.

---

## 2. 소프트웨어 배포 절차 (Deployment Process)

코드의 품질 유지와 안정적인 서비스 운영을 위해 다음과 같은 파이프라인을 준수합니다.

* **코드 리뷰:** 모든 코드는 메인 브랜치 병합 전 최소 2인 이상의 시니어 개발자 코드 리뷰를 거쳐야 합니다.
* **배포 자동화:** 리뷰가 완료된 코드는 반드시 승인된 CI/CD 파이프라인을 통해서만 배포됩니다.
* **롤백 전략:** 배포 직후 장애 발생 시 5분 이내에 이전 버전으로 복구할 수 있는 환경을 상시 유지합니다.

---

## 3. 데이터베이스 설계 원칙 (Database Standard)

데이터 정합성과 확장성을 위해 다음의 설계 표준을 따릅니다.

* **정규화 규칙:** 관계형 DB 사용 시 모든 테이블은 기본적으로 제3정규형(3NF)을 준수하여 설계해야 합니다.
* **성능 최적화:** 대량의 데이터를 다루는 테이블에 인덱스를 생성하거나 변경할 경우, 실행 계획 분석 후 DBA의 검토를 거쳐야 합니다.
* **명명 규칙:** 모든 테이블과 컬럼명은 사내 표준 명명 규칙(Snake Case 등)을 엄격히 적용합니다.

---

## 4. 로그 관리 및 보안 규정 (Logging & Privacy)

장애 대응 및 보안 감사를 위해 로그는 정해진 규정에 따라 관리됩니다.

* **보관 주기:** 모든 API 호출 로그는 중앙 로깅 시스템(ELK 스택 등)을 통해 최소 90일간 보관됩니다.
* **개인정보 보호:** 로그 출력 시 전화번호, 이메일, 계좌번호 등 개인정보가 포함된 데이터는 마스킹 처리가 의무화됩니다.
* **민감 정보:** 로그 파일에 평문 비밀번호나 API 키를 직접 기록하는 행위는 엄격히 금지됩니다.

---

## 5. 네트워크 구성 표준 (Network Architecture)

네트워크 보안 강화를 위해 물리적/논리적 격리 원칙을 준수합니다.

* **환경 격리:** 개발 환경, 테스트 환경, 운영 환경은 가상 네트워크(VPC) 수준에서 완전히 격리되어야 합니다.
* **방화벽 설정:** 모든 인바운드/아웃바운드 트래픽은 최소 권한 원칙(Least Privilege)에 따라 필요한 포트만 개방합니다.
* **VPN 사용:** 사외에서 내부 망에 접속할 경우 반드시 지정된 사내 VPN을 통해서만 접근이 가능합니다.
