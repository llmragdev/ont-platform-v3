## 구현 범위

### 1. Next.js 프로젝트 설정 파일 (신규 생성)

기존 `src_nextjs/`에 설정 파일이 없어 빌드 불가 상태였음. 전체 설정 파일 생성:

| 파일 | 역할 |
|------|------|
| `next.config.mjs` | API 프록시 (`/api/*` → `localhost:8000/api/*`) |
| `tsconfig.json` | TypeScript 설정 |
| `tailwind.config.js` | Tailwind CSS 콘텐츠 경로 |
| `postcss.config.js` | PostCSS 설정 |
| `src/app/layout.tsx` | App Router 루트 레이아웃 |
| `src/app/globals.css` | Tailwind 지시자 |

### 2. API 클라이언트 (신규)

`src_nextjs/src/lib/api.ts`

- `DEFAULT_TENANT` — 기본 테넌트 설정 (companyId, projectId, role)
- `checkHealth()` — 백엔드 연결 확인 (3초 타임아웃)
- `fetchWorkflowQueue(cfg)` — 워크플로우 큐 조회
- `executeWorkflowAction(cfg, docId, entityId, action)` — 액션 실행
- `hybridAsk(cfg, question)` — AI 질의
- `fetchOntologyDocs(cfg)` — 온톨로지 문서 목록
- `fetchEntities(cfg, docId)` — 엔티티 목록
- `createEntity(cfg, docId, entity)` — 엔티티 생성
- `seedDemoData(cfg)` — 데모 Order 엔티티 3개 생성

모든 함수는 x-user-id, x-company-id, x-project-id, x-role 헤더를 자동 첨부.

### 3. page.tsx 전면 개편

`src_nextjs/src/app/page.tsx`

**v1.0 → v2.0 변경 사항:**

| 항목 | v1.0 | v2.0 |
|------|------|------|
| 데이터 소스 | mock-data.ts 고정 | 백엔드 API 우선, mock 폴백 |
| 백엔드 상태 | 없음 | LIVE / DEMO 인디케이터 |
| 엔티티 형식 | Order 고정 | DisplayOrder (백엔드 제네릭 엔티티 호환) |
| 워크플로우 | 로컬 상태 변경 | 백엔드 execute → queue 자동 갱신 |
| AI 질의 | 로컬 키워드 검색 | /api/hybrid/ask POST |
| 사이드바 | 메뉴만 | 메뉴 + 테넌트 설정 표시 |
| 데모 시드 | 없음 | 백엔드 빈 상태 시 "데모 데이터 생성" 버튼 |
| 오류 처리 | 없음 | actionError 표시, 로딩 상태 |

**동작 흐름:**
1. 마운트 시 `checkHealth()` → backendStatus 설정
2. online: `fetchWorkflowQueue()` → DisplayOrder[] 로드
3. offline: mock-data → DisplayOrder[] 변환 (DEMO 배너 표시)
4. 백엔드 온라인 + 데이터 없음 → "데모 데이터 생성" 버튼 노출
5. 워크플로우 액션 실행 후 큐 자동 갱신
