## Phase별 세부 계획

### Phase 1 — 데이터 준비 (25분)

```
Step 1-1. PDF 업로드 (curl 스크립트 실행)
          확인: GET /api/documents → 목록에 있는지
          확인: vector_db 청크 수 > 0

Step 1-2. 온톨로지 스키마 확장
          추가: PROGRAM (budget, year, quota 속성)
          추가: DIVISION (quota_2025, quota_2024, target 속성)

Step 1-3. 엔티티 시드 스크립트 작성 + 실행
          대상: ai-voucher-2025 네임스페이스
          수량: 22개 엔티티
          타입: PROGRAM(2), ORGANIZATION(9), CATEGORY(4), METRIC(4), EVENT(3)

Step 1-4. qa_dataset.json 파일 생성
          위치: test_data/ai-voucher-2025/qa_dataset.json
          케이스: 25개 (온톨로지 7 / 벡터 9 / 하이브리드 6 / 경계 3)
```

### Phase 2 — Backend (30분)

```
Step 2-1. app/api/integration_test.py 신규 작성
          - 데이터셋 로드 함수
          - hybridAsk 호출 래퍼
          - 소스 판정 로직 (ontology_hits / vector_hits 기반)
          - 키워드 매칭 + forbidden_keywords 검사
          - 결과 JSON 저장

Step 2-2. 4개 엔드포인트 구현
          POST /api/integration-test/run
          GET  /api/integration-test/projects
          GET  /api/integration-test/{project}/runs
          GET  /api/integration-test/{project}/runs/{run_id}

Step 2-3. main.py 라우터 등록 (2줄)
```

### Phase 3 — Frontend (30분)

```
Step 3-1. api.ts에 통합 테스트 API 추가 (5개 함수)

Step 3-2. IntegrationTestRunner.tsx 신규 작성
          - 프로젝트 선택 드롭다운
          - 테스트 실행 버튼 + 진행 상태 표시
          - 실행 이력 목록 (pass율, 소요시간)
          - 케이스별 카드 (소스 배지, pass/fail, 답변, 증거)
          - 필터 (전체/온톨로지/벡터/하이브리드, 통과/실패)

Step 3-3. page.tsx 메뉴 + 라우팅 추가
          사이드바 "운영" 섹션에 "통합 테스트" 메뉴 추가
```

### Phase 4 — 검증 (20분)

```
Step 4-1. 테스트 실행 → 결과 JSON 확인
Step 4-2. 실패 케이스 원인 분류
          유형 A: 소스 불일치 (엔티티 미등록)
          유형 B: 키워드 불일치 (표현 변환)
          유형 C: 환각 감지 (Q025 필수 통과 확인)
Step 4-3. 필요 시 엔티티/키워드 보완 후 재실행
```
