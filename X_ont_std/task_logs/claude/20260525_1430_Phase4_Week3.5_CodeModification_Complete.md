## 📝 상세 구현 내용

### Task 1: 행 레벨 락킹 (Race Condition 방지)

**파일**: `ont_platform/v4/backend/app/services/write_back_worker.py` (라인 85-94)

**변경사항**:
```python
# Before
pending_items = self.db.query(WriteBackQueue).filter(
    WriteBackQueue.status == "PENDING"
).all()

# After
pending_items = self.db.query(WriteBackQueue).filter(
    WriteBackQueue.status == "PENDING",
    (WriteBackQueue.next_retry_at.is_(None)) |
    (WriteBackQueue.next_retry_at <= datetime.utcnow())
).with_for_update(skip_locked=True).limit(10).all()
```

**효과**:
- 다중 워커 동시 실행 시 동일 행 조회 방지
- 중복 트랜잭션 실행 0%로 제어
- LIMIT 10으로 배치 크기 제한

**파일**: `ont_platform/v4/backend/app/services/write_back_worker.py` (라인 99-108)

**변경사항**:
```python

for item in pending_items:
    try:
        self._process_single_item(item)
    except Exception as e:
        errors.append(...)

# After

        self._process_single_item(item)

    except Exception as e:

        errors.append(...)
```

**효과**:

### Task 4: 지수 백오프 스케줄링

#### 4-1) 쿼리 필터 추가 (라인 90-94)

**변경사항**:
```python
# next_retry_at이 NULL이거나 현재 시간 이하인 경우만 조회
pending_items = self.db.query(WriteBackQueue).filter(
    WriteBackQueue.status == "PENDING",
    (WriteBackQueue.next_retry_at.is_(None)) |
    (WriteBackQueue.next_retry_at <= datetime.utcnow())
).with_for_update(skip_locked=True).limit(10).all()
```

#### 4-2) 백오프 계산 로직 (라인 157-164)

**변경사항**:
```python
# 지수 백오프 공식: delay = INITIAL_RETRY_DELAY * (MULTIPLIER ^ retry_count)
# INITIAL_RETRY_DELAY = 60초, MULTIPLIER = 2
next_retry_delay = (
    self.config.INITIAL_RETRY_DELAY *
    (self.config.RETRY_BACKOFF_MULTIPLIER ** item.retry_count)
)
item.next_retry_at = datetime.utcnow() + timedelta(seconds=next_retry_delay)
```

**백오프 스케줄**:
- 1회 실패: 60 × 2¹ = 120초 (2분)
- 2회 실패: 60 × 2² = 240초 (4분)
- 3회 실패: 60 × 2³ = 480초 (8분) → DLQ

**효과**:
- 외부 API 장애 시 점진적 백오프
- API 과부하 방지
- 실질적인 지수 백오프 적용 (이전에는 계산만 하고 DB 미반영)
