### 2. 각 API 상세 설계 내용

#### 3.2.1 문서 업로드 (POST /api/v1/documents/upload)
- 요청: file, category_large, category_mid, category_low(선택), project_code(선택)
- 응답: doc_id, file_name, pipeline_status(01), assigned_vector_db, created_at

#### 3.2.2 문서 목록 조회 (GET /api/v1/documents)
- 쿼리 파라미터: page, size, pipeline_status, category_large, category_mid, sort
- 응답: total, page, size, items[] (페이지네이션)

#### 3.2.3 문서 상태 조회 (GET /api/v1/documents/{doc_id})
- 경로 파라미터: doc_id
- 응답: 문서 메타데이터 전체 (org_id, dept_code, vector_db_id, version, timestamps, 생성/수정자)

#### 3.2.4 문서 재업로드 (PUT /api/v1/documents/{doc_id})
- 요청: file + 선택적 category 변경 필드
- 응답: doc_id(기존), file_name(새), pipeline_status(02), version(+1)

#### 3.2.5 문서 삭제 (DELETE /api/v1/documents/{doc_id})
- 경로 파라미터: doc_id
- 응답: doc_id, deleted_chunks (벡터 DB에서 삭제된 청크 수)

### 3. 메타데이터 표준화

17개 필드 정의 (필수/자동/선택):
- **WHAT 축** (지식 분류): category_large, category_mid, category_low
- **WHO 축** (접근 제어): tenant_id, org_id, dept_code
- **시스템 필드**: doc_id, file_name, vector_db_id, version, pipeline_status
- **타임스탬프**: created_at, updated_at, created_by, updated_by

### 4. 청킹 및 라우팅 표준

- **청크 크기**: 300~500 토큰/청크, 50~100 토큰 겹침
- **벡터 DB 라우팅**: category_mid 기준으로 자동 라우팅
  - 채용 → vdb_hr_recruit_01
  - 복리 → vdb_hr_welfare_01
  - 교육 → vdb_hr_training_01
  - 규정 → vdb_compliance_01
  - 기술 → vdb_tech_01

### 5. Word 문서 생성

`convert_to_word.py` 스크립트 실행:
- 입력: `RAG_표준_설계_v1.5_임베딩 대상 문서 관리.md`
- 출력: `RAG_표준_설계_v1.5_임베딩 대상 문서 관리.docx`
- 테이블, 제목 레벨, 코드 블록 자동 변환
