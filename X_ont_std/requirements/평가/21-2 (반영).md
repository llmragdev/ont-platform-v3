## 2. 상세 조치 내용

### 2.1 아키텍처 서비스 분리
`main.py`에 집중되어 있던 비즈니스 로직을 기능별 서비스 레이어로 완전히 분리하여 운영형 확장성을 확보했습니다.
- **OntologyService**: 온톨로지 컨텍스트 및 관계 탐색 담당.
- **SearchService**: BM25 엔진을 통한 비정형 데이터 검색 담당.
- **WorkflowService**: 업무 프로세스 상태 전이 및 유효성 검사 담당.
- **PolicyService**: 사용자 권한 및 데이터 보안 정책 담당.
- **AuditService**: 시스템 로그 및 거버넌스 기록 담당.

### 2.2 RAG(Retrieval-Augmented Generation) 고도화
단순한 `if-else` 분기 방식에서 벗어나 실제 검색 엔진의 동작 방식을 구현했습니다.
- 질문에서 대상 객체(Order, Customer)를 자동으로 식별합니다.
- 식별된 객체 간의 관계가 온톨로지 정의와 일치하는지 우선 검증합니다.
- 질문과 가장 연관성이 높은 정책 문서를 BM25 알고리즘으로 검색하여 답변의 근거(Evidence)로 활용합니다.

### 2.3 거버넌스 및 운영 안정성
엔터프라이즈 환경에서 필수적인 운영 요소를 코드로 구현했습니다.
- 모든 API 호출 및 중요 액션은 감사 로그에 기록되어 추적 가능합니다.
- 사용자의 역할(Admin, Viewer 등)에 따라 특정 데이터가 마스킹되거나 액션이 제한됩니다.
- UI 상에서 API 호출 실패 시 에러 메시지를 명확히 표시하고 로딩 상태를 지원합니다.

## 3. 향후 과제
- 실제 데이터베이스(Snowflake 등) 및 LLM API(OpenAI/Vertex AI)와의 연동 테스트.
- Playwright를 활용한 프론트엔드 E2E 자동 테스트 시나리오 추가.
