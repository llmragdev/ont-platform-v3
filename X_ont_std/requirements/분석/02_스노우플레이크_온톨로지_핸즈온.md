# 스노우플레이크 온톨로지 핸즈온

## 1. 목표

이 문서는 스노우플레이크 데이터를 기반으로 간단한 온톨로지 형태의 객체 모델을 만들어 보는 실습입니다. 팔란티어처럼 완전한 온톨로지 플랫폼을 구현하는 것이 아니라, 데이터웨어하우스 위에서 객체, 속성, 관계, 액션 개념을 어떻게 모델링할 수 있는지 이해하는 데 목적이 있습니다.

실습 주제는 고객 주문 관리입니다.

## 2. 예제 도메인

업무 객체:

- Customer
- Product
- Order
- OrderItem

관계:

- Customer는 여러 Order를 가진다
- Order는 여러 OrderItem을 가진다
- OrderItem은 Product를 참조한다

액션 예시:

- 주문 상태 변경
- 고액 주문 플래그 지정
- 고객 위험 등급 갱신

## 3. 데이터베이스와 스키마 생성

```sql
CREATE OR REPLACE DATABASE ONTOLOGY_EDU;
USE DATABASE ONTOLOGY_EDU;

CREATE OR REPLACE SCHEMA RAW;
CREATE OR REPLACE SCHEMA ONTOLOGY;
CREATE OR REPLACE SCHEMA APP;
```

역할:

- `RAW`: 원천 데이터
- `ONTOLOGY`: 객체와 관계를 표현하는 의미 계층
- `APP`: 업무 액션과 애플리케이션용 뷰

## 4. 원천 테이블 생성

```sql
USE SCHEMA RAW;

CREATE OR REPLACE TABLE CUSTOMERS (
    CUSTOMER_ID STRING,
    CUSTOMER_NAME STRING,
    SEGMENT STRING,
    REGION STRING,
    CREATED_AT DATE
);

CREATE OR REPLACE TABLE PRODUCTS (
    PRODUCT_ID STRING,
    PRODUCT_NAME STRING,
    CATEGORY STRING,
    UNIT_PRICE NUMBER(12, 2)
);

CREATE OR REPLACE TABLE ORDERS (
    ORDER_ID STRING,
    CUSTOMER_ID STRING,
    ORDER_DATE DATE,
    STATUS STRING
);

CREATE OR REPLACE TABLE ORDER_ITEMS (
    ORDER_ITEM_ID STRING,
    ORDER_ID STRING,
    PRODUCT_ID STRING,
    QUANTITY NUMBER(10, 0)
);
```

## 6. 객체 뷰 만들기

### Customer 객체

```sql
USE SCHEMA ONTOLOGY;

CREATE OR REPLACE VIEW CUSTOMER_OBJECT AS
SELECT
    CUSTOMER_ID AS OBJECT_ID,
    CUSTOMER_NAME,
    SEGMENT,
    REGION,
    CREATED_AT
FROM RAW.CUSTOMERS;
```

### Product 객체

```sql
CREATE OR REPLACE VIEW PRODUCT_OBJECT AS
SELECT
    PRODUCT_ID AS OBJECT_ID,
    PRODUCT_NAME,
    CATEGORY,
    UNIT_PRICE
FROM RAW.PRODUCTS;
```

### Order 객체

```sql
CREATE OR REPLACE VIEW ORDER_OBJECT AS
SELECT
    O.ORDER_ID AS OBJECT_ID,
    O.CUSTOMER_ID,
    O.ORDER_DATE,
    O.STATUS,
    SUM(OI.QUANTITY * P.UNIT_PRICE) AS ORDER_AMOUNT
FROM RAW.ORDERS O
JOIN RAW.ORDER_ITEMS OI
    ON O.ORDER_ID = OI.ORDER_ID
JOIN RAW.PRODUCTS P
    ON OI.PRODUCT_ID = P.PRODUCT_ID
GROUP BY
    O.ORDER_ID,
    O.CUSTOMER_ID,
    O.ORDER_DATE,
    O.STATUS;
```

## 7. 관계 뷰 만들기

```sql
CREATE OR REPLACE VIEW CUSTOMER_ORDER_RELATION AS
SELECT
    CUSTOMER_ID AS SOURCE_OBJECT_ID,
    ORDER_ID AS TARGET_OBJECT_ID,
    'CUSTOMER_PLACED_ORDER' AS RELATION_TYPE
FROM RAW.ORDERS;

CREATE OR REPLACE VIEW ORDER_PRODUCT_RELATION AS
SELECT
    OI.ORDER_ID AS SOURCE_OBJECT_ID,
    OI.PRODUCT_ID AS TARGET_OBJECT_ID,
    'ORDER_CONTAINS_PRODUCT' AS RELATION_TYPE,
    OI.QUANTITY
FROM RAW.ORDER_ITEMS OI;
```

## 8. 계산 속성 추가

고객별 주문 요약을 객체 속성처럼 사용할 수 있습니다.

```sql
CREATE OR REPLACE VIEW CUSTOMER_ENRICHED_OBJECT AS
SELECT
    C.OBJECT_ID,
    C.CUSTOMER_NAME,
    C.SEGMENT,
    C.REGION,
    COUNT(O.OBJECT_ID) AS ORDER_COUNT,
    COALESCE(SUM(O.ORDER_AMOUNT), 0) AS TOTAL_ORDER_AMOUNT,
    CASE
        WHEN COALESCE(SUM(O.ORDER_AMOUNT), 0) >= 5000 THEN 'High'
        WHEN COALESCE(SUM(O.ORDER_AMOUNT), 0) >= 1000 THEN 'Medium'
        ELSE 'Low'
    END AS CUSTOMER_VALUE_TIER
FROM CUSTOMER_OBJECT C
LEFT JOIN ORDER_OBJECT O
    ON C.OBJECT_ID = O.CUSTOMER_ID
GROUP BY
    C.OBJECT_ID,
    C.CUSTOMER_NAME,
    C.SEGMENT,
    C.REGION;
```

## 9. 액션 테이블 만들기

스노우플레이크에서 실제 액션은 외부 애플리케이션, 프로시저, 태스크, API 연동으로 구현할 수 있습니다. 여기서는 액션 요청을 기록하는 방식으로 단순화합니다.

```sql
USE SCHEMA APP;

CREATE OR REPLACE TABLE ACTION_REQUESTS (
    ACTION_ID STRING DEFAULT UUID_STRING(),
    OBJECT_TYPE STRING,
    OBJECT_ID STRING,
    ACTION_TYPE STRING,
    REQUESTED_BY STRING,
    REQUESTED_AT TIMESTAMP_NTZ DEFAULT CURRENT_TIMESTAMP(),
    PAYLOAD VARIANT,
    STATUS STRING DEFAULT 'Requested'
);
```

## 10. 주문 승인 액션 기록

```sql
INSERT INTO ACTION_REQUESTS (
    OBJECT_TYPE,
    OBJECT_ID,
    ACTION_TYPE,
    REQUESTED_BY,
    PAYLOAD
)
SELECT
    'Order',
    OBJECT_ID,
    'ApproveOrder',
    CURRENT_USER(),
    OBJECT_CONSTRUCT(
        'previous_status', STATUS,
        'order_amount', ORDER_AMOUNT
    )
FROM ONTOLOGY.ORDER_OBJECT
WHERE OBJECT_ID = 'O001';
```

## 11. 업무용 조회 뷰

```sql
CREATE OR REPLACE VIEW ORDER_REVIEW_QUEUE AS
SELECT
    O.OBJECT_ID AS ORDER_ID,
    C.CUSTOMER_NAME,
    C.CUSTOMER_VALUE_TIER,
    O.ORDER_DATE,
    O.STATUS,
    O.ORDER_AMOUNT
FROM ONTOLOGY.ORDER_OBJECT O
JOIN ONTOLOGY.CUSTOMER_ENRICHED_OBJECT C
    ON O.CUSTOMER_ID = C.OBJECT_ID
WHERE O.STATUS = 'Submitted'
ORDER BY O.ORDER_AMOUNT DESC;
```

조회:

```sql
SELECT * FROM APP.ORDER_REVIEW_QUEUE;
```

## 12. 실습 정리

이 실습에서는 스노우플레이크 위에 다음 개념을 구성했습니다.

- 원천 테이블
- 객체 뷰
- 관계 뷰
- 계산 속성
- 액션 요청 테이블
- 업무용 조회 큐

핵심은 데이터웨어하우스의 테이블을 그대로 노출하는 것이 아니라, 업무 사용자가 이해하는 객체와 관계 중심의 의미 계층을 만드는 것입니다.
