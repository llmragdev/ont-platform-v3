## 1. 현황 분석 — 변경 전 구조 이해

### 1.1 사용자 시스템 이중 구조 (핵심)

현재 코드에는 **사용자 시스템이 두 개** 존재한다. 이 두 시스템은 **역할이 다르므로 분리 유지**한다.

| 구분 | 기존 (워크플로우 데모) | 신규 (테넌트 관리) |
| --- | --- | --- |
| 데이터 출처 | `backend/app/data.py` 인메모리 | `backend/app/config/users.json` |
| 사용자 예시 | Admin, FinanceManager, Analyst | alice, bob, carol, dave |
| 역할 체계 | Admin / FinanceManager / Analyst / Viewer | admin / editor / viewer |
| API 경로 | `GET /api/users` (기존 유지) | `GET /api/tenant/users` (신규) |
| 용도 | 주문 승인 워크플로우 / 정책 엔진 | 문서·온톨로지 company 격리 / 편집 권한 |
| 프론트 컴포넌트 | 기존 `UserSwitcher` (select) | 신규 `TenantUserSwitcher` (드롭다운) |

> **원칙**: 기존 워크플로우 사용자 시스템은 건드리지 않는다. 신규 테넌트 시스템을 옆에 추가한다.

### 1.2 기존 프론트엔드 상태 관리 구조

```
layout.tsx          ← 현재 아무 context 없음. UserProvider 추가 위치
  └── page.tsx      ← 전체 앱 상태(users, currentUserKey 등)를 useState로 관리
        ├── UserSwitcher    ← props 기반 (기존 워크플로우용)
        ├── OntologyGraphEditor
        ├── OntologyInstanceEditor
        └── ...
```

신규 `UserContext`는 `layout.tsx`에 추가하고, 기존 `page.tsx`의 상태와 **독립적으로** 운용한다.

```typescript
export type TenantRole = "admin" | "editor" | "viewer";

export interface TenantUser {
  id: string;
  name: string;
  company_id: string;
  role: TenantRole;
  project_ids: string[];
  permission_override?: Partial<Permissions>;
}

export interface Permissions {
  can_edit_diagram: boolean;
  can_edit_ontology: boolean;
  can_upload_doc: boolean;
  can_delete_doc: boolean;
  can_manage_users: boolean;
  can_view_audit_log: boolean;
}

export interface Company {
  id: string;
  name: string;
  description: string;
}

export interface Project {
  id: string;
  company_id: string;
  name: string;
  description: string;
  created_by: string;
  created_at: string;
}

export interface UserContextValue {
  user: TenantUser | null;
  permissions: Permissions;
  company: Company | null;
  projects: Project[];
  currentProject: Project | null;
  switchUser: (id: string) => Promise<void>;
  switchProject: (id: string) => void;
}
```

### 4.2 `backend/app/vector_search.py` (또는 docs_registry 접근 코드)

`list_documents()` 반환 시 `company_id` 필드 fallback 처리 추가:

```python
def list_documents(self, company_id: str = "default") -> list[dict]:
    docs = self._load_registry()
    return [
        d for d in docs
        if d.get("company_id", "default") == company_id
    ]
```
