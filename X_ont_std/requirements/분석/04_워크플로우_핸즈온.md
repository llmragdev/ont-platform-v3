# 워크플로우 핸즈온

## 1. 목표

이 문서는 객체기반 온톨로지에서 워크플로우를 어떻게 표현하고 실행할 수 있는지 직접 구현해 보는 실습입니다. 워크플로우는 단순한 절차도가 아니라, 객체가 어떤 상태에서 어떤 액션을 통해 다음 상태로 이동할 수 있는지를 정의하는 모델입니다.

예제는 주문 승인 프로세스를 사용합니다.

## 2. 워크플로우의 핵심 개념

워크플로우는 다음 요소로 구성할 수 있습니다.

- 대상 객체 타입
- 상태 속성
- 액션
- 전이 규칙
- 실행 조건
- 실행 이력

주문 객체의 예:

```text
Submitted
  -> ApproveOrder
  -> Approved
  -> FulfillOrder
  -> Fulfilled
  -> CloseOrder
  -> Closed
```

반려와 취소를 포함하면 다음과 같습니다.

```text
Submitted
  -> ApproveOrder -> Approved
  -> RejectOrder  -> Rejected

Approved
  -> FulfillOrder -> Fulfilled
  -> CancelOrder  -> Cancelled

Fulfilled
  -> CloseOrder   -> Closed
```

## 3. 기본 객체 모델

먼저 객체 타입과 객체 인스턴스를 정의합니다.

```python
from dataclasses import dataclass, field
from datetime import datetime
from typing import Any, Callable


@dataclass
class ObjectType:
    name: str
    required_properties: set[str] = field(default_factory=set)


@dataclass
class ObjectInstance:
    object_id: str
    object_type: ObjectType
    values: dict[str, Any]

    def get_status(self) -> str:
        return self.values["status"]

    def set_status(self, status: str) -> None:
        self.values["status"] = status
```

이 실습에서는 워크플로우를 이해하는 것이 목적이므로 속성 타입 검증은 단순화합니다.

## 4. 액션 정의

액션은 객체에 대해 실행되는 업무 행동입니다.

```python
@dataclass
class ActionDefinition:
    name: str
    object_type: ObjectType
    handler: Callable[[ObjectInstance, dict[str, Any]], dict[str, Any]]

    def execute(
        self,
        target: ObjectInstance,
        payload: dict[str, Any],
    ) -> dict[str, Any]:
        if target.object_type.name != self.object_type.name:
            raise TypeError(
                f"{self.name} cannot run on {target.object_type.name}"
            )

        return self.handler(target, payload)
```

액션 핸들러는 상태 변경 외에 승인자, 사유, 처리 메모 같은 추가 값을 기록할 수 있습니다.

## 5. 워크플로우 전이 정의

전이는 특정 상태에서 특정 액션을 실행했을 때 다음 상태로 이동하는 규칙입니다.

```python
@dataclass
class WorkflowTransition:
    name: str
    object_type: ObjectType
    from_status: str
    action_name: str
    to_status: str
    condition: Callable[[ObjectInstance, dict[str, Any]], bool] | None = None

    def can_execute(
        self,
        target: ObjectInstance,
        payload: dict[str, Any],
    ) -> bool:
        if target.object_type.name != self.object_type.name:
            return False

        if target.get_status() != self.from_status:
            return False

        if self.condition is not None:
            return self.condition(target, payload)

        return True
```

조건을 사용하면 금액, 권한, 지역, 위험 등급 같은 업무 규칙을 넣을 수 있습니다.

## 6. 실행 이력 모델

워크플로우는 실행 이력을 남기는 것이 중요합니다. 누가, 언제, 어떤 액션을 실행했고 상태가 어떻게 바뀌었는지 추적해야 합니다.

```python
@dataclass
class WorkflowEvent:
    object_id: str
    action_name: str
    from_status: str
    to_status: str
    actor: str
    payload: dict[str, Any]
    occurred_at: datetime = field(default_factory=datetime.utcnow)
```

## 7. 워크플로우 엔진 구현

워크플로우 엔진은 액션과 전이를 등록하고, 실행 가능 여부를 확인한 뒤 상태를 변경합니다.

```python
class WorkflowEngine:
    def __init__(self) -> None:
        self.actions: dict[str, ActionDefinition] = {}
        self.transitions: list[WorkflowTransition] = []
        self.events: list[WorkflowEvent] = []

    def register_action(self, action: ActionDefinition) -> None:
        self.actions[action.name] = action

    def register_transition(self, transition: WorkflowTransition) -> None:
        self.transitions.append(transition)

    def get_available_actions(self, target: ObjectInstance) -> list[str]:
        available_actions = []

        for transition in self.transitions:
            if transition.can_execute(target, {}):
                available_actions.append(transition.action_name)

        return available_actions

    def execute(
        self,
        action_name: str,
        target: ObjectInstance,
        payload: dict[str, Any],
    ) -> dict[str, Any]:
        if action_name not in self.actions:
            raise ValueError(f"Unknown action: {action_name}")

        matching_transition = None

        for transition in self.transitions:
            if (
                transition.action_name == action_name
                and transition.can_execute(target, payload)
            ):
                matching_transition = transition
                break

        if matching_transition is None:
            raise ValueError(
                f"Action {action_name} is not allowed from {target.get_status()}"
            )

        from_status = target.get_status()
        action_result = self.actions[action_name].execute(target, payload)
        target.set_status(matching_transition.to_status)

        event = WorkflowEvent(
            object_id=target.object_id,
            action_name=action_name,
            from_status=from_status,
            to_status=matching_transition.to_status,
            actor=payload["actor"],
            payload=payload,
        )
        self.events.append(event)

        return {
            "object_id": target.object_id,
            "action": action_name,
            "from_status": from_status,
            "to_status": matching_transition.to_status,
            "action_result": action_result,
        }
```

## 9. 액션 핸들러 만들기

```python
def approve_order(
    order: ObjectInstance,
    payload: dict[str, Any],
) -> dict[str, Any]:
    order.values["approved_by"] = payload["actor"]
    order.values["approval_comment"] = payload.get("comment")

    return {
        "message": "Order approved",
        "approved_by": payload["actor"],
    }


def reject_order(
    order: ObjectInstance,
    payload: dict[str, Any],
) -> dict[str, Any]:
    order.values["rejected_by"] = payload["actor"]
    order.values["reject_reason"] = payload["reason"]

    return {
        "message": "Order rejected",
        "rejected_by": payload["actor"],
    }


def fulfill_order(
    order: ObjectInstance,
    payload: dict[str, Any],
) -> dict[str, Any]:
    order.values["fulfilled_by"] = payload["actor"]

    return {
        "message": "Order fulfilled",
        "fulfilled_by": payload["actor"],
    }


def close_order(
    order: ObjectInstance,
    payload: dict[str, Any],
) -> dict[str, Any]:
    order.values["closed_by"] = payload["actor"]

    return {
        "message": "Order closed",
        "closed_by": payload["actor"],
    }
```

## 13. 조건부 전이 추가

업무에서는 모든 사용자가 모든 액션을 수행할 수 없습니다. 예를 들어 5000 이상 주문은 관리자만 승인할 수 있다고 가정합니다.

```python
def manager_required_for_large_order(
    order: ObjectInstance,
    payload: dict[str, Any],
) -> bool:
    if order.values["amount"] < 5000:
        return True

    return payload.get("role") == "manager"
```

조건을 전이에 연결합니다.

```python
large_order = ObjectInstance(
    object_id="O002",
    object_type=order_type,
    values={
        "status": "Submitted",
        "amount": 8000.0,
        "customer_id": "C002",
    },
)

engine.register_transition(
    WorkflowTransition(
        name="LargeOrderApproval",
        object_type=order_type,
        from_status="Submitted",
        action_name="ApproveOrder",
        to_status="Approved",
        condition=manager_required_for_large_order,
    )
)
```

주의할 점은 이미 `Submitted -> ApproveOrder -> Approved` 전이가 있다면 조건 없는 전이가 먼저 매칭될 수 있다는 것입니다. 실제 구현에서는 같은 액션과 상태 조합에 여러 전이가 생기지 않도록 정책을 정하거나, 조건이 있는 전이를 우선 평가해야 합니다.

## 15. 온톨로지와 워크플로우 연결 방식

온톨로지에서 워크플로우는 다음과 같이 연결됩니다.

| 온톨로지 요소 | 워크플로우 표현 |
| --- | --- |
| 객체 타입 | 워크플로우 대상 |
| 객체 인스턴스 | 현재 처리 대상 |
| 속성 | 상태, 금액, 담당자, 위험도 |
| 관계 | 승인자, 고객, 주문 품목, 연결 업무 |
| 액션 | 상태를 바꾸는 업무 행동 |
| 이벤트 | 실행 이력과 감사 로그 |

핵심은 워크플로우를 화면 중심으로 만들지 않는 것입니다. 먼저 객체 상태와 액션을 정의하고, 화면은 그 위에 얹는 것이 좋습니다.

## 16. 확장 과제

다음 기능을 추가해 볼 수 있습니다.

- 액션별 권한 모델
- 상태별 SLA 계산
- 승인 대기 큐
- 병렬 승인
- 반려 후 재상신
- 이벤트 기반 알림
- 워크플로우 정의를 JSON으로 분리
- Streamlit 또는 FastAPI 화면 연결

## 17. 요약

워크플로우는 객체의 상태와 액션 전이를 모델링하는 방식으로 표현할 수 있습니다. 객체기반 온톨로지에서는 워크플로우가 객체, 속성, 관계, 액션, 이벤트와 자연스럽게 연결됩니다. 작게 시작할 때는 `status` 속성, 전이 규칙, 액션 핸들러, 실행 이력만 구현해도 충분히 실용적인 워크플로우 모델을 만들 수 있습니다.
