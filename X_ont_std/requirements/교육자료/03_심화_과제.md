# 03. 심화 과제

> 최소 1개 선택. 각 과제는 코드 변경 + 테스트 추가 + `pytest` 통과까지가 완료 조건.

## A. 객체 타입 추가 — "Invoice" (난이도 ★★)

**목표**: 주문에 연결되는 청구서 객체를 추가하고, 검색/컨텍스트에 노출.

**작업**:
1. [backend/app/data.py](../../claud_통합/backend/app/data.py)에 `RAW_INVOICES` 추가 (O001, O002, O003에 각각 1건씩)
2. [backend/app/ontology.py](../../claud_통합/backend/app/ontology.py)의 `_build_registry()`에 Invoice 타입과 ORDER_HAS_INVOICE 관계 등록
3. `get_order_context()`가 `invoices` 키도 반환하도록 확장
4. 프론트엔드 컨텍스트 패널에 Invoice 섹션 추가
5. 테스트: 새 케이스 `tests/test_invoice.py` 작성

**힌트**: 기존 Product 처리 흐름을 그대로 따라가면 됨.

## B. 워크플로우 액션 추가 — "RequestRevision" (난이도 ★★)

**목표**: 추가 정보가 필요할 때 Submitted → Submitted로 돌리는 비파괴 액션.

**작업**:
1. [backend/app/workflow.py](../../claud_통합/backend/app/workflow.py)에 `request_revision` 핸들러 + `WorkflowTransition` 등록
2. [backend/app/policy.py](../../claud_통합/backend/app/policy.py)에 `RequestRevision` 액션 권한 추가
3. 화면에서 노란색 버튼으로 노출
4. E2E 시나리오 추가: `frontend/e2e/scenarios.spec.ts`

**힌트**: HoldOrder를 참고하되 to_status를 다시 Submitted로.

## C. 새로운 검색 룰 — 가격대 필터 (난이도 ★★)

**목표**: "5000원 이상 주문 보여줘" 같은 자연어 질의에서 금액 조건을 자동 인식.

**작업**:
1. [backend/app/rag.py](../../claud_통합/backend/app/rag.py)에 `extract_amount_filter()` 추가 (`>=5000`, `under 1000` 등 정규식)
2. `build_search_query()`에서 금액 조건을 키워드로 보강
3. `app_context.py`의 `ask()`에서 검색 결과를 추가 필터링
4. evaluate.py에 케이스 2개 추가 (`amount>=5000` / `amount<1000`)
