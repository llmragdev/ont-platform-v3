# 02. 실습 플로우 — 시나리오 5종 + 코드 워크스루

## 실습 1: 시나리오 5종 (60분)

브라우저 `http://localhost:3000` 열어둔 채로 진행. 우상단 셀렉터로 사용자 전환.

### 시나리오 1 — 정상 승인 (analyst + O001)

1. **현재 사용자**: `Kim Ops (AccountManager)` 확인
2. 좌측 메뉴 → **대시보드** → 표에서 **O001** 행 클릭
3. 우측 컨텍스트 패널 확인: customer=`Alpha Manufacturing`, risk=`Low`, amount=`3,200`
4. 좌측 메뉴 → **승인 워크플로우** → O001 행에서 **ApproveOrder** 클릭
5. 토스트 `O001 → Approved` 표시되면 성공

**학습 포인트**: amount<5000 AND risk=Low이므로 AccountManager 권한으로 승인 가능. PolicyEngine 분기를 코드에서 확인:
- [backend/app/policy.py](../../claud_통합/backend/app/policy.py) `can_execute_action()` 의 `if action == "ApproveOrder"` 분기

### 시나리오 2 — 고위험 거부 (analyst + O003)

1. **승인 워크플로우** 화면에서 O003 행 찾기
2. ApproveOrder 버튼이 **보이지 않음** 확인 (큐에 표시되어도 액션 비어 있음)
3. 직접 시도 (PowerShell — 4xx에서 예외가 나므로 try-catch로 감싸 본문까지 보기):
   ```powershell
   try {
     Invoke-RestMethod -Method Post `
       -Uri http://localhost:8000/api/workflow/execute `
       -ContentType 'application/json' `
       -Body '{"action":"ApproveOrder","order_id":"O003"}'
   } catch {
     Write-Host "HTTP $($_.Exception.Response.StatusCode.value__)"
     Write-Host $_.ErrorDetails.Message
   }
   ```
   Bash/WSL/macOS라면:
   ```bash
   curl -X POST http://localhost:8000/api/workflow/execute \
     -H "Content-Type: application/json" \
     -d '{"action":"ApproveOrder","order_id":"O003"}'
   ```
4. 응답 `409 ACTION_NOT_ALLOWED` 확인

**학습 포인트**: C003은 risk=`High`이므로 PolicyEngine이 차단. 큐 단계와 액션 실행 단계 **두 번** 검증되는 이중 방어 구조.

### 시나리오 3 — 금액 임계 분기 (analyst→finance)

1. analyst 상태로 **승인 워크플로우** → O002 행 확인 (보임 / 안 보임)
2. 우상단 사용자 셀렉터로 **Finance Lead (FinanceManager)** 전환
3. **승인 워크플로우** 다시 보기 → O002 행에 ApproveOrder 버튼 등장
4. 버튼 클릭 → Approved

**학습 포인트**: O002 amount=8200 (≥5000)이므로 FinanceManager만 승인 가능. 코드:
- `if order["amount"] < 5000: return user["role"] in ["AccountManager", "FinanceManager"]`
- `return user["role"] == "FinanceManager"`

### 시나리오 4 — 지역 거부 (viewer)

1. 우상단 셀렉터 → **Read Only (Viewer)** 전환
2. 좌측 **객체 탐색** → 주문 표에 O001만 표시 (O002 Busan, O003 Incheon은 viewer의 region=Seoul에 없음)
3. 직접 호출 시도:
   ```powershell
   curl "http://localhost:8000/api/objects/orders/O002/context?user=viewer"
   ```
4. 응답 `403 FORBIDDEN`

**학습 포인트**: PolicyEngine.can_read_object → ORDER_REGION_MAP에서 O002→Busan, viewer.regions=[Seoul]이므로 거부.

### 시나리오 5 — 속성 마스킹 (viewer)

1. viewer 상태에서 **객체 탐색** → 고객 표
2. **C001 Alpha Manufacturing** 행: risk 값이 `Restricted` 로 표시
3. analyst로 전환 → 같은 행: risk=`Low`, contract_terms=`Custom discount rate: ***` 로 표시
4. finance로 전환 → contract_terms=`Standard support terms, custom discount 7%` (원본)

**학습 포인트**: 세 단계 마스킹 정책. 같은 객체라도 user.role에 따라 응답이 달라진다.

## 실습 2: 코드 워크스루 (60분)

`/api/ask` 가 어떻게 답을 만드는지 8단계 추적.

질문 예시: `O001 주문 승인해도 될까?` → 응답의 `steps` 배열을 그대로 코드와 매핑.

| Step | 응답 trace | 코드 위치 |
| --- | --- | --- |
| 1 | 질문에서 객체 후보 추출 | [rag.py:7](../../claud_통합/backend/app/rag.py) `extract_object_ids()` |
| 2 | Ontology Service에서 객체와 관계 조회 | [ontology.py:155](../../claud_통합/backend/app/ontology.py) `get_order_context()` |
| 3 | Policy Engine에서 객체 접근 권한 확인 | [policy.py:23](../../claud_통합/backend/app/policy.py) `assert_can_read_object()` |
| 4 | Policy Engine에서 액션 권한 확인 | [policy.py:43](../../claud_통합/backend/app/policy.py) `available_actions()` |
| 5 | RAG Service에서 검색 질의 강화 | [rag.py:18](../../claud_통합/backend/app/rag.py) `build_search_query()` |
| 6 | Search Service에서 권한 필터링 문서 검색 | [search.py:68](../../claud_통합/backend/app/search.py) `SearchService.search()` |
| 7 | RAG Service에서 프롬프트 생성 | [rag.py:34](../../claud_통합/backend/app/rag.py) `build_prompt()` |
| 8 | LLM Gateway 호출 (gemini/rule-based) | [llm_gateway.py:64](../../claud_통합/backend/app/llm_gateway.py) `generate()` |

각 step 결과는 응답 JSON의 `steps`, `ontology_context`, `context`, `prompt`, `evidence`, `available_actions`, `answer`에서 확인 가능.

### 핵심 코드 5개

1. **OntologyRegistry** ([ontology.py](../../claud_통합/backend/app/ontology.py)) — 객체 타입/인스턴스/관계를 명시적으로 등록. 새 객체 타입 추가 실습 가능.
2. **BM25Search** ([search.py](../../claud_통합/backend/app/search.py)) — 한글 힌트 토크나이저 + 진짜 BM25 공식 (IDF·k1·b).
3. **PolicyEngine** ([policy.py](../../claud_통합/backend/app/policy.py)) — role+region+amount+risk가 결합되는 거버넌스 코어.
4. **WorkflowService** ([workflow.py](../../claud_통합/backend/app/workflow.py)) — 5 액션·7 전이·정책 콜백.
5. **LLMGateway** ([llm_gateway.py](../../claud_통합/backend/app/llm_gateway.py)) — Gemini 키 로테이션 + 룰베이스 폴백.
