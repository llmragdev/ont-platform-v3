## 3. 구현 추적

### 3.1 기본 모델

`src_codex`:
- `src_codex/backend/models.py`
- `PropertyDefinition`
- `PropertyDefinition.type_name`
- `ObjectType`
- `ObjectInstance`
- `ObjectInstance.validate()`

`src_anti`:
- `src_anti/backend/models.py`
- `Customer`
- `Order`
- `Product`
- `Document`

판단:
- `src_codex`: 구현됨. 속성 타입 표시를 `type_name`으로 분리해 타입 표현 변경에도 덜 취약하게 개선됨
- `src_anti`: 부분 구현

### 3.2 관계 모델

`src_codex`:
- `RelationshipDefinition`
- `RelationshipInstance`
- `OntologyRegistry.find_related()`
- `OntologyRegistry.find_sources()`
- `OntologyRegistry.find_relationships()`

`src_anti`:
- 별도 관계 모델 없음
- `Order.customerId`, `Order.productIds` 필드로 관계 표현

판단:
- `src_codex`: 구현됨. 정방향, 역방향, 조건 기반 관계 인스턴스 탐색을 지원하도록 개선됨
- `src_anti`: 부분 구현

### 3.3 액션 모델

`src_codex`:
- `ActionDefinition`
- `WorkflowTransition`
- `WorkflowEvent`

`src_anti`:
- 별도 액션 모델 없음
- 문자열 액션 이름과 `WorkflowService.TRANSITIONS`로 처리

판단:
- `src_codex`: 구현됨
- `src_anti`: 부분 구현

### 3.4 레지스트리

`src_codex`:
- `src_codex/backend/ontology.py`
- `OntologyRegistry`
- `register_object_type()`
- `create_object()`
- `register_relationship_type()`
- `link()`
- `find_related()`
- `find_sources()`
- `find_relationships()`

`src_anti`:
- 별도 온톨로지 레지스트리 없음
- `data.py`의 전역 Repository가 데이터 저장 역할

판단:
- `src_codex`: 구현됨. 객체 속성에 직접 의존하지 않고 관계 그래프를 통해 컨텍스트를 조립할 수 있도록 확장됨
- `src_anti`: 미구현에 가까운 부분 구현

### 3.5 관계 탐색

`src_codex`:
- `OntologyRegistry.find_related()`
- `OntologyRegistry.find_sources()`
- `OntologyRegistry.find_relationships()`
- `OntologyService.get_order_context()`

`src_anti`:
- `OntologyService.get_order_context()`

판단:
- `src_codex`: 구현됨. `OntologyService.get_order_context()`가 `customer_id`, `product_ids` 같은 편의 속성보다 `PLACED_ORDER`, `ORDER_CONTAINS_PRODUCT` 관계를 우선 사용하도록 개선됨
- `src_anti`: 부분 구현

### 3.6 유연성 검증

`src_codex`:
- `src_codex/tests/test_services.py`
- `test_order_context_uses_registry_relationships()`
- `test_registry_can_traverse_relationships_in_both_directions()`

검증 내용:
- 주문 객체의 비정규화 속성(`customer_id`, `product_ids`)이 틀어져도 등록된 관계 그래프에서 고객과 제품 컨텍스트를 복원
- 고객에서 주문으로 가는 정방향 탐색과 주문에서 고객으로 가는 역방향 탐색 확인
- 관계 인스턴스 조건 검색 확인

판단:
- `src_codex`: 유연성 회귀 테스트 추가됨
- `src_anti`: 해당 검증 없음

## 4. 요약

`03` 문서의 직접 구현 요구는 `src_codex`에 거의 그대로 반영되어 있습니다. 이번 점검에서 `src_codex`는 단순 필드 조립이 아니라 관계 레지스트리를 통해 컨텍스트를 복원하도록 개선되어, 객체 속성 구조가 바뀌어도 관계 중심 온톨로지 모델을 유지할 수 있게 되었습니다. 액션 실행은 문서 예시처럼 `OntologyRegistry`에 직접 넣기보다 `WorkflowEngine`으로 분리되어 있으며, 이는 상태 전이와 감사 로그를 다루기 위한 확장형 설계로 볼 수 있습니다. `src_anti`는 Pydantic DTO와 컨텍스트 조립으로 일부 개념을 대체하지만, 온톨로지 레지스트리 구조는 없습니다.
