## 2. 백엔드 구현 체크리스트

### 2.1 데이터 파일

- [ ] `companies.json` — 2개 이상 회사 포함
- [ ] `users.json` — 역할별 대표 사용자 5명 이상 (기존 `analyst` 포함)
- [ ] `projects.json` — 회사당 1개 이상 프로젝트, `doc-ff68a066` 귀속

### 2.2 API 엔드포인트

- [ ] `GET /api/companies` — 전체 목록
- [ ] `GET /api/users` — 전체 목록 (비밀번호 없음, 권한 플래그 포함)
- [ ] `GET /api/users/{id}` — 단일 사용자 상세
- [ ] `GET /api/users/{id}/permissions` — 권한 플래그만 반환
- [ ] `GET /api/projects?user={id}` — 사용자 소속 프로젝트
- [ ] `GET /api/projects/{id}` — 프로젝트 상세

### 2.3 미들웨어

- [ ] `get_current_user(user: str = Query(...))` 의존성 — users.json에서 조회
- [ ] `require_permission(flag)` 의존성 팩토리 — 403 반환
- [ ] company_id 자동 추출 — user → company_id 매핑

## 4. 테스트 계획

| 테스트 케이스 | 방법 | 예상 결과 |
| --- | --- | --- |
| alice → bob 전환 시 편집 버튼 비활성화 | 수동 UI | 다이어그램 편집 버튼 disabled |
| carol (Globex) → ACME 문서 조회 불가 | API 직접 호출 | 빈 목록 반환 |
| bob이 편집 API 직접 호출 시 | curl/Postman | 403 permission_denied |
| localStorage 재방문 시 마지막 사용자 복원 | 브라우저 새로고침 | 이전 선택 사용자 유지 |
| 존재하지 않는 user_id | `?user=unknown` | 404 or 403 반환 |

## 5. 구현 순서 권장

```
1. companies.json, users.json, projects.json 작성
2. GET /api/users, /api/users/{id}/permissions 구현
3. UserContext + UserProvider 구현
4. UserSwitcher 컴포넌트 구현 + 헤더 배치
```
