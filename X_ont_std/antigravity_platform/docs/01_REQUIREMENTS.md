# 01. 통합 요건 정의서 (Enterprise Hybrid Knowledge Platform)

## 1. 프로젝트 비전
본 프로젝트는 비정형 문서에서 추출한 지식을 온톨로지와 벡터 RAG로 통합하여 고신뢰 지식 서비스를 제공하는 플랫폼입니다.

## 2. 상세 요구사항 (Traceable Requirements)

### 2.1 테넌트 보안 및 격리 (Security)
- **[REQ-SEC-01]** 모든 데이터(문서, 벡터, 온톨로지)는 `company_id`와 `project_id` 기반으로 물리적/논리적으로 격리되어야 함.
- **[REQ-SEC-02]** 시스템은 RBAC(Role-Based Access Control)을 지원하며, 모든 API는 실행 전 사용자의 권한(Scope)을 검증해야 함.
- **[REQ-SEC-03]** 테넌트 간 데이터 침범 시도 시 시스템은 즉각적으로 403 Forbidden 에러를 반환하고 로그를 기록해야 함.

### 2.2 범용 온톨로지 관리 (Ontology)
- **[REQ-ONT-01]** 시스템은 도메인 중립적이어야 하며, JSON 설정 파일(`ontology.schema.json`)에 따라 동적으로 엔티티/관계 타입을 정의함.
- **[REQ-ONT-02]** 모든 엔티티와 관계는 `created_by`, `company_id` 등 메타데이터를 포함한 표준 스키마를 준수해야 함.
- **[REQ-ONT-03]** 사용자는 UI를 통해 추출된 지식 데이터를 보정(수정/삭제/확정)할 수 있어야 함.

### 2.3 하이브리드 질의 엔진 (Intelligence)
- **[REQ-QRY-01]** 질의 엔진은 자연어 질문을 해석하여 결정론적 실행 계획(Execution Plan)을 생성해야 함.
- **[REQ-QRY-02]** 답변 생성 시 참조된 벡터 컨텍스트(문서 페이지)와 온톨로지 노드 정보를 출처(Citation)로 명시해야 함.
- **[REQ-QRY-03]** 구조형 데이터가 필요한 질문(계산, 필터링 등)은 LLM의 추론이 아닌 코드의 연산 결과로 처리해야 함.
