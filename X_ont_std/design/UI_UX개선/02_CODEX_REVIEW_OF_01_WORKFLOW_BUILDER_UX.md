# 01 Workflow Builder UI/UX 개선안 검토

작성일: 2026-06-13  
검토자: Codex

## 1. 검토 결론

`01_WORKFLOW_BUILDER_UX_IMPROVEMENT_PLAN.md`는 Workflow Builder 화면 자체를 개선하기 위한 상세 실행안으로 유효하다.
특히 다음 내용은 현재 `ont_platform v5`에서 바로 반영 가치가 높다.

- Builder 안에서 실행 상태를 바로 보여주는 Execution Panel
- 실행 중인 블록 상태 표시
- 노드 박스 디자인 개선
- 메뉴 구조 재정리
- 온톨로지 엔티티로 이동하는 연결 UX

다만 이 문서는 Workflow Builder 중심의 상세 설계안이고, `UI_UX_개선안_및_참고웹사이트.md`는 전체 콘솔 UI/UX 개선 방향을 잡는 마스터 문서로 보는 것이 좋다.

권장 역할:

```text
UI_UX_개선안_및_참고웹사이트.md
  = 전체 UI/UX 방향, 메뉴 구조, 화면 역할, 장기 로드맵

01_WORKFLOW_BUILDER_UX_IMPROVEMENT_PLAN.md
  = Workflow Builder 화면의 구체 설계와 구현 체크리스트

02_CODEX_REVIEW_OF_01_WORKFLOW_BUILDER_UX.md
  = 두 문서 간 관계, 충돌 조정, 반영 우선순위
```

## 2. 01 문서에서 유지해야 할 핵심 아이디어

### 2.1 Builder 우측 Execution Panel

01 문서의 가장 중요한 제안이다.
현재처럼 실행 결과를 `Workflow Trace`에서만 확인하면 사용자가 화면을 오가야 한다.

유지 권장:

```text
Workflow Builder에서 Run
  -> 같은 화면 우측 패널에서 실행 로그와 상태 확인
  -> 필요 시 Trace 상세 화면으로 이동
```

이 방향은 반드시 반영하는 것이 좋다.

### 2.2 실행 중 블록 상태 표시

워크플로우가 실제로 실행되고 있다는 느낌을 주려면 캔버스에서 상태가 보여야 한다.

반영할 상태:

- 대기
- 실행 중
- 성공
- 실패
- 스킵

상태별 색상과 아이콘을 일관되게 적용한다.

### 2.3 노드 박스 시각화

01 문서는 노드에 입력/출력 정보를 표시하자는 방향을 담고 있다.
이는 현재 작은 라벨 박스 형태보다 훨씬 낫다.

권장 노드 구성:

```text
아이콘
단계명
짧은 설명
Input
Output
실행 상태
실행 시간
```

### 2.4 온톨로지 엔티티 연결

워크플로우 실행 결과에서 온톨로지 엔티티로 바로 이동하는 기능은 플랫폼의 핵심 차별점이다.

반영할 액션:

- `객체 탐색에서 보기`
- `온톨로지 맵에서 강조`
- `Trace에서 관계 보기`

## 3. 조정이 필요한 부분

### 3.1 Split View 60/40 고정은 유연하게 적용

01 문서는 그래프 60%, 실행 패널 40% split view를 권장한다.
하지만 현재 화면은 좌측 팔레트, 중앙 캔버스, 우측 속성 패널 구조이므로 고정 60/40은 다소 답답할 수 있다.

권장 조정안:

```text
편집 전:
  좌측 팔레트 + 중앙 캔버스 + 우측 속성 패널

실행 중:
  좌측 팔레트 축소
  중앙 캔버스 유지
  우측 패널이 실행 탭으로 자동 전환

실행 완료 후:
  우측 패널에서 결과/이력/Trace 이동 제공
```

즉, 01 문서의 Execution Panel 아이디어는 유지하되, 레이아웃은 `우측 탭 패널` 방식으로 구현하는 것이 현실적이다.

### 3.2 메뉴 구조는 01 문서보다 마스터 문서 기준 권장

01 문서의 메뉴 구조는 Dashboard, Workflow, Ontology, Knowledge, Settings로 나누는 방향이다.
이 방향도 좋지만, 현재 시나리오 운영을 강조하려면 마스터 문서의 구조가 더 직접적이다.

권장 최종 메뉴:

```text
시나리오 운영
온톨로지 관리
검증/운영
분석/질의
```

이유:

- 고객 자동댓글, 공장 반복 고장 대응 같은 시나리오 중심 데모에 적합하다.
- 사용자가 "무엇을 실행할 수 있는가"를 먼저 이해한다.
- Workflow, Ontology, Trace의 관계를 시나리오 단위로 묶어 설명하기 쉽다.

### 3.3 모바일 반응형은 우선순위 낮음

01 문서는 모바일 반응형도 포함한다.
하지만 현재 플랫폼은 개발/운영 콘솔 성격이 강하고, 워크플로우 캔버스는 데스크톱 중심이다.

권장 우선순위:

```text
P0/P1: 데스크톱 UX 완성
P2 이후: 태블릿/모바일 대응
```

모바일은 당장 핵심이 아니다.

## 5. 구현 우선순위 제안

### P0. 바로 체감되는 Builder 개선

1. 우측 패널 탭 구조 추가
   - 속성
   - 실행
   - 온톨로지
   - 이력

2. 실행 중 상태 표시
   - running
   - success
   - error
   - skipped

3. 실행 로그를 Builder 안에 표시
   - 현재 단계
   - 처리 건수
   - MCP 호출 결과
   - 댓글/정비지시 등록 결과

4. 실행 이력에서 Trace 보기 연결

### P1. 온톨로지 연결 강화

1. 노드 선택 시 관련 온톨로지 객체 표시
2. `객체 탐색에서 보기` deep link
3. `온톨로지 맵에서 강조` 액션
4. Trace 화면에서 실행 객체/관계 표시 강화

### P2. 비주얼 정리

1. 노드 카드 디자인 개선
2. 아이콘 적용
3. edge animation 개선
4. 메뉴 그룹 재구성
5. 시나리오 홈 추가

## 6. 기획 판단

`Workflow Trace`만으로 실행 결과를 보여주는 것은 부족하다.
Trace는 상세 분석 화면으로 두고, Builder 자체에 실행 패널과 최근 이력을 넣어야 한다.

최종 UX는 다음 구조가 좋다.

```text
Workflow Builder
  = 만들고, 수정하고, 실행하고, 바로 결과를 보는 화면

Workflow Trace
  = 특정 실행 1건을 깊게 분석하는 화면

Ontology Explorer / Ontology Map
  = 실행 결과가 축적된 객체와 관계를 탐색하는 화면
```
