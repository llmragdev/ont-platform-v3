## 🎨 템플릿 갤러리

**목적**: 사전 정의된 워크플로우 템플릿 제공  
**주요 기능**:
- 카테고리별 템플릿 검색
- 템플릿 미리보기
- 한번의 클릭으로 복제 및 시작

### 템플릿 분류

| 카테고리 | 설명 | 예시 |
|---------|------|------|
| **승인 프로세스** | 비즈니스 승인 워크플로우 | 구매 승인, 휴가 신청 |
| **데이터 통합** | 외부 시스템 연동 | ERP 연동, API 호출 |
| **보고서 생성** | 자동 보고서 생성 | 월별 리포트, 분석 보고 |
| **알림 및 통지** | 조건부 알림 전송 | Slack, Email, Teams |
| **데이터 정제** | ETL 프로세스 | 중복 제거, 포맷 변환 |

### 템플릿 복제 프로세스

```
1. 템플릿 갤러리에서 원하는 템플릿 검색
   ↓
2. 템플릿 카드 클릭 → 미리보기 확인
   ↓
3. [복제하기] 버튼 클릭
   ↓
4. 새 워크플로우 이름 입력 (자동 제안: "Copy of [원본명]")
   ↓
5. 빌더와 실행으로 자동 이동
   ↓
6. 필요에 따라 노드, 스킬, 매핑 수정
   ↓
7. [저장] → [실행]
```

### 템플릿 상세 보기

미리보기에서 볼 수 있는 정보:
- 워크플로우 구조 (노드, 연결)
- 사용된 스킬 목록
- 입력/출력 데이터 형식
- 작성자 및 최종 수정일
- 사용 통계 (실행 횟수, 성공률)

## 🔨 빌더와 실행

**목적**: 워크플로우 설계 및 즉시 실행  
**주요 기능**:
- 캔버스 기반 비주얼 워크플로우 편집
- 노드 추가/삭제/연결
- 스킬 설정 및 입력 매핑
- 온톨로지 매핑 (결과 저장)
- 즉시 실행 및 결과 확인

### 인터페이스 구성

```
┌──────────────────────────────────────────────────────┐
│ 빌더와 실행                                          │
├──────────────────────────────────────────────────────┤
│                                                      │
│  [←] [저장] [실행▶] [공유] [복제] [삭제] [히스토리]  │
│                                                      │
│  ┌────────────────────────────────────────────────┐ │
│  │                                                │ │
│  │  [START 노드]                                 │ │
│  │        │                                      │ │
│  │        ├─→ [Skill Node 1]                    │ │
│  │        │        │                            │ │
│  │        │        └─→ [Skill Node 2]           │ │
│  │        │               │                    │ │
│  │        └─→ [END 노드]←─┘                    │ │
│  │                                                │ │
│  │  [+] 노드 추가  [🔗] 연결  [⚙️] 설정        │ │
│  │                                                │ │
│  └────────────────────────────────────────────────┘ │
│                                                      │
│  ┌────────────────────────────────────────────────┐ │
│  │ 노드 상세 정보 / 스킬 설정                      │ │
│  ├────────────────────────────────────────────────┤ │
│  │ 선택 노드: [Skill Node 1]                     │ │
│  │                                                │ │
│  │ 📋 기본 정보                                   │ │
│  │  ├─ 노드 ID: skill_1                        │ │
│  │  ├─ 스킬: ontology-write                    │ │
│  │  └─ 버전: 1.0                               │ │
│  │                                                │ │
│  │ 🔗 입력 매핑 (Input Mapping)                  │ │
│  │  ├─ entityType: "Project"                  │ │
│  │  ├─ properties: {{nodes.start.output}}     │ │
│  │  └─ [+ 매핑 추가]                          │ │
│  │                                                │ │
│  │ 📤 온톨로지 매핑 (Output)                     │ │
│  │  ├─ 이 노드의 결과를 온톨로지에 저장하기     │ │
│  │  └─ [매핑 설정]                             │ │
│  │                                                │ │
│  └────────────────────────────────────────────────┘ │
│                                                      │
└──────────────────────────────────────────────────────┘
```

### 주요 작업

#### 1️⃣ 노드 추가

```
1. [+] 노드 추가 버튼 클릭
2. 노드 타입 선택
   ├─ START (시작)
   ├─ END (종료)
   ├─ Skill (스킬 실행)
   ├─ Condition (조건 분기)
   └─ Parallel (병렬 처리)
3. 캔버스에서 위치 선택
4. 노드 ID 입력
```

#### 2️⃣ 스킬 설정

**스킬 선택**:
```
1. Skill 노드 클릭
2. "스킬" 드롭다운에서 선택
   예) ontology-write, rag-ontology-lookup, request-classify
3. 스킬 버전 선택 (기본: 최신)
```

**입력 매핑**:
```
1. "입력 매핑" 섹션의 [편집] 클릭
2. 각 입력 필드에 대해:
   ├─ 리터럴 값: "고정값"
   └─ 표현식: {{nodes.이전노드ID.output.필드명}}
3. [검증] → [저장]
```

**출력 확인**:
```
실행 후 결과 패널에서:
- Output Data (JSON 형식)
- 스킬 실행 정보 (ID, 타입, 버전)
- 실행 시간, 상태 등
```

#### 3️⃣ 온톨로지 매핑

노드 결과를 온톨로지에 자동 저장:

```
1. 노드의 "온톨로지 매핑" 탭 클릭
2. 매핑 설정
   ├─ 엔티티 타입 선택 (예: Project, Equipment)
   ├─ 속성 매핑 (결과 필드 → 온톨로지 속성)
   └─ 관계 설정 (선택사항)
3. [저장]
```

매핑 예시:
```json
{
  "entityType": "Project",
  "mapping": {
    "name": "{{nodes.skill_1.output.projectName}}",
    "status": "{{nodes.skill_1.output.status}}",
    "budget": "{{nodes.skill_1.output.amount}}"
  }
}
```

#### 4️⃣ 워크플로우 실행

```
1. [저장] 버튼으로 변경사항 저장
2. [실행▶] 버튼 클릭
3. 입력 데이터 제공 (필요시)
4. 실행 진행도 모니터링
5. 결과 확인 → [상세 보기]로 실행 추적 이동
```

### 고급 기능

**표현식 검증**:
- `{{}}` 표현식 입력 시 자동 완성 및 검증
- 타입 체크 (배열, 객체, 문자열 등)
- 존재하지 않는 노드/필드 경고

**히스토리**:
- 모든 저장 버전 관리
- 이전 버전 복원 가능

**공유 및 협업**:
- 워크플로우 URL 공유
- 팀원 초대 (읽기/쓰기)

## 🔧 스킬 관리

**목적**: 워크플로우에서 사용할 재사용 가능한 스킬(실행 기능) 관리  
**주요 기능**:
- 내장 스킬 조회 (ontology-write, RAG 검색 등)
- 커스텀 스킬 생성/편집/삭제
- 스킬 입출력 스키마 정의
- 스킬 검색 및 필터링

### 스킬 분류

**내장 스킬** (시스템 제공):

| 스킬 ID | 타입 | 입력 | 출력 | 용도 |
|---------|------|------|------|------|
| `ontology-write` | builtin | entityType, properties, relations | entityId, saved | 온톨로지에 엔티티 저장 |
| `rag-ontology-lookup` | builtin | query, limit, entityTypes | documents[], entities[] | 문서/엔티티 검색 |
| `fault-recurrence-check` | builtin | equipmentId, faultType | isRecurring, pattern | 반복 고장 패턴 분석 |
| `request-classify` | builtin | text, categories | category, confidence | AI 텍스트 분류 |
| `customer-comment-create` | mcp_http | text, type | id, createdAt | 고객 의견 저장 (외부 시스템) |
| `factory-comment-create` | mcp_http | text, type | id, createdAt | 공장 의견 저장 (외부 시스템) |
| `factory-maintenance-create` | mcp_http | type, description | id, createdAt | 유지보수 요청 생성 |

**커스텀 스킬** (사용자 생성):
- HTTP 기반 스킬: 외부 API 호출
- MCP HTTP: Model Context Protocol 연동
- Custom Code (Phase 2+): 사용자 정의 로직

│ │                                                   │

### 커스텀 스킬 생성

```
1. [새 스킬 만들기] 버튼
2. 기본 정보 입력
   ├─ ID: my-skill-1
   ├─ 이름: 내 커스텀 스킬
   ├─ 설명: 스킬의 용도
   └─ 카테고리: integration
3. 구현 타입 선택
   ├─ HTTP: 외부 API 호출
   └─ MCP HTTP: Model Context Protocol
4. 엔드포인트 URL 입력
5. 입출력 스키마 정의 (JSON)
   ```json
   {
     "inputSchema": {
       "type": "object",
       "properties": {
         "param1": {"type": "string"},
         "param2": {"type": "number"}
       },
       "required": ["param1"]
     },
     "outputSchema": {
       "type": "object",
       "properties": {
         "result": {"type": "string"},
         "status": {"type": "boolean"}
       }
     }
   }
   ```
6. [저장]

```

### 스킬 검색 및 필터

```
검색: 스킬명, ID, 태그 검색
필터: 전체 | 내장 | 커스텀 | Phase 1 실행 가능
정렬: 이름 | 최근 수정 | 사용 빈도
```

## 📊 실행 추적

**목적**: 워크플로우 실행 결과 모니터링 및 분석  
**주요 기능**:
- 실행 히스토리 조회
- 노드별 실행 상태 표시
- 입출력 데이터 상세 확인
- 성공/실패 분석
- 온톨로지 저장 결과 확인

### 실행 추적 화면

```
┌──────────────────────────────────────────────────────┐
│ 실행 추적 (실행 결과와 온톨로지 흐름)               │
├──────────────────────────────────────────────────────┤
│                                                      │
│ 실행 선택: [workflow_1]  시작: 2026-06-14 10:30  │
│ 상태: [완료] ✓  실행 시간: 2.5초                   │
│                                                      │
│ ┌────────────────────────────────────────────────┐ │
│ │  실행 흐름 (타임라인)                           │ │
│ ├────────────────────────────────────────────────┤ │
│ │                                                │ │
│ │ 1️⃣ START (즉시)                              │ │
│ │  └─ ✓ 완료                                    │ │
│ │                                                │ │
│ │ 2️⃣ ontology-write (0ms ~ 500ms)              │ │
│ │  └─ ✓ 완료                                    │ │
│ │     Input: {entityType: "Project", ...}      │ │
│ │     Output: {entityId: "proj-123", saved: true} │
│ │                                                │ │
│ │ 3️⃣ rag-lookup (500ms ~ 1200ms)               │ │
│ │  └─ ✓ 완료                                    │ │
│ │     Input: {query: "...", limit: 5}          │ │
│ │     Output: {documents: [...], entities: [...]} │
│ │                                                │ │
│ │ 4️⃣ request-classify (1200ms ~ 1800ms)        │ │
│ │  └─ ✓ 완료                                    │ │
│ │     Input: {text: "...", categories: [...]}  │ │
│ │     Output: {category: "request", confidence: 0.92} │
│ │                                                │ │

## ✅ 승인 워크플로우

**목적**: 업무 승인 프로세스 관리 (상태 전이, 담당자 액션)  
**주요 기능**:
- 승인 요청 조회
- 상태 전이 (요청 → 승인 → 거부 등)
- 담당자별 액션 정의
- 조건부 라우팅

### 워크플로우 상태

```
[요청됨]
   ↓
[담당자 검토 대기]
   ├─ → [승인됨] (조건: 금액 < 100M)
   │       ↓
   │    [완료]
   │
   └─ → [추가 검토 필요] (조건: 100M ≤ 금액 < 1B)
           ↓
        [관리자 승인 대기]
           ├─ → [승인됨] → [완료]
           └─ → [거부됨] → [반려]
```

### 주요 작업

**내 승인 대기 목록 확인**:
```
1. 승인 워크플로우 메뉴 선택
2. "내 승인 대기" 탭
3. 요청 카드에서 [상세 보기]
```

**승인/거부**:
```
1. 요청 선택
2. 상세 정보 검토
   ├─ 요청자 정보
   ├─ 요청 사항 (workflow 결과)
   └─ 금액, 날짜, 기타 메타데이터
3. [승인] 또는 [거부 (사유 입력)] 클릭
4. 다음 담당자가 알림 수신
```

**추가 정보 요청**:
```
1. "더 알아보기" 버튼
2. 요청자에게 메시지
3. 요청자가 답변 후 상태 업데이트
```

### 승인 통계

```

## 📦 Writeback DLQ

**목적**: 외부 시스템 저장 실패 큐 모니터링  
**주요 기능**:
- 실패한 write-back 요청 조회
- 재시도 관리
- 실패 원인 분석
- 수동 개입 옵션

### DLQ 항목 상태

| 상태 | 의미 | 액션 |
|------|------|------|
| **Pending** | 처음 실패한 요청 | 원인 분석 → 재시도 또는 수정 |
| **Retrying** | 재시도 진행 중 (3회 기본) | 대기 |
| **Failed** | 모든 재시도 실패 | 수동 개입 필요 |
| **Resolved** | 수동으로 해결됨 | 내역 보기 |

### DLQ 화면

```
┌──────────────────────────────────────────────────────┐
│ Writeback DLQ (외부 등록 실패 큐 모니터링)          │
├──────────────────────────────────────────────────────┤
│                                                      │
│ 📊 통계                                              │
│ ├─ Pending: 2개                                     │
│ ├─ Retrying: 1개                                    │
│ ├─ Failed: 3개                                      │
│ └─ 이주 해결됨: 12개                                │
│                                                      │
│ 필터: [상태] [날짜] [대상 시스템] [워크플로우]      │
│                                                      │
│ 📋 DLQ 항목 목록                                    │
│                                                      │
│ ┌─────────────────────────────────────────────────┐│
│ │ 1. Pending - SAP 연동 실패                     ││
│ │    워크플로우: vendor-creation-flow            ││
│ │    실패 시간: 2026-06-14 10:30                ││
│ │    에러: Connection refused (SAP 서버 다운)   ││
│ │    재시도: 0/3                                 ││
│ │    [상세] [재시도] [무시] [수정 후 재시도]     ││
│ └─────────────────────────────────────────────────┘│
│                                                      │
│ ┌─────────────────────────────────────────────────┐│
│ │ 2. Failed - Slack 알림 실패                    ││
│ │    대상: #notifications 채널                    ││
│ │    원인: Invalid token (토큰 만료)              ││
│ │    마지막 재시도: 2026-06-13 15:45            ││
│ │    [상세] [토큰 갱신] [무시]                   ││
│ └─────────────────────────────────────────────────┘│
│                                                      │
│ ...                                                 │
│                                                      │
└──────────────────────────────────────────────────────┘
```

### 실패 원인 분석

```
1. DLQ 항목 클릭 → [상세 보기]
2. 에러 정보 확인
   ├─ HTTP 상태 코드 (404, 500 등)
   ├─ 에러 메시지
   ├─ 요청 본문 (입력 데이터)
   └─ 응답 본문 (서버 답변)
3. 원인 파악
   ├─ 네트워크 문제: 재시도
   ├─ 데이터 오류: 수정 후 재시도
   ├─ 인증 오류: 자격증명 갱신
   └─ 기타: 수동 개입
```

### 복구 프로세스

**자동 재시도**:
```
1. [재시도] 버튼 → 지정된 횟수만큼 자동 재시도
2. 재시도 간격: 1분 → 5분 → 15분 (지수 백오프)
3. 실패 시 → 다시 대기열에 추가
```

**수동 수정**:
```
1. [수정 후 재시도] 클릭
2. 요청 본문 수정 (JSON 편집기)
   예) 금액 형식 수정, 필수 필드 추가
3. [재시도]
```

**무시**:
```
1. [무시] 클릭
2. 사유 입력 (선택사항)
3. DLQ에서 제거 (감사 로그에만 기록)
```
