# 스킬 관리 및 워크플로우 연결 매뉴얼

**문서 번호**: 14  
**대상 화면**: Skill Manager, Builder and Run  
**목적**: 워크플로우에서 재사용 가능한 실행 기능인 스킬을 이해하고, 워크플로우 노드와 연결하는 방법을 정리한다.

---

## 1. 스킬이란

스킬은 워크플로우 노드가 실행할 수 있는 기능 단위이다.

예:

```text
고객사 댓글 등록
공장 게시판 댓글 등록
정비지시 생성
온톨로지 객체 저장
RAG/온톨로지 조회
반복 고장 확인
요청 분류
```

워크플로우는 “절차”이고, 스킬은 그 절차 안에서 실제로 수행되는 “기능”이다.

---

## 2. 스킬을 별도로 관리하는 이유

스킬을 분리하면 다음 장점이 있다.

| 장점 | 설명 |
|---|---|
| 재사용 | 여러 워크플로우에서 같은 실행 기능을 공유 |
| 표준화 | 외부 시스템 호출 방식과 입력/출력 형식을 통일 |
| 교체 가능 | 같은 워크플로우에서 다른 구현체로 바꾸기 쉬움 |
| 감사 가능 | 어떤 기능이 어떤 입력으로 실행됐는지 추적 가능 |
| 확장 가능 | 고객사별 커스텀 기능을 추가하기 쉬움 |

---

## 3. 스킬 유형

| 유형 | 설명 | 예 |
|---|---|---|
| builtin | 플랫폼 내부에 기본 제공 | 요청 분류, 반복 고장 확인 |
| http | 일반 HTTP API 호출 | 외부 검색 API 호출 |
| mcp_http | MCP 중계 서버 호출 | comment.create, maintenance.create |
| custom | 사용자 정의 코드 또는 확장 기능 | 향후 확장 대상 |

현재 운영에서는 builtin, http, mcp_http 중심으로 사용하는 것이 안전하다.

---

## 4. Skill Manager 화면

Skill Manager에서는 등록된 스킬을 조회한다.

확인 항목:

- 스킬 ID
- 스킬 이름
- 스킬 유형
- 버전
- 입력 스키마
- 출력 스키마
- MCP/HTTP 호출 설정
- Built-in 또는 Custom 여부

데모에서는 “스킬이 워크플로우에서 재사용 가능한 실행 기능”이라는 점을 보여주는 정도가 적절하다.

---

## 5. 워크플로우에 스킬 노드 추가

1. `Builder and Run`으로 이동한다.
2. 좌측 노드 팔레트 또는 우측 스킬 탭에서 사용할 스킬을 선택한다.
3. 캔버스에 스킬 노드를 추가한다.
4. 노드를 선택하고 속성에서 `skillId`, `version`, 입력 설정을 확인한다.
5. 이전 노드와 연결선을 만든다.
6. 다음 노드와 연결한다.
7. 저장 후 실행한다.

---

## 6. 입력 매핑 개념

스킬은 고정 입력값 또는 이전 노드 결과를 입력으로 받을 수 있다.

예:

```json
{
  "question_id": "{{nodes.request_input.output.question_id}}",
  "comment": "{{nodes.draft_response.output.reply_text}}",
  "mode": "post"
}
```

의미:

- `question_id`는 요청 입력 노드의 결과에서 가져온다.
- `comment`는 답변 생성 노드의 결과에서 가져온다.
- `mode`는 고정값으로 `post`를 사용한다.

---

## 7. 스킬 실행 결과 확인

워크플로우 실행 후 우측 패널의 `입출력` 탭에서 확인한다.

확인할 것:

- 스킬에 전달된 입력값
- 렌더링된 실제 입력값
- 스킬 실행 출력
- 오류 메시지
- 외부 호출 결과

스킬 실행이 실패하면 노드 상태가 실패로 표시되고, Workflow Trace에서 더 자세한 원인을 확인한다.

---

## 8. 스킬과 온톨로지의 관계

스킬은 실행 기능이고, 온톨로지는 업무 의미를 저장한다.

예:

| 스킬 | 온톨로지 저장 결과 |
|---|---|
| customer-comment-create | ExternalComment 객체 생성 |
| factory-maintenance-create | MaintenanceTask 객체 생성 |
| ontology-write | 지정한 객체와 관계 저장 |
| fault-recurrence-check | FaultEvent의 반복 여부 속성 갱신 |

스킬이 직접 온톨로지를 저장할 수도 있고, 스킬 결과를 별도 ontology write 노드가 저장할 수도 있다.

---

## 9. 설계 시 주의 사항

- 스킬 ID는 업무 의미가 드러나게 작성한다.
- 스킬 입력/출력 스키마를 문서화한다.
- 외부 시스템 직접 호출보다 MCP 중계를 우선한다.
- Custom Skill은 운영 안정성, 권한, 보안 검토 후 활성화한다.
- 스킬 실패 시 재시도와 감사 로그 정책을 함께 설계한다.

---

## 10. 데모 설명 문장

```text
스킬은 워크플로우 블록이 실제로 수행할 수 있는 기능입니다.
예를 들어 댓글 등록, 정비지시 생성, 온톨로지 저장, RAG 조회 같은 기능을 스킬로 관리하면
여러 워크플로우에서 같은 기능을 재사용하고,
고객사별로 다른 외부 시스템도 같은 방식으로 연결할 수 있습니다.
```
