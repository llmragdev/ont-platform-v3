# 메뉴별 화면 상세 및 향후 기능 매뉴얼

**문서 번호**: 17  
**대상 화면**: Ontology Console v5 전체 좌측 메뉴  
**기준 파일**: `Sidebar.tsx`, `page.tsx`, `frontend/src/components/*`  
**목적**: 좌측 메뉴별 화면을 사용자가 이해할 수 있도록 화면 구성, 확인 항목, 사용 절차, 현재 한계, 향후 추가 기능을 정리한다.

---

## 1. 문서 사용 방법

이 문서는 메뉴 이름만 설명하는 문서가 아니다.  
각 메뉴를 눌렀을 때 사용자가 화면에서 무엇을 봐야 하고, 어떤 작업을 해야 하며, 향후 어떤 기능이 추가되어야 하는지 설명한다.

| 항목 | 설명 |
|---|---|
| 화면 목적 | 이 화면이 왜 필요한지 |
| 주요 화면 구성 | 화면에서 보이는 영역 |
| 사용자가 확인할 것 | 시연 또는 운영 중 봐야 하는 정보 |
| 주요 작업 | 사용자가 실제로 수행하는 작업 |
| 현재 한계 | 지금 화면에서 부족하거나 오해될 수 있는 부분 |
| 향후 추가 기능 | 제품화 또는 납품 전 보강하면 좋은 기능 |

---

## 2. 워크플로우 메뉴

워크플로우 메뉴는 이 솔루션의 중심이다.  
업무 흐름을 만들고, 실행하고, 실행 결과를 추적하는 화면들이 모여 있다.

---

### 2.1 워크플로우 홈

**화면 목적**  
프로젝트의 워크플로우 현황을 한눈에 보고, 템플릿/실행/추적 화면으로 진입하는 시작 화면이다.

**주요 화면 구성**

| 영역 | 설명 |
|---|---|
| 요약 카드 | 활성 워크플로우, 최근 실행, 성공/실패 현황 |
| 최근 템플릿 | 바로 복제하거나 열 수 있는 템플릿 |
| 최근 실행 | 최근 실행된 워크플로우 상태 |
| 바로가기 | 템플릿 갤러리, 빌더와 실행, 실행 추적 이동 |

**사용자가 확인할 것**

- 현재 프로젝트에 어떤 워크플로우가 있는가
- 최근 실행이 성공했는가
- 실패 또는 대기 중인 실행이 있는가
- 데모를 시작할 워크플로우가 준비되어 있는가

**주요 작업**

```text
워크플로우 홈
  -> 최근 템플릿 확인
  -> 빌더와 실행 이동
  -> 최근 실행 상태 확인
```

**현재 한계**

- 홈 화면이 단순 요약에 머물면 업무 담당자가 다음 행동을 판단하기 어렵다.
- 실행 실패 원인이나 외부 등록 실패 여부까지 한눈에 보이기 어렵다.

**향후 추가 기능**

- 업무 시나리오별 카드 제공: 고객사 문의, 공장 정비, 승인 업무 등
- 최근 실패 실행에 대한 원인 요약
- “데모 시작” 버튼 제공
- 사용자 역할별 추천 작업 표시
- 회사/프로젝트별 워크플로우 사용량 차트

---

### 2.2 템플릿 갤러리

**화면 목적**  
미리 정의된 업무 자동화 템플릿을 복제해서 프로젝트 워크플로우로 만드는 화면이다.

**주요 화면 구성**

| 영역 | 설명 |
|---|---|
| 템플릿 목록 | 사용 가능한 업무 흐름 템플릿 |
| 템플릿 상세 | 목적, 단계, 사용 스킬, 온톨로지 매핑 정보 |
| 복제 버튼 | 템플릿을 현재 프로젝트 워크플로우로 복제 |
| 카테고리/검색 | 도메인 또는 업무 유형별 템플릿 탐색 |

**사용자가 확인할 것**

- 고객사 자동댓글 템플릿이 있는가
- 공장 자동화 정비지시 템플릿이 있는가
- 템플릿이 어떤 온톨로지 객체와 연결되는가
- 복제 후 수정 가능한가

**주요 작업**

```text
템플릿 선택
  -> 상세 확인
  -> Clone 또는 복제
  -> 워크플로우 이름 입력
  -> 빌더와 실행 화면에서 수정
```

**현재 한계**

- 템플릿 간 차이가 화면에서 직관적으로 비교되지 않을 수 있다.
- 템플릿이 어떤 외부 시스템을 호출하는지 더 명확히 보여줄 필요가 있다.

**향후 추가 기능**

- 템플릿 미리보기 다이어그램
- 템플릿별 필요 서비스 체크리스트
- 템플릿 버전 관리
- 템플릿 복제 시 company_id/project_id 적용 내역 표시
- 템플릿별 데모 데이터 자동 생성

---

### 2.3 빌더와 실행

**화면 목적**  
워크플로우를 캔버스에서 편집하고, 즉시 실행하며, 실행 중인 블록 상태와 입출력을 확인하는 핵심 화면이다.

**주요 화면 구성**

| 영역 | 설명 |
|---|---|
| 상단 바 | 워크플로우 선택, 이름, 저장, 복제, 실행, 삭제 |
| 실행 설정 | 실행 모드, status, 처리 건수, 재수행 옵션 |
| 노드 팔레트 | 입력, 분류, 자산 매핑, 반복 확인, RAG, MCP 등 블록 |
| 캔버스 | 워크플로우 블록과 연결선 |
| 우측 패널 | 실행 현황, 선택 항목, 입출력, 온톨로지, 이력 |

**사용자가 확인할 것**

- 현재 선택한 워크플로우가 맞는가
- 실행 모드가 `dry_run`인지 `post`인지
- 처리 건수가 데모에 맞게 1로 되어 있는가
- 실행 중 블록이 색상/상태로 표시되는가
- 실행 완료 후 블록별 결과가 우측 패널에 보이는가

**주요 작업**

```text
워크플로우 선택
  -> 노드 배치
  -> 연결선 생성
  -> 필요 없는 블록 또는 선 삭제
  -> 저장
  -> 실행
  -> 입출력 확인
  -> 온톨로지 매핑 확인
```

**현재 한계**

- 블록 속성과 워크플로우 전체 속성이 한 패널 안에 있으면 사용자가 혼동할 수 있다.
- 연결선 선택/삭제, 분기 조건 편집은 더 직관적이어야 한다.
- 실행 중 상태, 성공, 실패, 미실행 상태가 더 강하게 시각화될 필요가 있다.
- 노드가 많아지면 화면이 좁고 흐름을 따라가기 어렵다.

**향후 추가 기능**

- 실행 중 자동 포커싱과 단계별 하이라이트
- 블록 상태 범례: 미실행, 실행 중, 성공, 실패, 건너뜀
- 연결선 라벨 편집과 조건 분기 편집 UI
- 미니맵, 자동 정렬, 단계별 그룹 접기
- 선택 항목 패널과 전체 워크플로우 설정 패널 분리
- 실행 전 유효성 검사: 끊어진 선, 필수 입력 누락, 스킬 미설정
- 블록별 재실행
- 실행 결과를 타임라인으로 재생하는 기능

### 2.4 스킬 관리

**화면 목적**  
워크플로우 노드에서 재사용할 실행 기능을 관리하는 화면이다.

**주요 화면 구성**

| 영역 | 설명 |
|---|---|
| 스킬 요약 | 전체 스킬 수, Built-in, Custom, MCP/HTTP 유형 |
| 검색/필터 | 스킬 이름, 유형, 태그 기준 검색 |
| 스킬 카드 | 스킬 ID, 이름, 유형, 버전, 설명 |
| 스키마 영역 | 입력 스키마, 출력 스키마 |
| 커스텀 스킬 | 향후 사용자 정의 스킬 생성 영역 |

**사용자가 확인할 것**

- 어떤 스킬을 워크플로우에서 사용할 수 있는가
- 스킬이 외부 API/MCP를 호출하는가
- 입력값과 출력값은 무엇인가
- 현재 스킬이 Built-in인지 Custom인지

**주요 작업**

```text
스킬 검색
  -> 스킬 상세 확인
  -> 입력/출력 스키마 확인
  -> 빌더에서 해당 스킬 노드로 사용
```

**현재 한계**

- Custom Skill 생성/수정/삭제 기능은 아직 운영 수준으로 더 다듬어야 한다.
- 스킬 테스트 실행 화면이 별도로 필요하다.
- 스킬이 어떤 워크플로우에서 사용 중인지 추적이 필요하다.

**향후 추가 기능**

- 스킬 생성 마법사
- 스킬별 테스트 실행 패널
- 스킬 버전 관리
- 사용 중인 워크플로우 목록 표시
- 스킬 권한 관리
- 스킬 실행 감사 로그
- MCP 연결 상태 테스트 버튼

---

### 2.5 실행 추적

**화면 목적**  
워크플로우 실행 결과와 온톨로지 저장 흐름을 추적하는 화면이다.

**주요 화면 구성**

| 영역 | 설명 |
|---|---|
| 실행 목록 | 워크플로우 실행 이력 |
| 실행 상세 | 실행 상태, 시작/종료 시간, 오류 |
| 단계별 결과 | 노드별 성공/실패, 입력/출력 |
| 온톨로지 흐름 | 생성된 객체와 관계 |

**사용자가 확인할 것**

- 어떤 워크플로우가 언제 실행되었는가
- 실행 결과가 성공인지 실패인지
- 어떤 노드에서 오류가 났는가
- 어떤 온톨로지 객체가 생성되었는가

**주요 작업**

```text
실행 선택
  -> 상태 확인
  -> 노드별 결과 확인
  -> 온톨로지 연결 확인
  -> 필요 시 재실행 또는 장애 분석
```

**현재 한계**

- 빌더 화면의 실행 이력과 실행 추적 화면의 역할 경계가 더 명확해야 한다.
- 워크플로우별 이력 필터가 더 강화되어야 한다.

**향후 추가 기능**

- 워크플로우별 실행 이력 타임라인
- 실패 노드 기준 필터
- 외부 MCP 호출 결과와 payload 보기
- 실행 이력 비교
- 재실행 버튼
- 실행 로그 다운로드

---

### 2.6 승인 워크플로우

**화면 목적**  
AI 또는 워크플로우가 만든 결과를 사람이 승인, 반려, 보류하는 상태 전이 화면이다.

**주요 화면 구성**

| 영역 | 설명 |
|---|---|
| 승인 대기 목록 | 사람 검토가 필요한 항목 |
| 상세 정보 | 요청 내용, AI 판단, 근거 |
| 액션 버튼 | 승인, 반려, 보류, 담당자 지정 |
| 상태 이력 | 이전 상태와 변경 이력 |

**사용자가 확인할 것**

- 어떤 항목이 사람 승인을 기다리는가
- AI가 제안한 조치가 무엇인가
- 근거가 충분한가
- 승인하면 어떤 외부 실행이 발생하는가

**주요 작업**

```text
승인 대상 선택
  -> 상세와 근거 확인
  -> 승인 또는 반려
  -> 상태 변경 이력 확인
```

**현재 한계**

- 현재 자동 실행 시나리오와 승인 시나리오의 연결이 더 명확히 보일 필요가 있다.
- 역할 기반 권한 체계가 도메인 역할과 플랫폼 역할로 분리되어야 한다.

**향후 추가 기능**

- 승인 정책 설정
- 다단계 승인
- 승인 전/후 외부 실행 미리보기
- 담당자 자동 추천
- SLA/마감 시간 표시
- 승인 사유 필수 입력

---

### 2.7 Writeback DLQ

**화면 목적**  
외부 시스템 등록 실패 건을 모니터링하고 재처리하는 화면이다.

**주요 화면 구성**

| 영역 | 설명 |
|---|---|
| 실패 목록 | 외부 등록 실패 건 |
| 실패 상세 | target, payload, error, retry count |
| 재처리 액션 | 단건 재시도, 무시, 보류 |
| 필터 | 상태, 시스템, 시간, 워크플로우 기준 |

**사용자가 확인할 것**

- 댓글 또는 정비지시 등록 실패가 있는가
- 실패 원인이 외부 시스템 장애인지 payload 오류인지
- 재처리가 가능한가

**주요 작업**

```text
실패 건 선택
  -> 오류 메시지 확인
  -> payload 확인
  -> 재처리 또는 보류
```

**현재 한계**

- 실패 건이 워크플로우 실행 이력과 강하게 연결되어야 한다.
- 재시도 정책과 수동 재처리 권한이 더 명확해야 한다.

**향후 추가 기능**

- 자동 재시도 정책 설정
- Dead Letter 사유 분류
- payload 수정 후 재처리
- 외부 시스템별 장애 대시보드
- 알림 연동

## 3. 온톨로지 메뉴

온톨로지 메뉴는 업무 데이터의 의미와 관계를 관리한다.

---

### 3.1 관계 탐색

**화면 목적**  
온톨로지 객체와 관계를 그래프로 조회하는 화면이다.

**주요 화면 구성**

| 영역 | 설명 |
|---|---|
| 그래프 캔버스 | 객체 노드와 관계 선 |
| 객체 상세 | 선택한 객체의 속성 |
| 관계 목록 | incoming/outgoing 관계 |
| 타입 필터 | 객체 타입별 보기 |

**사용자가 확인할 것**

- 워크플로우 실행 결과가 어떤 객체로 저장되었는가
- 요청, 댓글, 정비지시, 설비가 어떻게 연결되는가
- 특정 객체의 incoming/outgoing 관계가 무엇인가

**현재 한계**

- 그래프가 겹치거나 선이 꼬이면 업무 흐름이 잘 보이지 않는다.
- 조회 화면과 편집 화면의 역할 차이가 명확히 보여야 한다.

**향후 추가 기능**

- 자동 레이아웃 알고리즘 선택
- 관계 경로 하이라이트
- 워크플로우 실행 ID 기준 그래프 필터
- 객체 타입별 색상 범례
- 선택 객체에서 관련 워크플로우 실행으로 이동

---

### 3.2 스키마 관리

**화면 목적**  
온톨로지의 엔티티 타입, 속성, 관계 타입을 정의하는 화면이다.

**주요 화면 구성**

| 영역 | 설명 |
|---|---|
| 엔티티 타입 목록 | ServiceRequest, Equipment 등 |
| 속성 정의 | 이름, 타입, 필수 여부 |
| 관계 타입 목록 | has_reply, affects 등 |
| 스키마 저장/검증 | 구조 변경 전 검증 |

**사용자가 확인할 것**

- 현재 도메인에 어떤 객체 타입이 있는가
- 어떤 관계 타입이 정의되어 있는가
- 워크플로우 매핑에서 사용할 타입이 준비되어 있는가

**현재 한계**

- 스키마 변경이 기존 인스턴스와 워크플로우에 미치는 영향이 더 잘 보여야 한다.

**향후 추가 기능**

- 스키마 변경 영향도 분석
- 스키마 버전 관리
- 템플릿 스키마 설치/삭제
- 필수 속성 검증
- 워크플로우 매핑과 스키마 자동 비교

---

### 3.3 인스턴스 편집

**화면 목적**  
실제 온톨로지 객체 데이터를 생성하고 수정하는 화면이다.

**주요 화면 구성**

| 영역 | 설명 |
|---|---|
| 객체 타입 선택 | 어떤 타입의 인스턴스를 볼지 선택 |
| 인스턴스 목록 | 저장된 객체 목록 |
| 상세 편집 | 속성 수정 |
| 저장/삭제 | 객체 변경 반영 |

**사용자가 확인할 것**

- 테스트용 공장, 라인, 설비 데이터가 있는가
- 워크플로우 실행으로 생성된 객체가 정상인가
- 객체 속성이 업무적으로 맞는가

**현재 한계**

- 관계 편집과 속성 편집이 분리되어 있어 처음 보는 사람은 흐름을 이해하기 어렵다.

**향후 추가 기능**

- 객체 생성 마법사
- 관계까지 함께 편집하는 폼
- CSV/Excel 가져오기
- 변경 이력 표시
- 필수 속성 누락 경고

---

### 3.4 관계 그래프 편집

**화면 목적**  
객체 간 관계를 시각적으로 편집하고 배치하는 화면이다.

**주요 화면 구성**

| 영역 | 설명 |
|---|---|
| 그래프 캔버스 | 편집 가능한 객체와 관계 |
| 객체 추가 | 기존 객체 또는 새 객체 추가 |
| 관계 연결 | 노드 간 관계 생성 |
| 속성 패널 | 선택 객체/관계 상세 |

**사용자가 확인할 것**

- 객체가 어떤 관계로 연결되어 있는가
- 관계를 새로 만들거나 수정할 수 있는가
- 화면 배치가 이해하기 쉬운가

**현재 한계**

- 관계선 선택, 삭제, 라벨 편집, 자동 정렬이 더 강화되어야 한다.
- 하드코딩처럼 보이는 타입 태그는 스키마 기반으로 명확히 표시되어야 한다.

**향후 추가 기능**

- 드래그 앤 드롭 관계 생성
- 관계선 삭제/수정/라벨 변경
- 스키마 기반 허용 관계 추천
- 그래프 레이아웃 저장
- 선택 객체에서 인스턴스 편집 화면 이동
- 잘못된 관계 검증

---

### 3.5 RDF 워크벤치

**화면 목적**  
외부 RDF 또는 연결 데이터를 가져오고 내부 온톨로지와 매핑하는 화면이다.

**주요 화면 구성**

| 영역 | 설명 |
|---|---|
| RDF 입력/업로드 | RDF 파일 또는 URL 입력 |
| 파싱 결과 | 클래스, 속성, 관계 미리보기 |
| 매핑 설정 | 내부 스키마와 연결 |
| 가져오기 결과 | 성공/실패, 생성 객체 수 |

**사용자가 확인할 것**

- 외부 RDF가 정상 파싱되는가
- 내부 스키마와 어떤 타입으로 연결되는가
- 가져온 데이터가 관계 탐색에서 보이는가

**현재 한계**

- 일반 업무 사용자에게 RDF 개념은 어렵기 때문에 고급 관리 메뉴로 분리하는 것이 좋다.

**향후 추가 기능**

- RDF 샘플 템플릿
- 매핑 추천
- import 전 영향도 미리보기
- Wikidata/DBpedia 같은 외부 소스 커넥터
- 가져오기 롤백

---

## 4. 질의와 분석 메뉴

질의와 분석 메뉴는 사용자가 저장된 업무 데이터와 문서 지식에 질문하는 영역이다.

---

### 4.1 대시보드

**화면 목적**  
운영 상태, 작업 큐, 주요 지표를 요약해 보여주는 화면이다.

**주요 화면 구성**

| 영역 | 설명 |
|---|---|
| 지표 카드 | 대기, 진행, 완료, 실패 수 |
| 작업 큐 | 처리 대상 목록 |
| 상태별 분포 | 업무 상태 요약 |
| 최근 변화 | 최근 실행 또는 변경 내역 |

**향후 추가 기능**

- 시나리오별 KPI
- 워크플로우 성공률/실패율
- 평균 처리 시간
- 외부 등록 실패율
- 테넌트/프로젝트별 비교

---

### 4.2 객체 탐색

**화면 목적**  
온톨로지 객체를 검색하고 상세 속성을 빠르게 확인하는 화면이다.

**주요 화면 구성**

| 영역 | 설명 |
|---|---|
| 검색창 | 객체 이름, ID, 타입 검색 |
| 결과 목록 | 검색된 객체 목록 |
| 상세 패널 | 선택 객체 속성 |
| 관련 객체 | 연결된 주요 관계 |

**향후 추가 기능**

- 고급 필터
- 최근 본 객체
- 객체에서 관계 탐색 화면 이동
- 객체에서 관련 워크플로우 실행 이력 이동
- 즐겨찾기

---

### 4.3 온톨로지 질의

**화면 목적**  
자연어 질문을 통해 온톨로지 객체와 관계 기반 답변을 받는 화면이다.

**주요 화면 구성**

| 영역 | 설명 |
|---|---|
| 질문 입력 | 자연어 업무 질문 |
| 예시 질문 | 사용자가 바로 눌러볼 질문 |
| 답변 영역 | AI 답변 |
| 근거 객체 | 답변에 사용된 온톨로지 객체 |

**향후 추가 기능**

- 질문 의도 분석 표시
- 사용된 그래프 경로 표시
- 답변 신뢰도
- 답변에서 객체 클릭 시 상세 이동
- 질의 템플릿 저장

---

### 4.4 통합 질의

**화면 목적**  
온톨로지 구조 데이터와 문서 RAG 근거를 결합해 질문하는 화면이다.

**주요 화면 구성**

| 영역 | 설명 |
|---|---|
| 질문 입력 | 복합 질문 입력 |
| 온톨로지 결과 | 관련 객체/관계 |
| RAG 근거 | 관련 문서 조각 |
| 종합 답변 | 객체 관계와 문서 근거를 결합한 답변 |

**향후 추가 기능**

- 온톨로지/RAG 기여도 분리 표시
- 근거 충돌 감지
- 답변 출처별 색상 구분
- 후속 질문 추천
- 보고서 형태 내보내기

---

### 4.5 문서 RAG 질의

**화면 목적**  
문서 기반 근거를 검색하고 답변을 생성하는 화면이다.

**주요 화면 구성**

| 영역 | 설명 |
|---|---|
| 질문 입력 | 문서 기반 질문 |
| 검색 결과 | 관련 문서 조각 |
| 답변 | 근거 기반 생성 답변 |
| 출처 | 문서명, 페이지, 점수 |

**향후 추가 기능**

- 문서 업로드/인덱싱 관리
- 출처 문서 미리보기
- 답변 근거 하이라이트

| 그래프 미리보기 | 결과 관계 시각화 |

**향후 추가 기능**

- 쿼리 템플릿
- 자동 완성
- 쿼리 실행 계획
- 제한 시간/결과 수 경고
- 쿼리 저장과 공유

## 5. 운영과 검증 메뉴

운영과 검증 메뉴는 실제 운영 환경에서 신뢰성을 확보하기 위한 화면이다.

---

### 5.1 감사 로그

**화면 목적**  
사용자 작업, 상태 변경, 외부 호출 이력을 추적하는 화면이다.

**주요 화면 구성**

| 영역 | 설명 |
|---|---|
| 로그 필터 | 기간, 사용자, 액션, 상태 |
| 로그 목록 | 감사 이벤트 목록 |
| 상세 보기 | payload, 이전/이후 값, 외부 시스템 |
| 다운로드 | CSV 등 내보내기 |

**사용자가 확인할 것**

- 누가 어떤 워크플로우를 실행했는가
- 외부 시스템에 어떤 요청이 나갔는가
- 실패한 호출이 있는가
- 상태 변경 이력이 남았는가

**향후 추가 기능**

- 워크플로우 실행 ID 기준 필터
- 외부 MCP 호출 payload 마스킹
- 민감정보 자동 제거
- 감사 리포트 다운로드
- 이상 행위 탐지

---

### 5.2 통합 테스트

**화면 목적**  
워크플로우, RAG, 온톨로지, 외부 호출이 정상 동작하는지 검증하는 화면이다.

**주요 화면 구성**

| 영역 | 설명 |
|---|---|
| 테스트 시나리오 목록 | 고객사 문의, 공장 정비 등 |
| 실행 버튼 | 테스트 실행 |
| 결과 요약 | 성공/실패, 오류 수 |
| 상세 결과 | 단계별 테스트 결과 |

**사용자가 확인할 것**

- 배포 전 주요 시나리오가 정상인지
- RAG 답변과 온톨로지 근거가 연결되는지
- 외부 writeback이 성공하는지
- 최근 변경으로 기존 기능이 깨지지 않았는지

**향후 추가 기능**

- 테스트 케이스 편집
- 기대 결과와 실제 결과 비교
- 회귀 테스트 자동 실행
- 테스트 리포트 저장
- CI/CD 연동

## 6. 메뉴별 향후 기능 우선순위

제품화 관점에서는 모든 기능을 한 번에 추가하기보다 아래 순서가 적절하다.

| 우선순위 | 메뉴 | 추가 기능 |

| 1 | 빌더와 실행 | 블록 상태 시각화, 입출력 강화, 선/블록 편집 완성 |
| 2 | 실행 추적 | 워크플로우별 실행 이력, 실패 원인 추적 |
| 3 | 관계 탐색 | 실행 결과 기반 그래프 필터와 경로 하이라이트 |
| 4 | 스킬 관리 | 스킬 테스트 실행, Custom Skill 관리 |
| 5 | 감사 로그 | MCP 호출 이력과 payload 마스킹 |

| 7 | 스키마 관리 | 스키마 버전과 영향도 분석 |
| 8 | 통합 질의 | RAG/온톨로지 근거 분리 표시 |

## 7. 납품용 화면 기획 보완 방향

현재 화면은 PoC와 기술 검증에는 충분히 의미가 있다.  
기업 납품용으로 보이려면 다음 방향으로 정리하는 것이 좋다.

| 방향 | 설명 |
|---|---|
| 업무 중심 진입 | 기술 메뉴보다 고객사 문의, 공장 정비 같은 업무 카드로 시작 |
| 역할별 메뉴 | 일반 사용자, 업무 설계자, 관리자, 개발자 메뉴 분리 |
| 실행 중심 화면 | Run 후 단계별 상태, 입출력, 외부 결과가 한 화면에서 보이게 구성 |
| 설명 가능한 AI | 답변, 근거 문서, 온톨로지 관계, 실행 로그를 함께 표시 |
| 운영 안정성 | DLQ, 감사 로그, 통합 테스트를 운영 콘솔로 묶기 |
| 설정 분리 | 스키마, 스킬, MCP, 권한 설정은 관리자 영역으로 분리 |

---

## 8. 데모용 설명 순서

외부 시연에서는 모든 메뉴를 하나씩 자세히 누르기보다 다음 흐름으로 설명한다.

```text
1. 워크플로우 홈
   - 현재 자동화 업무 현황

2. 빌더와 실행
   - 업무 흐름을 보고 실행

3. 실행 추적
   - 어떤 단계가 처리됐는지 확인

4. 관계 탐색
   - 실행 결과가 온톨로지 관계로 남았는지 확인

5. 통합 질의
   - 저장된 관계와 문서 근거를 질문

6. 감사 로그 또는 DLQ
   - 운영 환경에서 추적과 복구가 가능함을 설명
```
