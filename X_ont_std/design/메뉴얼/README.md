## ⚡ 주요 개념 정리

### 워크플로우
- **정의**: 단계별 업무 처리 과정
- **구성**: 노드(작업) + 간선(연결) + 스킬(실행)
- **실행**: START → 여러 노드 → END
- **결과**: 온톨로지에 자동 저장 가능

### 온톨로지
- **정의**: 구조화된 데이터 모델
- **구성**: 엔티티(객체) + 관계(연결) + 속성(특성)
- **스키마**: 데이터 타입 정의
- **인스턴스**: 실제 데이터

### 스킬
- **정의**: 재사용 가능한 작업 단위
- **타입**: 내장(온톨로지, RAG), HTTP, MCP, Custom
- **입력/출력**: JSON 스키마로 정의
- **사용**: 워크플로우 노드에서 호출

### 질의
- **온톨로지 질의**: AI 기반 자연어 → SPARQL 변환
- **RAG 질의**: 문서 검색 기반 답변
- **통합 질의**: 구조 + 문서 결합
- **SPARQL**: 전문가용 정형 쿼리

## 🔧 자주 묻는 질문 (FAQ)

### Q1: 워크플로우와 스킬의 차이는?
**A**: 워크플로우는 전체 프로세스(START → A → B → END)이고, 스킬은 각 단계에서 실행되는 작업(A, B)입니다.

### Q2: 온톨로지에 데이터를 어떻게 저장하나요?
**A**: 3가지 방법:
1. 인스턴스 편집에서 직접 입력
2. CSV 일괄 가져오기
3. 워크플로우의 온톨로지 매핑으로 자동 저장

### Q3: SPARQL을 모르면 어떻게 하나요?
**A**: 온톨로지 질의(AI)를 사용하면 자연어로 쿼리합니다. SPARQL은 고급 기능입니다.

### Q4: 외부 시스템 연동은 어떻게 하나요?
**A**: 스킬로 HTTP 또는 MCP 기반 API 호출 → 결과를 온톨로지에 저장

### Q5: 데이터 삭제 시 복구 가능한가요?
**A**: 네, 감사 로그에서 삭제 기록 조회 → [복원] 버튼으로 복구 가능
