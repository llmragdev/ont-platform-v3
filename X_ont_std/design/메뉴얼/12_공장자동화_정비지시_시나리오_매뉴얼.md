# 공장자동화 정비지시 시나리오 매뉴얼

**문서 번호**: 12  
**시나리오**: Scenario 2 - 공장 현장 고장 요청 정비지시 자동화  
**대상 시스템**: ont_platform, s2_factory_board, s2_factory_mcp  
**목적**: 공장 현장에서 반복 고장 또는 품질 이상 요청이 접수되었을 때, 워크플로우가 원인과 조치 방향을 판단하고 정비지시 또는 안내 댓글을 등록한다.

---

## 1. 시나리오 개요

공장 자동화 시나리오는 단순 문의 응답보다 업무 가치가 더 직관적이다.  
현장 요청, 설비, 생산 라인, 공정 단계, 고장 이력, 품질 이슈를 연결해 “반복 고장인지”, “품질 문제인지”, “정비지시가 필요한지”를 판단한다.

```text
현장 고장 요청 접수
  -> 요청 유형 분류
  -> 공장/라인/설비 매핑
  -> 반복 고장 여부 확인
  -> 품질 영향 또는 정비 필요성 판단
  -> 정비지시 또는 현장 안내 댓글 생성
  -> 공장 MCP 서버 호출
  -> 모의 게시판에 결과 등록
  -> 온톨로지에 설비/고장/정비 관계 저장
```

---

## 2. 예시 업무 상황

기술 설명보다 아래처럼 현장 언어로 설명하는 것이 좋다.

```text
세종 배터리팩 공장 3번 조립 라인에서
검사 카메라 촬영 품질이 10시와 11시에 반복적으로 떨어졌습니다.
현장 담당자가 고장 요청을 등록하면,
워크플로우가 동일 설비의 반복 고장인지 확인하고
정비 확인 지시 또는 품질 점검 안내를 생성합니다.
```

다른 예시:

```text
화성 전장 모듈 공장 2번 테스트 라인에서
토크 체결기 압력 값이 기준보다 낮게 반복 측정되었습니다.
시스템은 설비 고장 가능성과 품질 영향 여부를 함께 판단하고
정비 담당자에게 조치 요청을 남깁니다.
```

## 4. 공장 게시판에서 요청 만들기

1. 브라우저에서 `http://127.0.0.1:8091`을 연다.
2. 자동 Webhook 테스트가 아니라면 Webhook 자동 트리거를 끈다.
3. 수동등록 또는 데모 시나리오 순차 입력을 사용해 현장 요청을 만든다.
4. 댓글 또는 정비지시가 아직 없는 상태인지 확인한다.

권장 입력 예시:

```text
제목: [품질] 3번 조립 라인 배터리 탭 불량 증가
공장/라인: 세종 배터리팩 공장 > 3번 조립 라인
공정/설비: 검사 단계 > 검사 카메라
내용: 용접기 재가동 이후부터 검사 카메라 촬영 품질이 평소 대비 4% 이상 저하되어 불량이 대량 잡힙니다. 배터리 탭 외관 치수 점검 및 품질 위원회 조사가 권장됩니다.
```

## 5. 워크플로우 구성 이해

공장 자동화 워크플로우는 일반적인 “3번 조립 처리” 같은 모호한 단계가 아니라, 현장 요청 처리에 필요한 업무 단계로 구성되어야 한다.

권장 단계:

| 순서 | 단계 | 의미 |
|---:|---|---|
| 1 | 현장 요청 입력 | 게시판의 고장/품질 요청을 가져온다 |
| 2 | 고장/품질 분류 | 설비 고장인지 품질 이슈인지 판단한다 |
| 3 | 공장/라인/설비 매핑 | 요청 내용을 실제 공장 자산과 연결한다 |
| 4 | 반복 여부 확인 | 같은 설비에서 반복 발생했는지 확인한다 |
| 5 | 상황 등록 | 고장 이벤트를 온톨로지에 기록한다 |
| 6 | 정비 확인권 생성 | 정비가 필요한 경우 작업 지시를 만든다 |
| 7 | 품질 문제 연결 | 품질 영향이 있으면 품질 이슈와 연결한다 |
| 8 | 현장 안내 생성 | 작업자에게 남길 안내 메시지를 생성한다 |
| 9 | 정비/품질 알림 | 담당자 또는 게시판에 결과를 남긴다 |

---

## 6. 워크플로우 실행

1. ont_platform 콘솔에서 `Builder and Run`으로 이동한다.
2. 공장 자동화 워크플로우를 선택한다.
3. 실행 설정을 확인한다.

| 항목 | 권장값 |
|---|---|
| 실행 모드 | `post` |
| status | `open` |
| 처리 건수 | `1` |
| 이미 처리한 요청도 재수행 | 반복 시연 시 체크 |

4. `Run`을 클릭한다.
5. 블록별 실행 상태가 바뀌는지 확인한다.
6. 우측 패널에서 `completed`, 진행률 100%, 오류 0을 확인한다.

## 7. 결과 확인

### 7.1 공장 모의 게시판

확인 항목:

- 현장 요청 상세 화면에 댓글이 등록되었는지
- 정비 지시서 영역에 작업 지시가 생성되었는지
- 요청 상태가 처리 또는 안내 완료 상태로 바뀌었는지

### 7.2 온톨로지 관계

확인할 객체:

```text
ServiceRequest
Factory
ProductionLine
ProcessStep
Equipment
FaultEvent
MaintenanceTask
QualityIssue
```

확인할 관계:

```text
Factory -> has_line -> ProductionLine
ProductionLine -> has_step -> ProcessStep
ProcessStep -> uses -> Equipment
ServiceRequest -> reports -> FaultEvent
FaultEvent -> affects -> Equipment
FaultEvent -> creates -> MaintenanceTask
QualityIssue -> possibly_caused_by -> FaultEvent
```

## 8. 데모 설명 문장

```text
이 시나리오는 공장 게시판의 고장 요청을 단순 접수하는 것이 아니라,
요청 내용을 공장, 생산 라인, 공정, 설비, 고장 이력과 연결합니다.
그 결과 반복 고장인지, 품질 영향이 있는지, 정비지시가 필요한지를 워크플로우로 판단하고
그 결과를 게시판과 온톨로지에 동시에 남깁니다.
```

## 9. 실패 시 점검

| 증상 | 원인 후보 | 조치 |
|---|---|---|
| 게시판 댓글이 없음 | s2_factory_mcp 미기동 | MCP 서버 실행 확인 |
| 404 Not Found | target URL 불일치 | 게시판 설정의 Webhook Target 확인 |
| 워크플로우가 running 유지 | 마지막 노드 완료 처리 누락 | Workflow Trace와 backend 로그 확인 |
| 정비지시가 없음 | 분기 조건이 안내 댓글 경로로 이동 | 입출력 탭에서 분류 결과 확인 |
| 온톨로지 관계가 없음 | ontology write 단계 실패 | 실행 이력의 ontology node 결과 확인 |
