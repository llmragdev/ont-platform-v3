# 스키마 관리 - 화면 상세 가이드

**메뉴**: 스키마 관리  
**목적**: 엔티티 타입 및 관계 타입 정의

---

## 📐 화면 구조

```
┌─────────────────────────────┐
│ [새 엔티티 타입] [새 관계]  │
├─────────────────────────────┤
│                             │
│ 📋 엔티티 타입 (5)          │
│                             │
│ ┌─ Project ────────────────┐│
│ │ ID: entity-type:Project │ │
│ │ 속성: 10개              │ │
│ │ 인스턴스: 42개          │ │
│ │ [편집] [삭제]          │ │
│ └────────────────────────┘ │
│                             │
│ 🔗 관계 타입 (8)            │
│                             │
│ ┌─ hasTeam ────────────────┐│
│ │ Domain: Project         │ │
│ │ Range: Team             │ │
│ │ Cardinality: 1:N        │ │
│ │ [편집] [삭제]          │ │
│ └────────────────────────┘ │
│                             │
└─────────────────────────────┘
```

## 🎯 엔티티 타입 에디터

```
기본 정보:
  ID: entity-type:Project
  이름: Project
  설명: 프로젝트 엔티티

속성 스키마:
  name (string, 필수)
  status (enum: active|inactive|archived)
  startDate (date)
  budget (number)
  [+ 속성 추가]

[저장] [취소]
```

---

## 🔗 관계 타입 에디터

```
ID: rel:hasTeam
이름: hasTeam
Domain: [Project▼]
Range: [Team▼]
Cardinality: [1:N▼]
설명: 프로젝트가 팀을 가짐

특성:
  ☐ 이행적 (transitive)
  ☐ 대칭적 (symmetric)
  ☐ 역관계 자동 생성

역관계: belongsToProject (자동)

[저장] [취소]
```

## 🚀 향후 기능

- [ ] **속성 유효성 규칙**: 정규식, 범위 검증
- [ ] **상속 관계**: 엔티티 타입 상속
- [ ] **제약 조건**: Cardinality 시각화
- [ ] **영향도 분석**: 스키마 변경 시 영향받는 인스턴스 수
- [ ] **버전 관리**: 스키마 변경 이력
- [ ] **마이그레이션**: 기존 데이터 자동 변환
