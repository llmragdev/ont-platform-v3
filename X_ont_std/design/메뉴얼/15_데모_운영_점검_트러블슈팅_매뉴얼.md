# 데모 운영 점검 및 트러블슈팅 매뉴얼

**문서 번호**: 15  
**대상**: 시연자, 개발자, 운영 담당자  
**목적**: 온톨로지+워크플로우+RAG 통합 솔루션을 데모하거나 테스트할 때 필요한 사전 점검, 실행 순서, 장애 대응 방법을 정리한다.

---

## 1. 데모 전 점검 체크리스트

| 항목 | 확인 |
|---|---|
| backend 8001 실행 | ont_platform API 정상 응답 |
| frontend 3002 실행 | 콘솔 화면 접속 가능 |
| 고객사 게시판 8090 | 문의 등록 및 댓글 확인 가능 |
| 공장 게시판 8091 | 현장 요청 등록 및 댓글/정비지시 확인 가능 |
| customer_mcp 실행 | 고객사 댓글 등록 중계 가능 |
| s2_factory_mcp 실행 | 공장 댓글/정비지시 등록 중계 가능 |
| 브라우저 캐시 | 이전 실행 결과로 혼동되지 않도록 새로고침 |
| 실행 모드 | dry_run 또는 post 확인 |
| 처리 건수 | 데모에서는 1 권장 |
| 재수행 옵션 | 이미 처리한 건을 다시 실행할 때 체크 |

## 2. 권장 데모 순서

### 2.1 짧은 데모

```text
1. 공장 게시판에서 현장 고장 요청 확인
2. ont_platform Builder and Run에서 워크플로우 실행
3. 블록별 실행 상태 확인
4. 공장 게시판에 댓글 또는 정비지시 등록 확인
5. Ontology Explorer에서 설비/고장/정비 관계 확인
```

### 2.2 전체 데모

```text
1. 고객사 문의 자동댓글 시나리오 실행
2. 공장 자동화 정비지시 시나리오 실행
3. Workflow Trace에서 실행 이력 확인
4. Ontology Explorer에서 관계 그래프 확인
5. Skill Manager에서 재사용 기능 구조 설명
6. 통합 질의 또는 RAG 화면에서 근거 검색 설명
```

## 4. 자주 발생하는 문제

### 4.1 frontend 실행 스크립트를 못 찾는 경우

증상:

```text
.\scripts\start_frontend.ps1 용어가 cmdlet으로 인식되지 않습니다.
```

원인:

- 현재 위치가 스크립트가 있는 폴더가 아니다.
- 스크립트 위치를 잘못 입력했다.

조치:

```powershell
cd E:\ontology_edu\X_ont_std\ont_platform\v5
.\scripts\start_frontend.ps1
```

스크립트 위치가 바뀌었으면 `RUNBOOK.md`를 기준으로 실행한다.

### 4.2 3002 포트가 이미 사용 중인 경우

증상:

```text
EADDRINUSE: address already in use :::3002
```

원인:

- 기존 frontend 서버가 이미 실행 중이다.

조치:

- 브라우저에서 `http://127.0.0.1:3002` 접속해 이미 떠 있는지 확인한다.
- 기존 서버를 사용할 수 있으면 새로 띄우지 않는다.
- 반드시 재기동이 필요하면 실행 중인 Node 프로세스를 확인 후 종료한다.

### 4.3 게시판에 댓글이 안 달리는 경우

확인 순서:

1. 워크플로우 상태가 `completed`인지 확인한다.
2. 실행 모드가 `post`인지 확인한다.
3. 처리 건수가 1 이상인지 확인한다.
4. 이미 처리한 건이면 재수행 옵션을 켰는지 확인한다.
5. MCP 서버가 실행 중인지 확인한다.
6. 게시판 target URL이 올바른지 확인한다.
7. Workflow Trace에서 MCP 호출 결과를 확인한다.

### 4.4 워크플로우가 계속 running으로 남는 경우

원인 후보:

- 마지막 노드 완료 상태 반영 누락
- 외부 호출 응답 대기
- frontend 상태 갱신 지연
- backend 실행 이력 저장 오류

조치:

- Workflow Trace에서 마지막 완료 노드를 확인한다.
- 게시판에는 결과가 등록됐는지 확인한다.
- 새로고침 후 상태가 바뀌는지 본다.
- 반복되면 backend 로그와 해당 workflow executor를 확인한다.

### 4.5 진행률이 100%가 아닌 경우

원인:

- 워크플로우 전체 노드 수와 실제 실행 대상 노드 수가 다르게 계산되었을 수 있다.
- 분기 노드 때문에 일부 노드는 실행되지 않는 것이 정상일 수 있다.

판단 기준:

- 상태가 completed이고 오류가 0이면 업무 처리는 성공일 수 있다.
- 데모 화면에서는 실제 실행 대상 기준으로 진행률을 계산하는 것이 좋다.

### 4.6 한글이 깨져 보이는 경우

원인:

- PowerShell 콘솔 인코딩 문제
- 파일 인코딩과 터미널 출력 인코딩 불일치
- frontend 번들 또는 JSON 파일 저장 인코딩 문제

조치:

- 브라우저 화면에서 깨지는지, 터미널에서만 깨지는지 구분한다.
- 실제 파일은 UTF-8로 저장한다.
- PowerShell 출력은 다음 설정을 사용할 수 있다.

```powershell
$OutputEncoding = [Console]::OutputEncoding = [System.Text.UTF8Encoding]::new()
```

## 5. 외부 공유 시 주의 사항

데모 영상을 외부에 보낼 때는 다음을 지킨다.

- 전체 소스 구조를 길게 노출하지 않는다.
- API key, 내부 경로, 개인 계정 정보가 보이지 않게 한다.
- 핵심 알고리즘이나 내부 구현 세부사항보다 업무 흐름과 결과를 보여준다.
- “완제품”보다 “작동형 PoC” 또는 “기술 검증 데모”로 표현한다.
- 경쟁사 가능성이 있는 회사에는 상세 설계 문서 전체를 보내지 않는다.

## 6. 운영 로그 확인 위치

환경에 따라 달라질 수 있으나 기본적으로 다음을 확인한다.

| 로그 | 확인 내용 |
|---|---|
| backend console | API 오류, workflow executor 오류 |
| Workflow Trace | 노드별 실행 상태와 입출력 |
| mock board log | Webhook 호출 성공/실패 |
| MCP audit log | 외부 중계 호출 결과 |
| storage 하위 run log | company_id/project_id별 실행 상태 |

---

## 7. 장애 대응 우선순위

장애가 발생하면 다음 순서로 본다.

```text
1. 화면 문제인지 서버 문제인지 구분
2. 워크플로우가 실행됐는지 확인
3. 외부 MCP 호출이 됐는지 확인
4. 게시판 등록 결과 확인
5. 온톨로지 저장 결과 확인
6. 동일 요청 재수행 여부 확인
```
