## 3. 프론트 UI 계약 보정

### 3.1 보정 이유

API는 v5.3 payload를 정상 반환하지만, UI 코드에서 다음 불일치가 있었다.

```text
1. SourcePanel이 _status="FILTERED"를 알지 못함
2. Backend limitations 이벤트는 배열인데 frontend는 { limitations: [] }만 기대
3. Backend follow_ups 이벤트는 배열인데 frontend는 { follow_up_suggestions: [] }만 기대
4. complete payload의 v5_3 객체가 Zustand store에 저장되지 않음
5. standalone /hybrid-query 페이지가 기본 projectId로 proj-01을 사용해 smoke 데이터와 어긋날 수 있음
```

### 3.2 수정 파일

```text
ont_platform/v5/frontend/src/store/useQueryStore.ts
ont_platform/v5/frontend/src/lib/api.ts
ont_platform/v5/frontend/src/components/query/AdaptiveQueryInterface.tsx
ont_platform/v5/frontend/src/components/query/SourcePanel.tsx
ont_platform/v5/frontend/src/components/query/AnswerDisplay.tsx
```

### 3.3 수정 내용

```text
1. QueryMessage에 v5_3 필드 추가
2. complete 이벤트의 v5_3 payload를 store에 저장
3. limitations/follow_ups 배열 이벤트를 frontend에서 수용
4. SourcePanel에 FILTERED 상태 라벨/스타일 추가
5. used=false인 source도 필터링된 근거로 계산
6. AnswerDisplay에 v5.3 answer_status / decision badge 표시
7. smoke 기본 프로젝트 fallback을 proj-deafe1fe로 조정
```
