## 3. Codex 수정 사항

파일:

```text
ont_platform/v5/backend/app/services/answerability_gate.py
```

변경:

```text
expert / expert_mode는 ontology_overlap 또는 chunk_overlap이 0이어도 GENERAL_ONLY로 판정.
```

근거:

```text
v5.3 정식 설계서의 전문가 모드 정책은 "일반 설명 허용, 단 출처와 분리"다.
따라서 전문가 모드에서 근거 부족을 곧바로 NO_ANSWER로 처리하면 설계 의도와 맞지 않는다.
제한/문서 모드의 NO_ANSWER 정책은 유지했다.
```

## 4. Claude Code 실행 지시

Claude Code는 다음 기준으로 UI smoke를 실행한다.

### 4.1 테스트 질문

```text
1. Snowflake 기반 RAG 평가에서 문서 저장소와 근거 페이지를 왜 함께 관리해야 하는가?
   mode=document_only
   기대: NO_ANSWER, confidence_score=0.0, sources FILTERED 또는 used=false

2. DB 스키마를 온톨로지로 변환할 때 어떤 절차가 필요한가?
   mode=expert_mode
   기대: GENERAL_ONLY 또는 NORMAL/PARTIAL, UI 렌더링 정상

3. 국방 지휘통제 통합 DB에서 상위 온톨로지가 필요한 이유는?
   mode=expert_mode
   기대: GENERAL_ONLY 또는 NORMAL/PARTIAL, UI 렌더링 정상

4. 온톨로지 기반 질의응답에서 온톨로지는 어떤 역할을 하는가?
   mode=expert_mode
   기대: GENERAL_ONLY 또는 NORMAL/PARTIAL, UI 렌더링 정상
```

### 4.2 확인 항목

```text
1. complete payload에 v5_3 객체가 포함되는가?
2. Snowflake 질문이 85% 정상 답변으로 표시되지 않는가?
3. NO_ANSWER일 때 confidence_score가 0.0인가?
4. NO_ANSWER sources가 FILTERED 또는 used=false로 표시되는가?
5. 전문가 모드 GENERAL_ONLY가 UI에서 오류나 빈 화면 없이 보이는가?
6. 0% confidence / 일반 설명 / 근거 부족 메시지가 UI를 깨지 않는가?
```
