## 2. 역할 분담

## 2.1 Codex 담당: 기술 리드 / 백엔드 계약 고정

목표:

```text
v5.3 Answerability Gate의 API 계약을 고정하고, 회귀 테스트 가능 상태로 만든다.
```

작업:

```text
1. API smoke 결과를 공식 상태 보고서로 정리
2. answerability_gate.py / entity_gate.py를 커밋 후보로 분류
3. phase0_report_script.py는 운영 커밋 제외 후보로 분류
4. document_with_limits 모드 정책을 설계서와 맞춰 재검토
5. 최소 회귀 테스트 스크립트를 정리하거나 기존 test_gate.py를 보강
```

완료 조건:

```text
1. Snowflake document_only는 NO_ANSWER + confidence 0.0 + FILTERED 유지
2. expert_mode는 GENERAL_ONLY 또는 정상 답변으로 살아 있음
3. complete payload에 v5_3가 항상 포함됨
4. 회귀 테스트 명령 1개로 재현 가능
```

## 2.2 Claude Code 담당: PM / UI smoke / 사용자 관점 판정

목표:

```text
실제 브라우저 UI에서 v5.3 상태가 사용자에게 깨지지 않고 전달되는지 확인한다.
```

작업:

```text
1. http://127.0.0.1:3001 접속
2. 프로젝트 proj-deafe1fe 기준 4문항 smoke 실행
3. Snowflake 질문에서 0% confidence 표시 확인
4. RAG source가 FILTERED 또는 used=false로 표시되는지 확인
5. 전문가 모드 GENERAL_ONLY가 빈 화면/오류/오해 유발 없이 표시되는지 확인
6. UI 화면 캡처 또는 로그 근거 남기기
7. 사용자 관점 GO/WAIT 판정 작성
```

테스트 질문:

```text
1. Snowflake 기반 RAG 평가에서 문서 저장소와 근거 페이지를 왜 함께 관리해야 하는가?
2. DB 스키마를 온톨로지로 변환할 때 어떤 절차가 필요한가?
3. 국방 지휘통제 통합 DB에서 상위 온톨로지가 필요한 이유는?
4. 온톨로지 기반 질의응답에서 온톨로지는 어떤 역할을 하는가?
```

완료 조건:

```text
1. UI에서 Snowflake가 정상설명/85%로 보이지 않음
2. 0% confidence가 레이아웃을 깨지 않음
3. FILTERED 근거가 사용 근거처럼 오해되지 않음
4. 전문가 모드 답변이 사용자에게 "문서 직접 근거"로 오인되지 않음
5. 최종 GO/WAIT 판정 보고서 작성
```

## 2.3 Antigravity 담당: QA / 정책 비판 / false positive·false negative 분석

목표:

```text
게이트가 너무 느슨하거나 너무 엄격한 지점을 찾아 정책 보정안을 제시한다.
```

작업:

```text
1. Snowflake 차단 케이스를 false positive 방어 관점에서 검토
2. document_with_limits 모드가 과도 차단되는지 검토
3. GENERAL_ONLY + confidence 0.85 조합이 사용자에게 과신을 줄 위험 검토
4. answer_status와 confidence_score의 정책 매핑 제안
5. 8~12개 추가 질문 세트 제안
```

중점 질문:

```text
1. GENERAL_ONLY일 때 confidence_score를 0.85로 유지해도 되는가?
2. GENERAL_ONLY는 RAG 5개가 있어도 문서 직접 근거로 표시하면 안 되는가?
3. document_with_limits는 NO_ANSWER보다 PARTIAL을 더 자주 허용해야 하는가?
4. FILTERED source와 일반 source의 UI 구분은 충분한가?
```

완료 조건:

```text
1. 정책 리스크 표 작성
2. answer_status별 confidence_score 권고안 작성
3. document_with_limits 보정 여부 GO/WAIT 판정
4. 추가 smoke 질문 세트 작성
```

## 3. 다음 의사결정 게이트

3-agent 결과를 모아 다음 중 하나로 판정한다.

```text
GO:
  UI smoke 통과, 정책 리스크 허용 가능, 회귀 테스트 재현 가능

WAIT:
  UI 표시 또는 confidence 정책 또는 document_with_limits 정책에 보정 필요

NO-GO:
  Snowflake가 다시 정상 답변으로 보이거나, v5_3 payload/FILTERED가 UI에서 확인되지 않음
```
