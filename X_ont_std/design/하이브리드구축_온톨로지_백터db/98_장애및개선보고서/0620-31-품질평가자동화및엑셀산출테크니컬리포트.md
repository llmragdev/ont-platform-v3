### 3.1 evaluate_team5_24qa.py (평가 수집)

]

**핵심 로직: SSE 파싱**

```python
def evaluate_single_question(question_id, question_text, mode="expert_mode"):
    url = f"{API_BASE}/api/v1/projects/{PROJECT_ID}/query/stream"
    params = {
        "project_id": PROJECT_ID,
        "session_id": f"eval-q{question_id}",
        "query": question_text,
        "mode": mode,
        "hide_irrelevant": "true",
        "allow_partial": "true",
        "separate_general": "true",
        "allow_general": "true",
    }
    
    answer = ""
    with requests.get(url, params=params, stream=True, timeout=30) as response:
        for line in response.iter_lines():
            if not line:
                continue
            line_str = line.decode('utf-8')
            if line_str.startswith('data: '):
                try:
                    data = json.loads(line_str[6:])
                    if 'token' in data:
                        answer += data.get('token', '')
                except:
                    pass
    
    return {"answer": answer, "score": calculate_score(answer, expected_items)}
```

**점수 계산: 키워드 매칭**

```python
score = 50  # 기본점
if answer:
    expected_items = EVALUATION_QUESTIONS[question_id - 1].get('expected_items', [])
    matched = sum(1 for item in expected_items if item in answer)
    score = min(100, 50 + (matched * 10))
```

**문제점:**
- 단순 substring matching (의미 고려 안 함)
- Snowflake 특별 규칙 미반영

def calculate_category_average(results, category):
    category_results = [r for r in results if r.get('category') == category]
    scores = [r.get('score', 0) for r in category_results]

## 5. LLM-as-a-Judge 전환 검토

### 5.1 현재 방식의 문제

```python
# 예시: 좋은 답변도 감점
answer = "온톨로지란 지식의 개념적 구조화를 말합니다..."
expected_items = ["개념분류", "관계모델링", "Class/Property/Instance"]

matched = 0  # "Class/Property/Instance" 없음

```

### 5.2 LLM-as-a-Judge 방식

**개념:**
```python
# Claude 또는 GPT를 평가자로 사용
def evaluate_with_llm(question, expected_items, answer):
    prompt = f"""
    질문: {question}
    기대 항목: {expected_items}
    
    응답을 평가하세요.
    - 정확도 (0-100)
    - 근거 수준 (0-3)
    - 피드백
    """
    
    result = claude_api.message(prompt)
    return result.accuracy_score
```

**장점:**
- ✅ 의미 기반 평가
- ✅ 자동으로 특별 규칙 학습
- ✅ 질적 피드백 제공

**단점:**
- ❌ API 비용 증가 (~$0.10/평가)
- ❌ 평가 시간 증가 (~5초/문항)
- ❌ 일관성 기대 어려움

**비용 분석:**
```
현재: 0초 × 24 = 0초
LLM: 5초 × 24 = 120초 + 비용

24문항당 비용: 약 $2.40
월 100회 평가: 약 $240
```

### 6.2 중기 (2-3주일)

```
1. 선택적 LLM-as-a-Judge
   └─ 낮은 점수(< 60)의 5%만 LLM 검증
   └─ 비용 20배 감소

2. 하이브리드 평가
   └─ 규칙: 빠르고 싼 스크리닝

### 6.3 장기 (Phase 3)

```
1. 다단계 평가 시스템
   └─ 자동 평가 → 신뢰도 점수 > 0.8 → 최종 확인
   └─ 신뢰도 < 0.5 → LLM 재평가

2. 피드백 루프
   └─ 사용자 수정 → 모델 미세조정
