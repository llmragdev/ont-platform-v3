**우여곡절 1: adaptive_query 파일 누락**
```
시간: 14:00
증상: "ImportError: cannot import name 'adaptive_query'"
원인: adaptive_query.py 파일이 완전히 없음!

문제점:
- Phase 1에서 작성했어야 하는 파일이 없음
- Claude Code가 "파일을 만들어야 하나?" 하다가
- "아니다, Codex의 일이다" 판단
- 역할 명확화의 중요성 발생

해결:
Codex: "파일을 찾아보니 완전히 없네요"
→ adaptive_query.py 재작성 복구
→ 문법/import 검증

학습: "이미 끝났다고 생각한 작업의 누락 확인"
```

**우여곡절 2: 좀비 프로세스 (Reloader 캐시)**
```
시간: 15:00
증상: 파일을 복구했는데도 같은 에러 반복
로그: "ImportError: cannot import name 'adaptive_query'"

근본 원인 (Antigravity 발견):
- Worker 프로세스는 죽음 ✅
- 하지만 Reloader(부모) 프로세스는 살아있음 ⚠️
- 부모가 "어? 파일 없네?" 캐시된 상태 유지
- 새로운 자식 프로세스 띄워도 부모가 같은 오류 알려줌
- → 무한정 ImportError 반복! 🧟‍♂️

깨달음:
"시스템 레벨에서 프로세스 관리를 이해해야 한다"
"새로 켜는 것 ≠ 완전히 리셋되는 것"

해결 (Antigravity):
- Get-CimInstance로 모든 python.exe 추적
- Stop-Process -Force로 완전 킬
- start_backend.ps1에 좀비 킬러 로직 추가
- "Stopping zombie uvicorn process" 메시지 추가

결과: 백엔드 정상 기동 ✅
```

## 💡 **배운 점: 유연한 협업의 핵심**

### **1. 역할은 정해진 것이 아니라 필요에 따라 진화한다**
```
처음: Antigravity + Claude Code의 분석 + 기획
→ 중간: Codex 합류로 구현 추가
→ 지금: 3명이 각자의 역할 + 필요시 보완
```

### **2. 문제가 복잡할수록 다양한 관점이 필요하다**
```
RAG 문제: 표면 (5개 반환) vs 심층 (핵심어 없음)
좀비 문제: 코드 (X) vs 시스템 (캐시 문제)
평가 문제: 사용자 피드백 → 전체 팀의 설계

각 관점이 없었다면 해결 불가능했을 것
```

### **3. 신속한 피드백과 오픈 마인드가 성공의 열쇠**
```
문제 발생 → 즉시 보고
가설 제시 → 즉시 검증
새 의견 → 즉시 수용 및 재설계

"우리 계획이 맞다"는 고집 없음
"더 나은 방법이 있는가"를 항상 질문
```

### **4. 기술과 전략의 조화**
```
전략만 있으면: 실행 불가 (관념)
기술만 있으면: 방향 잃음 (미로)
조화: 전략으로 방향 + 기술로 실행

이번 프로젝트 = 조화의 좋은 예
```
