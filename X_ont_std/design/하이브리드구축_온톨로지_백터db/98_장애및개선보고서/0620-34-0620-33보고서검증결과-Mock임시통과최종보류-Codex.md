### 2.4 test_api.py는 Mock 형식에 맞춘 테스트임

파일:

`E:\ontology_edu\X_ont_std\ont_platform\v5\backend\test_api.py`

현재 테스트는 SSE 라인을 다음 형식으로 파싱한다.

## 3. 왜 최종 승인하면 안 되는가

### 문제 1. 실제 검색 품질을 검증하지 못한다

현재 3/3 통과는 "하드코딩된 질문 3개에 대해 하드코딩된 응답이 나온다"는 의미다. 다음 항목을 검증하지 못한다.

- 현재 프로젝트의 실제 Chroma/Vector DB 조회 여부
- 실제 업로드 문서명과 페이지 반환 여부
- 실제 유사도/거리 점수 기반 필터링 여부
- 실제 Ontology 저장소 엔티티/관계 검색 여부
- 무관 질문에 대해 `관련 없음` 처리 여부

### 문제 2. Snowflake 정책 요구와 충돌한다

사용자 요구는 다음이었다.

> 검색에서 Snowflake 내용 없으면 관련 없음 해야지

하지만 현재 Mock 분기는 질문에 `Snowflake`가 포함되면 실제 문서 존재 여부와 무관하게 `Snowflake QA - [05] 성능 최적화 - 2025.pdf`를 만들어 반환한다.

이는 "문서에 없음"을 "관련 없음"으로 처리하는 정책과 정면으로 충돌한다.

### 문제 3. Ontology (2)가 실제 지식그래프가 아닐 수 있다

보고서와 테스트는 `Ontology: 2`를 성공으로 본다. 그러나 현재 코드는 `ontology_entities = [...]`를 직접 만든다. 즉, Ontology 탭의 숫자가 실제 온톨로지 저장소의 검색 성공을 의미하지 않는다.

이 상태에서 평가를 돌리면 Ontology 점수가 가짜로 상승할 수 있다.

## 5. 다음 조치 계획

### 5.1 즉시 조치

1. 0620-33 보고서를 최종 완료 보고서가 아니라 **임시 Mock 복구 보고서**로 재분류한다.
2. `adaptive_query.py`에서 Mock 분기를 실제 검색 파이프라인 뒤의 fallback/test fixture로 격하하거나 제거한다.
3. 실제 RAG 검색 결과가 없으면 답변 본문도 다음 원칙을 따른다.

```text
현재 프로젝트 문서 근거에서는 질문 주제와 직접 관련된 내용을 확인하지 못했습니다.
```

4. `Snowflake` 질문은 실제 Snowflake 문서가 검색되지 않으면 `RAG 0 / Ontology 0 / 관련 없음`이어야 한다.

### 5.2 실제 복구 기준

최종 승인은 아래 테스트를 통과한 뒤 가능하다.

| 테스트 | 기대 결과 |
|---|---|
| `온톨로지가 뭐야?` | 실제 업로드 문서 5개 내외 반환 |
| `Snowflake 기반 QA...` | Snowflake 문서가 없으면 관련 없음 |
| `Class와 Property 차이` | 실제 문서 또는 실제 온톨로지 근거가 있을 때만 답변 |
| Ontology 저장소 비어 있음 | Ontology 탭 0, 답변에 가짜 엔티티 금지 |
| Ontology 저장소 존재 | 실제 entities/relationships 기반 결과만 표시 |
| SourcePanel | 답변 본문 출처와 RAG/Ontology 탭 출처 일치 |

### 5.3 테스트 스크립트 보강

현재 `test_api.py`는 Mock 통과 테스트다. 다음 검증을 추가해야 한다.

- 반환 source name이 실제 업로드 문서 목록에 존재하는지 확인
- `Snowflake` 무관 질문에서 Mock 문서가 생성되지 않는지 확인
- Ontology 결과가 실제 ontology JSON 또는 DB 조회 결과인지 확인
- SSE 계약이 프론트의 EventSource 처리 방식과 일치하는지 확인
