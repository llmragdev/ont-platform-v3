## 1. 핵심 결론

사용자 지적처럼 v5에는 실제 이상 답변 문제가 있었다.

이 문제는 단순히 평가 기준 차이만으로 설명할 수 없다.

주요 원인:

1. `adaptive_query.py`에 질문과 무관한 일반 설명 템플릿이 하드코딩되어 있었다.
2. 검색 근거가 있어도 답변 본문을 생성하지 않고 파일명/페이지 출처만 나열했다.
3. RAG 출처와 답변 본문의 책임이 섞여 있었다.
4. Ontology 데이터가 부족해 Ontology 탭이 0으로 나오는 문항이 많았다.

---

## 2. 발견된 이상 답변 패턴

### 2.1 무관한 일반 설명 반복

예:

```text
응답 시간은 사용자 경험과 SLA를, 운영 제약은 비용, 권한, 보안, 장애 대응...
```

이 문장은 `Class와 Property의 차이`, `온톨로지의 한계`, `온톨로지와 지식그래프` 같은 질문에도 반복될 수 있었다.

원인:

`_build_no_evidence_answer()`에 Snowflake/RAG 운영 관점의 일반 설명이 고정 문구로 들어가 있었다.

### 2.2 근거만 있고 답변이 없음

예:

```text
질문하신 내용에 대해 연결된 문서 근거를 확인했습니다.
주요 근거는 NLP - [03] ... p.4 ...
```

문제:

이 문장은 실제 질문에 대한 설명이 아니라, 검색된 출처를 나열한 것이다.

출처 정보는 RAG 탭에서 보여야 하며, 답변 본문에는 질문에 대한 설명이 있어야 한다.

## 3. 조치 내용

대상 파일:

`E:\ontology_edu\X_ont_std\ont_platform\v5\backend\app\api\adaptive_query.py`

수정 내용:

1. 질문과 무관한 일반 설명 템플릿 제거
2. 근거 없음 상태에서 전문가모드라도 무조건 일반 설명을 생성하지 않도록 변경
3. Snowflake 질문은 별도 문서 근거가 없으면 Snowflake 근거 없음으로 명시
4. 답변 본문에서 파일명/페이지 출처 나열 제거
5. 검색된 RAG 청크에서 질문 토큰과 겹치는 핵심 문장을 추출해 답변 본문에 사용
6. 출처/페이지는 RAG 탭에서 확인하도록 문장 책임 분리

## 4. 변경 후 기대 동작

### 4.1 근거 없음

기존:

```text
문서 근거 판단: 근거 없음
일반 설명: 응답 시간은 사용자 경험과 SLA...
```

개선:

```text
현재 업로드되었거나 검색된 문서 근거에서 질문 주제 관련 내용을 확인하지 못했습니다.
전문가모드라도 문서 근거가 없으므로 일반 설명을 생성하지 않습니다.
```

### 4.2 근거 있음

기존:

```text
주요 근거는 파일명 p.4, 파일명 p.3...
```

개선:

```text
검색된 문서 조각에서 질문과 관련된 핵심 문장을 우선 사용한다.
구체적인 출처와 페이지는 아래 RAG 근거 탭에서 확인한다.
```

## 6. 남은 문제

1. 실제 운영 중인 백엔드 8001이 최신 코드를 반영하지 못할 수 있다.
   - Uvicorn reloader가 꼬인 상태가 여러 번 관측됨.
   - 재평가 전 `start_backend.ps1`로 완전 재시작 필요.

2. Ontology 데이터가 여전히 부족하다.
   - 현재 프로젝트 ontology JSON은 일부 문서에 대해서만 존재한다.
   - RAG는 검색되지만 Ontology는 0인 문항이 계속 발생할 수 있다.

3. 현재 답변 생성은 아직 LLM 합성이 아니라 경량 문장 추출 방식이다.
   - 이상한 일반 설명은 줄였지만, 고품질 설명형 답변을 위해서는 LLM 기반 grounded synthesis가 필요하다.
