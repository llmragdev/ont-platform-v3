## 1. 현재 시스템 달성 성과 (Phase 2 완료)
금일 오전, 팀(PM, Claude, Codex, Antigravity)의 완벽한 역할 분담을 통해 아래의 목표를 달성했습니다.
* **UI/UX 세밀화**: 단일 모드의 한계를 넘어, 4종의 체크박스(무관한 검색 숨기기, 부분 답변 허용, 출처 분리, 일반 설명 허용)를 통한 **응답 정책의 완전한 사용자 통제권** 확보.
* **할루시네이션 원천 차단**: 질문의 핵심 키워드가 문서에 존재하지 않을 경우 즉시 답변을 차단(`has_evidence=False`)하는 강력한 **Relevance Guardrail(관련성 방어벽)** 백엔드 구축.

*(※ 업데이트: 백엔드의 파라미터명 `separate_sources`와 프론트엔드의 `separate_general` 명칭 불일치를 현재 소스 기준으로 동기화 완료했습니다. 이제 100% 정상 작동합니다.)*

---

## 2. 향후 업그레이드 로드맵 (Phase 3 ~ 5)

### 🎯 [Phase 3] 지능형 LLM 연동 및 프롬프트 동적 제어 (단기: 1~2주 내)
현재 `adaptive_query.py`는 속도를 위해 룰(Rule) 기반의 하드코딩된 응답 텍스트를 스트리밍하고 있습니다. 이를 실제 LLM으로 교체해야 합니다.
1. **체크박스 상태 ↔ 프롬프트 동적 매핑**: 
   - 사용자가 체크한 UI 옵션 4가지를 LLM System Prompt로 직접 주입합니다.
   - *예: `allow_general=False`일 때 프롬프트: "문서에 없는 내용은 절대 답변하지 마시오."*
2. **단순 키워드 검사를 넘어선 의미론적(Semantic) 검증**: 
   - 현재 정규식을 이용한 영단어 매칭(`re.findall`)에서 진일보하여, 경량 로컬 LLM이나 Cross-Encoder를 활용해 "검색된 문서가 정말 질문에 대한 답을 포함하는지" 0.5초 내에 판별하는 **LLM-as-a-Judge 가드레일** 도입.

### 🎯 [Phase 4] 사용자 경험(UX) 및 피드백 루프 고도화 (중기: 1개월 내)
1. **실시간 출처 하이라이팅 (Citation Highlighting)**:
   - 답변이 스트리밍될 때, 각 문장 끝에 `[1]`, `[2]` 형태의 주석 앵커를 달고, 클릭 시 우측 PDF 뷰어의 해당 페이지/라인으로 자동 스크롤되도록 UI 고도화.
2. **할루시네이션 신고 및 강화 학습 (RLHF 기초)**:
   - 답변 컴포넌트 하단에 [👍] [👎] 버튼을 추가하고, 👎 클릭 시 "어떤 부분이 사실과 다른지(문서 기반 오류 vs 일반 지식 오류)"를 수집하여 향후 온톨로지 매핑 개선에 활용.

### 🎯 [Phase 5] 진정한 Graph-RAG 생태계 완성 (장기: 3개월 내)
1. **질문 기반 동적 SPARQL 생성 (NL2SPARQL)**:
   - 벡터 검색(Vector Search)과 별개로, 질문을 분석해 실시간으로 지식 그래프 쿼리(SPARQL)를 생성, 다단계 추론이 필요한 복잡한 질문(예: "A장비의 고장 원인이 되는 B부품의 이전 유지보수 이력은?")을 해결.
2. **문서 업로드 시 온톨로지 자동 추출 (Auto-Ontologization)**:
   - 사용자가 새 문서를 업로드하면, LLM이 백그라운드에서 문서의 개념(Concept), 속성(Property), 관계(Relationship)를 자동 추출하여 시스템 지식 그래프를 스스로 살찌우는 자가 성장형 파이프라인 구축.
