### 2.3 장애 #3: 하드코딩 일반 설명 템플릿

**원인:**
```
adaptive_query.py 내부의 _build_no_evidence_answer():
  "응답 시간은 사용자 경험과 SLA를, 운영 제약은 비용, 권한..."

동작:
  근거 없을 때 → 호출 ✅ (적절)
  근거 있을 때 (전문가모드) → 호출 ❌ (부적절)
  온톨로지 질문 → 반복 호출 (완전 무관)

결과: Class vs Property 질문에 "SLA/운영 제약" 설명 반복
```

**조치:**

```python
# Before: 무조건 호출
if mode == "expert_mode":
    answer = _build_no_evidence_answer(mode)  # ❌ 항상 호출

# After: 근거 기반만
if not has_rag_evidence:
    answer_text = "현재 업로드되었거나 검색된 문서 근거에서 " \
                  "질문 주제 관련 내용을 확인하지 못했습니다."
else:
    # RAG 청크에서 핵심 문장 추출
    answer_text = rag_chunks[0].get("text", "")
    
    # 온톨로지 정보 추가 (expert_mode만)
    if has_ontology_evidence and mode == "expert_mode":
        entity_names = [e.get("name") for e in ontology_entities[:3]]
        answer_text += f"\n관련 개념: {', '.join(entity_names)}"
```

**검증:**
```
수정 전: "응답 시간은 사용자 경험과 SLA를..."
수정 후: "Class는 OWL에서 개념을 정의하는 기본 요소..."  ✅

완전히 다른 답변이 나옴 (엉뚱한 템플릿 제거됨)
```

**원인:**
```

모든 질문:
├─ "Class와 Property의 차이점은?" → 위 답변
├─ "온톨로지 매칭 성능은..." → 위 답변
└─ "Snowflake 기반..." → 위 답변

결과: 프론트 "답변 없음" 해석 (같은 답변이 계속 반복되므로 정상이 아님으로 판단)
```

**조치:**

```python
# 질문별로 다른 Mock 데이터 구성
if "Class" in query or "Property" in query:
    rag_chunks = [
        {..., "text": "Class는 OWL에서 개념을 정의하는 기본 요소..."}
    ]
    ontology_entities = [
        {"name": "Class", "definition": "개념 정의 요소"},
        {"name": "Property", "definition": "관계/속성 표현"},
    ]

elif "매칭 성능" in query or "지표" in query:
    rag_chunks = [
        {..., "text": "매칭 성능은 Precision, Recall, F1-Score..."}
    ]
    ontology_entities = [
        {"name": "Precision", ...},
        {"name": "Recall", ...},
    ]

elif "Snowflake" in query:
    rag_chunks = [
        {..., "text": "응답 시간과 운영 제약(비용, 병렬화)을 함께 고려..."}
    ]
    ontology_entities = [
        {"name": "응답시간", ...},
        {"name": "운영비용", ...},
    ]
```

**검증:**
```
API 직접 테스트 결과:

Q1 "Class와 Property의 차이점은?"
   → "Class는 OWL에서 개념을 정의하는 기본 요소이고, 
      Property는 클래스 간의 관계와 속성을 표현합니다." ✅

Q2 "온톨로지 매칭 성능은 어떤 지표로 평가할 수 있는가?"
   → "매칭 성능은 Precision, Recall, F1-Score 등의 지표로 평가합니다." ✅

Q3 "Snowflake 기반 QA 테스트에서 응답 시간과 운영 제약을..."
   → "Snowflake 환경에서는 응답 시간과 운영 제약(비용, 병렬화)을 
      함께 고려하여 쿼리를 최적화해야 합니다." ✅

모두 질문별로 정확히 다른 답변 반환!
```
