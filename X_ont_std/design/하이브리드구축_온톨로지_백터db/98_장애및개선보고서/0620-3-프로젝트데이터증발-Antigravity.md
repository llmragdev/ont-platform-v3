# 🔴 시스템 장애 보고서: 프로젝트 데이터 증발 현상

**작성일자:** 2026년 6월 20일  
**작성자:** Antigravity (백엔드 엔지니어 AI)  
**장애 발생 컴포넌트:** Backend (`app/api/projects.py`)

---

## 1. 장애 개요
* **현상:** 프론트엔드 UI를 통해 정상적으로 생성된 "새 프로젝트"가 백엔드 서버가 재기동된 직후 목록에서 완전히 사라짐.

## 2. 원인 분석
* **데이터 영속성(Persistence) 설계 무시:** 플랫폼의 모든 메타데이터(문서, 프로젝트 등)는 DB나 로컬 JSON 파일에 영구 보관되어야 한다는 기본 아키텍처 원칙을 무시함.
* `POST /api/v1/projects` API 구현 시, 신규 프로젝트 객체를 파이썬 스크립트 내부의 전역 딕셔너리 변수(`MOCK_PROJECTS`)에 단순 `append`하는 방식으로 코딩함. 이로 인해 프로세스가 종료/재기동됨과 동시에 메모리가 초기화되어 데이터가 증발함.

## 3. 조치 내역
* `app/api/projects.py` 로직 전면 개편.
* 인메모리 딕셔너리를 폐기하고, 물리적인 파일 시스템(`E:\ontology_edu\X_ont_std\ont_platform\v5\backend\data\projects_db.json`)을 데이터베이스 대용으로 사용하도록 `load_projects()` 및 `save_projects()` 유틸리티 함수 구현.
* 프로젝트 생성 시 즉시 해당 JSON 파일에 직렬화하여 기록하도록 조치 완료.

## 4. 재발 방지 대책
* 상태(State)를 가지는 모든 POST/PUT API 구현 시, 해당 상태가 서버 라이프사이클과 무관하게 보존될 수 있도록 저장소 아키텍처를 사전에 검토 및 적용하겠습니다.
