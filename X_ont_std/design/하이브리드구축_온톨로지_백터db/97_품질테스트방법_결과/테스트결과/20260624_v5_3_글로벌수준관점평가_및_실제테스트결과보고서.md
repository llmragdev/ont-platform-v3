## 1. 요약

v5.3 Phase 1은 단순 RAG QA봇이 아니라, 검색 결과가 존재해도 답변 가능성 검사를 통과하지 못하면 답변을 차단하는 구조를 구현했다.

실제 테스트에서는 외부 도메인 질문 4건이 `NO_ANSWER / blocked / 0%`로 차단되었고, 내부 온톨로지 관련 질문 4건은 `PARTIAL / 75%` 또는 `GENERAL_ONLY / 55%`로 제한 답변되었다. 8건 모두 Word evidence 파일에 이미지 캡처와 판정 메타데이터가 포함되어 있음을 확인했다.

따라서 현재 수준은 다음과 같이 평가한다.

| 관점 | 판정 |
|---|---|
| 내부 데모 | GO |
| 제한 고객 PoC | 조건부 GO |
| 국내 단순 RAG QA 대비 | 상위권 후보 |
| 국내 엔터프라이즈 상용 제품 | 아직 추가 검증 필요 |

### 2.2 검증 방법

각 `.doc` 파일 내부 HTML에서 다음 항목을 확인했다.

- `<tr><th>질문</th>`: 질문 텍스트
- `<tr><th>v5.3 판정</th>`: v5.3 status 및 decision
- `<tr><th>신뢰도</th>`: confidence
- `data:image/png;base64`: 화면 캡처 이미지 포함 여부

검증 결과:


## 3. 테스트 결과 평가

### 3.1 차단 성능

외부 도메인 또는 현재 문서/온톨로지 근거 밖의 질문은 문서 제한 모드에서 적절히 차단되었다.

검증된 외부 도메인:

- Snowflake
- Kubernetes
- Azure AI Search
- OpenAI PDF QA 인덱스 설계

평가:

```text
차단 필요 질문 4/4 차단
NO_ANSWER confidence 0%
일반 지식 답변 생성 방지
```

판정: GO

### 3.2 통과/부분 답변 성능

온톨로지, DB 스키마 변환, C2 관계 그래프 등 내부 도메인에 가까운 질문은 차단되지 않고 제한 답변되었다.

평가:

```text
통과 필요 질문 4/4 통과 또는 제한 답변
PARTIAL confidence 75%
GENERAL_ONLY confidence 55%
```

판정: GO

### 3.3 UI 표시 품질

확인된 UI 표시:

- `NO_ANSWER / blocked`
- `PARTIAL / partial`
- `GENERAL_ONLY / partial`
- `0%`, `55%`, `75%` confidence
- Word 저장 결과에 화면 이미지 포함

판정: GO

### 3.4 Word evidence 저장

현재 구현은 정식 `.docx`가 아니라 Word 호환 HTML `.doc` 방식이다. 평가 증거 보존 용도로는 충분히 동작했다.

확인:

- 8개 파일 모두 이미지 포함
- 질문/판정/신뢰도 메타 포함
- 결과 검토 및 보고 근거로 사용 가능

한계:

- Word 보호 보기/편집 모드 이슈 가능
- 이미지 크기 조정이 일부 환경에서 필요할 수 있음
- 장기적으로 정식 `.docx` 또는 PDF export 필요

판정: Phase 1 GO, Phase 2 개선 필요

## 4. 글로벌 수준 관점 평가

### 4.1 현재 도달 수준

현재 v5.3 Phase 1은 글로벌 GA가 아니라 내부 데모/PoC 품질이다.

강점:

- answerability gate로 외부 도메인 질문 차단 가능
- 단순 similarity 기반 RAG보다 안전한 답변 정책
- `NO_ANSWER`, `PARTIAL`, `GENERAL_ONLY` 상태 분리
- confidence 정책 명확화
- RAG source, ontology source, ontology graph 표시
- Word evidence 저장 기능

국내 단순 RAG QA봇 대비로는 상위권 후보로 평가 가능하다. 특히 검색 결과가 있어도 근거성이 부족하면 답변을 차단하는 흐름은 일반적인 QA 데모보다 강하다.

### 4.2 글로벌 GA와의 차이

| 범주 | 현재 수준 | 글로벌 수준 요구 |
|---|---|---|
| 평가 데이터 | 8건 UI evidence + 16문항 회귀 | 수백~수천 문항 benchmark |
| 언어 | 한국어 중심 | 다국어, 영문, 혼합 질의 |
| 도메인 | 온톨로지/내부 데모 도메인 | 금융, 의료, 법률, 제조, 공공 등 다도메인 |
| UI 테스트 | 수동 smoke | CI 기반 Cypress/Playwright 자동화 |
| RAG 평가 | 사람 검토 중심 | RAGAS, TruLens, LLM-as-judge, 정량 metric |
| 성능 | 로컬 단일 사용자 | 동시성, latency SLA, 부하 테스트 |
| 보안 | 기본 개발 환경 | 인증/인가, 테넌트 격리, XSS/Injection, 감사로그 |
| 운영 | 로컬 로그 | Prometheus/Grafana/Datadog 수준 관측성 |
| 문서 저장 | Word 호환 `.doc` | 정식 `.docx`, PDF, 보안/DRM 연동 |
| 릴리즈 | 수동 검증 | CI/CD, release gate, rollback |

다음 표현은 피해야 한다.

```text
글로벌 GA 전 단계
```

## 5. 국내 수준 관점 평가

현재 기능 조합은 국내 일반 QA봇 또는 단순 RAG 데모와 비교할 때 기술적으로 강한 편이다.

차별점:

1. 검색 결과가 있어도 답변을 자동 생성하지 않는다.
2. 답변 가능성 gate가 `NO_ANSWER`를 명시적으로 낸다.
3. confidence를 status별로 분리한다.
4. 근거 source를 `USED/FILTERED`로 구분한다.
5. ontology graph를 함께 제시한다.
6. 평가 결과를 Word evidence로 남긴다.

평가:

```text
국내 단순 RAG QA봇 대비: 상위권
국내 온톨로지 결합 QA 데모 기준: 상위권 후보
국내 상용 엔터프라이즈 제품 기준: 추가 검증 필요
```

## 6. 남은 리스크

### 6.1 테스트 규모

현재 8건 Word evidence와 16문항 smoke는 기능 확인에는 충분하지만, 품질 보증에는 부족하다.

필요:

- 최소 100문항 평가셋
- 권장 300문항 이상
- 차단 필요/통과 필요/부분 답변/전문가 의견 질문 분리

### 6.2 자동화

Cypress spec은 있으나 실행 환경 이슈로 자동화 검증은 아직 WAIT/SKIP이다.

필요:

- Cypress 또는 Playwright 실행 환경 복구
- CI에서 자동 UI smoke
- 스크린샷 diff 또는 DOM assertion

### 6.3 LLM 품질 검증

Gemini quota 429 이슈가 있어 live LLM answer quality는 제한적으로만 검증되었다.

필요:

- quota 리셋 후 live generation 검증
- fallback/mock answer와 live answer 구분
- hallucination/faithfulness 평가

### 6.4 운영/보안

아직 글로벌 SaaS 수준의 운영·보안 검증은 없다.

필요:

- 인증/인가
- 테넌트 격리
- audit log
- 개인정보/민감정보 처리 정책
- query logging/redaction
