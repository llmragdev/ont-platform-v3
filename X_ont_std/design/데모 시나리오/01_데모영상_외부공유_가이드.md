# 데모 영상 외부 공유 가이드

- 작성일: 2026-06-14
- 대상 회사: 디노티시아, 엔코아
- 목적: 온톨로지 기반 워크플로우 자동화 PoC 데모 영상 공유
- 원칙: 기술력은 보여주되, 복제 가능한 내부 설계와 구현 상세는 노출하지 않는다.

---

## 1. 공유 전략

디노티시아와 엔코아에 데모 영상을 보낼 때는 같은 영상을 보내도 됩니다.

다만 가장 좋은 방식은 다음입니다.

```text
공통 데모 영상 1개
  + 회사별 짧은 메시지
  + 상세 구조는 미팅/NDA 이후 설명
```

처음 보내는 영상은 “실제로 동작한다”는 신뢰를 주는 것이 목적입니다.

내부 구현 방식, API 구조, 문서, 코드까지 설명하면 상대가 빠르게 유사 구조를 따라 만들 수 있으므로 주의해야 합니다.

## 3. 영상 구성안

### 3.1 문제 제시

권장 시간:

```text
30초
```

설명 포인트:

- 현장 요청, 고객 문의, 반복 장애 대응은 사람이 매번 판단하고 기록해야 한다.
- 수작업 처리에서는 누락, 중복, 이력 단절이 발생한다.
- 이 데모는 워크플로우, 온톨로지, 외부 시스템 연동을 묶어 자동 처리하는 예시다.

권장 멘트:

```text
이 데모는 공장 현장 요청이 들어왔을 때 워크플로우가 자동으로 실행되고,
처리 결과가 외부 시스템과 온톨로지에 함께 남는 흐름을 보여줍니다.
```

---

### 3.2 워크플로우 실행 화면

권장 시간:

```text
1분 30초
```

보여줄 화면:

- 워크플로우 빌더 또는 실행 화면
- 공장 자동화 워크플로우 선택
- `Run` 클릭
- 블록이 실행중/성공 상태로 바뀌는 장면
- 우측 실행 현황 패널
- 실행 이력 또는 최근 완료 단계

강조 포인트:

- 업무 흐름이 시각적으로 보인다.
- 각 단계의 실행 상태가 블록에서 바로 확인된다.
- 실행 결과가 이력으로 남는다.

권장 멘트:

```text
각 업무 단계는 워크플로우 블록으로 구성되어 있고,
실행하면 현재 어느 단계가 처리 중인지와 어떤 단계가 완료되었는지 확인할 수 있습니다.
```

---

### 3.3 외부 시스템 처리 결과

권장 시간:

```text
1분
```

보여줄 화면:

- 공장 자동화 모의 게시판
- 현장 요청 상세
- 자동으로 등록된 댓글 또는 정비 안내
- 필요 시 정비 지시서 생성 결과

강조 포인트:

- 워크플로우 실행 결과가 외부 시스템에 반영된다.
- 실제 운영에서는 게시판 대신 ERP, MES, EAM, 고객센터, 정비 시스템으로 바뀔 수 있다.

권장 멘트:

```text
데모에서는 모의 게시판에 결과를 등록하지만,
실제 환경에서는 ERP, MES, 정비 시스템, 고객센터 시스템과 같은 외부 시스템으로 확장할 수 있습니다.
```

---

### 3.4 온톨로지 관리 화면

권장 시간:

```text
1분
```

보여줄 화면:

- 온톨로지 관계 탐색 또는 관리자 화면
- 현장 요청, 설비, 생산 라인, 고장 이벤트, 정비 지시 관계
- 워크플로우 실행 결과가 객체와 관계로 남은 장면

강조 포인트:

- 단순 로그가 아니라 업무 객체와 관계로 축적된다.
- 반복 고장, 원인 분석, 후속 조치 추적에 활용할 수 있다.
- 워크플로우와 온톨로지가 연결되어 설명 가능한 업무 이력이 된다.

권장 멘트:

```text
처리 결과는 단순 로그로 끝나지 않고,
설비, 라인, 고장 이벤트, 정비 지시 같은 업무 객체와 관계로 남습니다.
그래서 이후 반복 고장 분석이나 후속 조치 추적에 활용할 수 있습니다.
```

---

### 3.5 실행 이력과 감사 추적

권장 시간:

```text
40초
```

보여줄 화면:

- 워크플로우 실행 이력
- 실행 성공/실패 상태
- 단계별 출력 결과
- 실행자, 실행 시각, 처리 결과

강조 포인트:

- 누가, 언제, 어떤 워크플로우를 실행했는지 추적 가능하다.
- 자동 처리 결과도 감사 가능한 형태로 남는다.
- 기업 운영 환경에서 중요한 통제 포인트가 된다.

권장 멘트:

```text
자동화가 실행되더라도 누가 언제 실행했고,
어떤 단계가 성공했는지 이력으로 남기 때문에 운영과 감사 관점에서 추적할 수 있습니다.
```

## 5. 영상에서 숨겨야 하는 것

아래 항목은 영상에 노출하지 않는 것이 좋습니다.

- VS Code 코드 화면
- 터미널 로그 상세
- GitHub 또는 Git 상태
- `design/스킬` 문서
- `workflow_templates` 파일
- `workflow_ontology_mappings` 파일
- API endpoint 상세
- MCP 호출 payload 상세
- storage 경로
- LLM 프롬프트
- 중복방지 구현 방식
- executor 내부 구조
- 실제 고객명 또는 실제 업무 데이터
- 실제 계정, 토큰, 인증 정보

주의:

```text
화면보다 문서와 구현 패턴이 더 위험하다.
```

상대에게 보여줄 것은 “제품 가치”이고, 숨길 것은 “복제 가능한 구현 방법”입니다.

## 6. 브라우저 녹화 시 주의사항

녹화 전에 아래를 확인합니다.

- 주소창 노출을 최소화한다.
- 가능하면 브라우저를 전체 화면으로 녹화한다.
- 북마크, 개인 프로필, 메신저 알림이 보이지 않게 한다.
- 실제 파일 경로나 포트 상세가 보이지 않게 한다.
- 데모 데이터가 모두 더미 데이터인지 확인한다.
- 녹화 중 터미널과 코드 에디터로 전환하지 않는다.
- 화면 전환은 워크플로우, 게시판, 온톨로지, 이력 화면 정도로 제한한다.

## 12. 최종 판단

데모 영상은 보내도 됩니다.

다만 처음 공유하는 영상은 아래 수준까지만 보여주는 것이 좋습니다.

```text
실제로 동작한다.
업무 흐름이 보인다.
외부 시스템에 결과가 반영된다.
온톨로지에 업무 관계가 남는다.
실행 이력으로 추적 가능하다.
```

보여주지 말아야 할 것은 아래입니다.

```text
어떻게 만들었는지
어떤 API와 JSON 구조를 쓰는지
어떤 설계 문서가 있는지
어떤 코드 구조로 되어 있는지
```

한 줄 결론:

```text
시연자는 “왜 좋은지”를 보여주고, “어떻게 만들었는지”는 감춘다.
```
