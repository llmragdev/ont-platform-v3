# 파이프라인 빌더(Pipeline Builder) 화면 및 기능 설계서

**문서 번호**: 01  
**작성자**: Antigravity  
**작성일**: 2026-06-14  
**대상 시스템**: ont_platform v5  
**목적**: 사용자가 소스 코드 작성 없이, 웹 UI 상에서 드래그 앤 드롭 방식으로 데이터 수집(Source), 가공/변환(Transform), 지능형 실행(Execute), 외부 시스템 등록(MCP Writeback), 온톨로지 적재(Ontology Sink) 단계를 조립하고 배포할 수 있는 **파이프라인 빌더(Pipeline Builder)** 기능을 설계한다.

---

## 1. 설계 배경

현재 ont_platform v5는 다음 두 가지 데이터 연동 기능들을 갖추고 있다.
- **워크플로우 실행 및 템플릿 복제**: 이미 정의된 워크플로우를 테스트 및 실행하는 기능.
- **데이터 흐름 라인리지 (Data Flow Lineage)**: 외부 데이터 수집부터 온톨로지 적재까지 실행 이력을 모니터링하는 **읽기 전용(Read-only) 도구**.

그러나 비즈니스 요구사항이 변경되거나 새로운 연동 시스템이 추가될 때, 데이터의 가공 규칙이나 LLM 프롬프트 흐름을 시각적으로 **"직접 설계하고 제작(Write)"**할 수 있는 파이프라인 설계기가 부재한 상태이다. 

따라서 팔란티어의 **Pipeline Builder**처럼 데이터와 AI 서비스, 온톨로지를 시각적으로 직접 매핑하고 파이프라인을 빌드/배포할 수 있는 저작 도구를 도입하여 제품의 유연성과 플랫폼 가치를 확장한다.

---

## 2. 핵심 아키텍처 (Architecture)

파이프라인 빌더는 설계 시점(Design-time)의 도구로 작동하며, 모니터링 시점(Run-time)인 데이터 흐름 화면과 결합하여 데이터 생애주기를 완성한다.

```text
┌──────────────────────────────────────────────────────────────────┐
│                     [1] 파이프라인 빌더 (설계기)                   │
│  - 노드 드래그 앤 드롭 (Source ➡️ Transform ➡️ Execute ➡️ Sink)   │
│  - 속성 입력 (LLM 프롬프트, 변수, API 경로 설정)                 │
└─────────────────────────────────┬────────────────────────────────┘
                                  │
                                  ▼ [배포 (Deploy)]
┌──────────────────────────────────────────────────────────────────┐
│              [2] 워크플로우 그래프 컴파일러 & 템플릿 저장            │
│  - DAG(순환 검사) 및 스키마 검증                                  │
│  - workflow_graphs.json 내 신규 템플릿 자동 배포                  │
└─────────────────────────────────┬────────────────────────────────┘
                                  │
                                  ▼ [실행 및 스케줄러 기동]
┌──────────────────────────────────────────────────────────────────┐
│                 [3] 데이터 흐름 라인리지 (모니터링)                │
│  - 각 단계별 실시간 성공/실패 여부 및 입출력 모니터링            │
│  - 온톨로지 최종 저장 데이터 상세 감사(Audit)                     │
└──────────────────────────────────────────────────────────────────┘
```

## 3. 노드 종류 및 속성 정의 (Node Types & Properties)

파이프라인 빌더 캔버스에 배치할 수 있는 노드는 4가지 대분류로 구성되며, 우측 속성 패널에서 세부 정보를 입력한다.

### 3.1 Source Nodes (입력 소스)
데이터가 시작되거나 이벤트를 감지하는 노드입니다.

| 노드 ID | 노드 표기명 | 목적 | 우측 속성 입력 필드 |
| :--- | :--- | :--- | :--- |
| **src-webhook** | 웹훅 이벤트 수신 | 외부 시스템(게시판, 알림 등)의 HTTP POST 이벤트를 실시간 수집 | 수신 Endpoint URI, API 인증 토큰 |
| **src-batch** | 배치 폴링 수집 | 주기적으로 외부 테이블 또는 REST API를 쿼리하여 데이터 수집 | 대상 API URL, 폴링 주기(Cron 식), 조회 Limit |
| **src-sap-mock** | SAP/ERP 연동 DB | 모의 레거시 데이터베이스 테이블의 신규 행을 감지 | 대상 테이블 명, 감지할 날짜/ID 컬럼명 |

### 3.2 Transform Nodes (가공 및 분류)
수집된 텍스트나 데이터를 파싱, 정제, 필터링 및 객체에 매핑하는 노드입니다.

| 노드 ID | 노드 표기명 | 목적 | 우측 속성 입력 필드 |
| :--- | :--- | :--- | :--- |
| **tf-classify** | LLM 의도/유형 분류 | LLM을 이용하여 유입된 텍스트의 카테고리 분류 | LLM 모델 선택, 카테고리 정의 리스트, Prompt |
| **tf-map** | 설비/자산 매핑 | 원문에서 설비명, 라인, 공장 정보를 추출하여 온톨로지 키와 매핑 | 온톨로지 매핑 스키마 선택 (Factory/Equipment 등) |
| **tf-check** | 반복/재발 여부 판단 | 온톨로지를 쿼리하여 특정 자산의 최근 N일 내 발생 빈도 계산 | 기준 대상 식별값 변수, 대상 기간 (예: 7일) |

### 3.3 Execute Nodes (지능형 실행)
실제 지식 DB를 조회하거나 LLM을 구동하여 가이드나 조치안을 생성하는 노드입니다.

| 노드 ID | 노드 표기명 | 목적 | 우측 속성 입력 필드 |
| :--- | :--- | :--- | :--- |
| **ex-rag** | 지식/RAG 조회 | 회사 내부 문서(매뉴얼, FAQ 등) 또는 온톨로지 DB에서 근거 검색 | 임베딩 모델 선택, 검색 Top-K 수, 가중치 필터 |
| **ex-draft** | 조치/답변 초안 생성 | RAG 조회 결과와 수집 데이터를 바탕으로 조치 지침서/답변 작성 | Prompt 템플릿(System/User), Max Tokens |

### 3.4 Sink / Writeback Nodes (출력 및 적재)
처리 결과를 외부 시스템에 전달하거나 온톨로지에 영구히 반영하는 종착 노드입니다.

| 노드 ID | 노드 표기명 | 목적 | 우측 속성 입력 필드 |
| :--- | :--- | :--- | :--- |
| **snk-mcp** | 외부 MCP 등록 | 특정 MCP 중계 계층(포트 8080/8081 등)을 호출하여 외부 게시판에 기재 | MCP 서버명, 도구명(e.g., comment.create), 매핑 파라미터 |
| **snk-ontology** | 온톨로지 저장 | 신규 인스턴스(FaultEvent 등) 및 관계 링크(has_task 등)를 온톨로지 적재 | 타겟 객체 타입, 속성-변수 매핑 테이블 |
| **snk-audit** | 감사 로그 및 알림 | 실행에 참여한 원천/가공 데이터 일체와 실행 타임라인을 기록 및 전송 | 로그 저장소 명칭, 알림 채널(e.g., Teams/Email) |

## 4. UI/UX 화면 설계 (Mockup)

화면은 작업 흐름을 한눈에 파악하고 제어할 수 있도록 **3분할 레이아웃**으로 구성한다.

```text
┌────────────────────────────────────────────────────────────────────────────────────────┐
│  🔄 파이프라인 빌더 (Pipeline Builder)                           [템플릿 저장] [배포 (Deploy)] │
├───────────────────────────┬────────────────────────────────────────────┬───────────────┤
│ 🛠️ 노드 팔레트            │ 🎨 캔버스 에디터 (React Flow Grid)         │ 📑 속성 패널  │
├───────────────────────────┤                                            │ (Properties)  │
│ 📥 입력 소스(Sources)     │    ┌──────────────┐                        ├───────────────┤
│   - 웹훅 이벤트 수신       │    │ 웹훅 이벤트   │                        │ 선택: [의도분류]│
│   - 배치 폴링 수집         │    └──────┬───────┘                        │               │
│                           │           │                                │ ■ LLM 모델:   │
│ ⚙️ 데이터 가공(Transforms)│           ▼                                │   GPT-4o      │
│   - LLM 의도/유형 분류 ───┼─────────▶ ┌──────────────┐                 │               │
│   - 설비/자산 매핑         │          │ LLM 의도분류 │                 │ ■ Prompt:     │
│   - 반복 고장 판단        │          └──────┬───────┘                 │   "아래 문의의 │
│                           │                 │                          │    의도를 분류..  │
│ 🧠 지능형 실행(Executes)  │                 ▼                          │               │
│   - RAG 근거 조회          │          ┌──────────────┐                 │ ■ 카테고리:   │
│   - 답변 초안 생성         │          │ 지식/RAG 조회│                 │   [계정, 결제] │
│                           │          └──────┬───────┘                 │               │
│ 📤 출력/적재(Sinks)        │                 │                          │               │
│   - 외부 MCP 등록          │                 ▼                          │               │
│   - 온톨로지 관계 저장      │          ┌──────────────┐                 │               │
│   - 감사 로그 기록         │          │ 외부 MCP 등록│                 │               │
│                           │          └──────────────┘                 │               │
└───────────────────────────┴────────────────────────────────────────────┴───────────────┘
```

### 4.1 핵심 인터랙션 가이드
1. **드래그 앤 드롭(Drag & Drop)**: 좌측 노드 팔레트에서 원하는 노드를 중앙 캔버스로 끌어다 놓으면 노드가 생성된다.
2. **연결선(Edge) 드래그**: 각 노드의 연결 포트(Handle)를 클릭 앤 드롭으로 이어 데이터 흐름 순서를 지정한다. (이때, 단방향 흐름만 허용하며 순환 연결은 방지)
3. **노드 선택**: 노드를 클릭하면 우측 속성 패널이 해당 노드의 타입에 맞는 설정 입력창(프롬프트, 매핑 필드, API 엔드포인트 등)으로 동적 전환된다.

## 5. 빌드 및 컴파일 흐름 (Compilation Flow)

사용자가 빌더 화면에서 우측 상단의 `[배포 (Deploy)]` 버튼을 클릭했을 때의 데이터 처리 파이프라인이다.

1. **DAG 유효성 검사**: 
   - 네트워크 연결이 단방향 유향 비순환 그래프(DAG) 구조를 충족하는지 검증한다.
   - 고립 노드가 존재하는지, 또는 루프가 형성되어 무한반복 가능성이 있는지 백엔드에서 우선 체크한다.
2. **속성값 유효성 검사**:
   - 각 노드에 기술된 필수 입력값(예: 웹훅 URL, LLM 프롬프트, 온톨로지 타겟 클래스 등)이 누락되었는지 검사한다.
3. **Pydantic 스키마 변환**:
   - 빌더 상의 노드와 에지 배열 데이터를 백엔드 `workflow_graphs.json` 포맷의 `nodes`와 `edges` 구조로 변환한다.
4. **저장 및 플랫폼 배포**:
   - 생성된 그래프 JSON 데이터를 `/storage/{company_id}/{project_id}/workflow_graphs.json` 에 프로젝트 스코프 템플릿(template_copy) 형태로 추가/갱신 저장한다.
   - 배포가 완료되는 즉시 **'워크플로우'** 실행 목록에 나타나며 기동될 준비를 마친다.

## 6. 저장 데이터 모델 명세 (Data Model)

파이프라인 빌더에서 디자인된 설정은 다음과 같이 기존 워크플로우 그래프 구조에 완벽히 호환되도록 컴파일된다.

```json
{
  "graph_id": "wfg-pipeline-generated-001",
  "name": "고객 문의 처리 파이프라인 (빌더 생성)",
  "scenario_id": "scenario1",
  "nodes": [
    {
      "id": "node-source-webhook",
      "type": "request_input",
      "data": {
        "label": "문의 이벤트 수신",
        "config": {
          "mode": "post",
          "auth_required": false
        }
      }
    },
    {
      "id": "node-transform-classify",
      "type": "intent_classify",
      "data": {
        "label": "LLM 의도분류",
        "config": {
          "model": "gpt-4o",
          "categories": ["password", "billing", "refund", "general"],
          "system_prompt": "문의 내용의 핵심 의도(intent)를 분류하시오."
        }
      }
    },
    {
      "id": "node-sink-mcp",
      "type": "customer_mcp_comment_create",
      "data": {
        "label": "외부 MCP 등록",
        "config": {
          "mcp_server": "customer_mcp",
          "port": 8080,
          "tool": "comment.create"
        }
      }
    }
  ],
  "edges": [
    {
      "id": "edge-1",
      "source": "node-source-webhook",
      "target": "node-transform-classify"
    },
    {
      "id": "edge-2",
      "source": "node-transform-classify",
      "target": "node-sink-mcp"
    }
  ]
}
```

## 7. 향후 로드맵 및 고려사항

1. **스키마 전파(Schema Propagation)**:
   - 이전 노드(예: Source)에서 지정한 출력 스키마(JSON 필드 목록)가 연결선을 타고 다음 노드(예: Transform)의 입력 변수 드롭다운 목록에 자동 완성으로 연동되게 설계하여 사용 편의성을 극대화한다.
2. **인라인 테스트(Interactive Testing / Preview)**:
   - 빌더 상에서 샘플 데이터를 넣고 `[테스트 실행]`을 누르면, 각 노드별 중간 가공 데이터를 미리 볼 수 있는 Preview 창 기능을 추가하여 디버깅 편의성을 제공한다.
3. **Palantir 대비 포지셔닝 차별화**:
   - 무거운 빅데이터 SQL 연산이 아닌, **LLM 에이전트(RAG) 조율, 외부 API/MCP 연동, 가벼운 온톨로지 그래프 적재에 초점**을 맞춘 **'AI 네이티브 파이프라인 빌더'**로서의 직관성을 시연 과정에서 강력히 내세운다.
