## 1. 개요 및 목적

본 문서는 온톨로지 플랫폼 v5에 성공적으로 통합된 **'데이터 흐름(Data Flow Lineage)'** 화면 및 API 연동 일체의 개발 완료 보고서입니다.  
기존 워크플로우 실행 추적 화면과 온톨로지 탐색 화면이 분리되어 있어 발생했던 데이터 라이프 사이클(수집 ➡️ 변환 ➡️ 조회 ➡️ 실행 ➡️ 외부 MCP writeback ➡️ 온톨로지 저장)의 분절된 설명력을 해결하고, 이를 단일 계보 캔버스에서 직관적으로 관제할 수 있도록 백엔드와 프론트엔드 전체 파이프라인을 실구현하였습니다.

## 2. 백엔드 개발 완료 내역

### 2.1 정적 데이터 흐름 설정 파일 (JSON)
시나리오별 데이터 계보의 흐름과 설명 메타데이터를 정적으로 정의하는 설정 스펙을 구성하였습니다.
- **[scenario1_customer_question.json](file:///E:/ontology_edu/X_ont_std/ont_platform/v5/backend/app/config/data_flows/scenario1_customer_question.json)**: 고객사 자동댓글 8단계 흐름 정의.
- **[scenario2_factory_fault.json](file:///E:/ontology_edu/X_ont_std/ont_platform/v5/backend/app/config/data_flows/scenario2_factory_fault.json)**: 공장 반복 고장 및 정비지시 자동발행 9단계 흐름 정의.

### 2.2 Pydantic 모델 설계
- **[data_flow.py](file:///E:/ontology_edu/X_ont_std/ont_platform/v5/backend/app/models/data_flow.py)**: 노드(`DataFlowNode`), 엣지(`DataFlowEdge`), 흐름 스펙(`DataFlowDefinition`) 직렬화 모델 설계.

### 2.3 API 라우터 구현
- **[data_flows.py](file:///E:/ontology_edu/X_ont_std/ont_platform/v5/backend/app/api/data_flows.py)**:
  - `GET /api/data-flows`: 등록된 시나리오 목록 조회.
  - `GET /api/data-flows/{flow_id}`: 정적 노드/엣지 다이어그램 조회.
  - `GET /api/data-flows/{flow_id}/runs/{workflow_run_id}`: 특정 실행 이력과 매핑하여 성공/실패 상태가 바인딩된 캔버스 데이터 조회.

### 2.4 동적 상태 매핑 서비스 로직 구현
- **[data_flow_service.py](file:///E:/ontology_edu/X_ont_std/ont_platform/v5/backend/app/services/data_flow_service.py)**:
  - 워크플로우 실행이 완료되면 생성되는 `{run_id}.json` 스냅샷 파일(Storage 내)을 읽어들여, 정적 노드에 대응하는 워크플로우 노드(예: `n6-writeback` ➡️ `customer-comment-create` 등)의 실행 결과를 탐색.
  - 단계별 `COMPLETED`(success), `FAILED`(failed), `RUNNING`(running) 등의 상태를 색상 코드로 변환하고, 입출력(`inputs`, `outputs`) 및 에러 메시지(`error`)를 동적으로 주입.

### 2.5 메인 서버 등록
- **[main.py](file:///E:/ontology_edu/X_ont_std/ont_platform/v5/backend/app/main.py)**:
  - 신규 라우터인 `data_flows_router`를 `/api/data-flows` 경로로 서버 엔트리에 성공적으로 바인딩 및 등록 완료.

## 5. 향후 R&D 고도화 방향 (Phase 4+)
1. **데이터 품질(Quality Check) 상태 연동**: 각 transform 노드에서 데이터가 정제될 때 품질 룰(Null check, Range check) 위반 건수를 노드 칩에 배지로 표기.
2. **영향도 분석(Impact Analysis) 지원**: persist 단계의 온톨로지 객체를 클릭하면, 다운스트림(Downstream) 관계망에서 영향을 받는 자산과 장비 리스트를 하이라이트하는 시각적 경로 역추적 기능 추가.
3. **재시도(Retry Trigger) 액션 통합**: writeback 단계에서 외부 등록이 실패(DLQ)했을 때, 캔버스 노드 상의 '재시도' 버튼을 클릭하면 즉각 백엔드 writeback API를 호출하는 상호작용성 강화.
