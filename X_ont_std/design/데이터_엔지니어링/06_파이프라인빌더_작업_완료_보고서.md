### 2.2 React Flow 기반 에디터 구현 (`PipelineBuilderView.tsx`)
- **시각적 저작 도구**:
  - React Flow를 탑재한 드로잉 캔버스를 구현하고 그리드 배경, 줌 컨트롤러, 미니맵을 내장하여 팔란티어 Foundry의 Pipeline Builder 스타일과 유사한 고급스럽고 프리미엄한 다크/라이트 Glassmorphism 테마를 구현했습니다.
- **노드 카탈로그 드래그앤드롭**:
  - 좌측 노드 팔레트에 4개 영역(Sources, Transforms, Executes, Sinks)으로 분류된 10종의 특화된 노드를 배치하여 사용자가 드래그해서 캔버스에 자유롭게 추가할 수 있는 인터랙션을 지원합니다.
- **커넥션 및 노드 제어**:
  - 각 노드의 포트를 통해 단방향 흐름 연결선을 제어할 수 있으며, 캔버스 상의 노드를 클릭하면 우측 속성 패널(Properties Panel)에서 세부 폼(프롬프트 내용, 카테고리 필드, MCP 서버/도구 파라미터 등)을 동적으로 갱신할 수 있는 양방향 데이터 바인딩을 구현했습니다.
- **클린 캔버스 및 삭제**:
  - 캔버스의 모든 노드를 지울 수 있는 초기화 및 개별 선택된 노드를 손쉽게 삭제할 수 있는 휴지통 기능을 완비했습니다.

## 3. 백엔드 연동 및 컴파일러 구현 검증

- **범용 워크플로우 API 재활용**:
  - 백엔드의 `/api/workflow-graphs` (POST/GET) API는 임의의 JSON 노드와 엣지를 데이터 모델로 저장하고 관리하는 범용 설계가 구현되어 있습니다.
  - 따라서 파이프라인 빌더에서 생성된 React Flow 구조의 데이터를 백엔드가 완벽하게 해석할 수 있는 Pydantic 및 JSON 구조로 실시간 컴파일하여, 신규 개발 공수 없이 높은 안정성으로 API를 재활용하여 저장에 성공했습니다.
- **배포 및 저장 경로**:
  - 배포(`[배포 (Deploy)]` 버튼) 진행 시 `/api/workflow-graphs` API로 JSON Payload를 전송하고, 백엔드는 해당 테넌트 프로젝트 폴더의 `workflow_graphs.json`에 `template_copy` 종류의 신규 그래프로 안전하게 병합 저장함을 검증했습니다.

## 4. 수동 배포 및 실행 검증 절차

개발 완료 후 아래 시나리오 검증을 수동으로 수행하여 통합 안정성을 확인했습니다.

1. **파이프라인 조립 및 배포**:
   - 좌측 메뉴 '파이프라인 빌더'에 진입.
   - `배치 폴링 수집(Source)` ➡️ `LLM 의도/유형 분류(Transform)` ➡️ `온톨로지 저장(Sink)` 순서로 노드를 드롭하고 엣지로 연결.
   - 각 노드 설정값 입력 완료 후 우측 상단의 `[배포 (Deploy)]` 버튼 클릭.
   - 성공 메시지("성공적으로 데이터 파이프라인을 배포했습니다!") 팝업 및 HTTP 200 OK 수신 확인.
2. **저장 결과 확인**:
   - 배포 후 '워크플로우 홈(Workflow Home)' 템플릿 갤러리에 저장한 파이프라인 이름이 표시되는지 확인.
   - 백엔드의 `workflow_graphs.json` 파일에 컴파일된 노드와 엣지가 스키마 명세에 맞추어 정확하게 기재되었는지 교차 검증.

## 5. 결론 및 향후 개선 방향

이번 파이프라인 빌더 통합 개발을 통해 ont_platform v5는 데이터 계보를 보기만 하는 읽기 전용 모니터링 도구에서 탈피하여, 사용자가 **직접 데이터 수집 및 변환 흐름을 AI 프롬프트 수준에서 설계하고 온톨로지와 결합하는 진정한 시각적 AI 데이터 통합 저작 환경(No-code AI ETL Builder)**을 갖추게 되었습니다.

**향후 마이너 개선 사항 (Phase 6+)**:
1. 노드 간 입력/출력 컬럼 스키마를 유추 및 전달해 주는 **'스키마 전파(Schema Propagation)'** 자동화 구현.
2. 캔버스 상에서 각 노드 단계의 가공 결과를 즉석에서 모의 데이터로 테스트 실행하여 에러와 출력을 검증할 수 있는 **'노드 단위 인라인 프리뷰(Node-level Preview)'** 기능 탑재.
