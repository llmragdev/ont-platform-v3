## 1. 개요 및 현재 상태 요약

AI Assistant와 Streamlit 앱 빌더를 연동하여 사용자가 챗봇에 코딩을 요청하고, 그 결과가 소스 코드 편집창에 자동 적용된 뒤 실제로 서버에서 구동되는 전체 파이프라인의 MVP를 구축했습니다.

- **백엔드 (`/api/streamlit-apps/run`)**: 실제 Streamlit 실행 및 미설치 시 Fallback HTML Preview를 지원하는 실행 서비스 구현 완료.
- **프론트엔드 연동**: AI Assistant 대화 답변에서 Python 코드를 추출하여 편집기에 자동 적용하는 이벤트 흐름 통합 완료.
- **주요 블로커**: 화면 레이아웃에서 코드 편집기(`textarea`) 영역이 수직으로 찌그러지거나(높이 0px 부근) 하단으로 스크롤되어 밀려 보이는 UI 결함이 지속되고 있습니다. 또한, 우측 채팅창의 추천 질문 카드 및 디자인 요소가 너무 커서 이전 대화 맥락이 잘 보이지 않는 불편이 있습니다.

## 3. 핵심 미해결 UI 블로커 및 분석

### 3.1 소스 편집창 (Textarea) 높이 붕괴 버그
- **현상**: StreamlitAppBuilder 화면 중앙의 소스 코드 입력용 `textarea`가 찌그러져서 코드를 보거나 수정할 수 없는 상태입니다.
- **원인 분석**:
  1. **부모 레이아웃의 스크롤 설정**: `page.tsx`에서 주 화면인 `<main data-testid="app-main">` 요소에 `overflow-y-auto`가 걸려 있어 높이가 유동적입니다.
  2. **Grid의 높이 계산 오류**: [StreamlitAppBuilder.tsx](file:///e:/ontology_edu/X_ont_std/ont_platform/v5/frontend/src/components/StreamlitAppBuilder.tsx)의 컨테이너 `div`가 `h-[calc(100vh-9.5rem)] min-h-[680px]`를 가지나, 그 자식인 편집 패널 `<main>` 내부에서 Flex-col 레이아웃이 적용되고, 다시 그 안의 `<div className="grid min-h-0 flex-1 lg:grid-cols-[220px_minmax(0,1fr)]">`로 나뉩니다.
  3. **h-full의 붕괴**: 우측 편집 영역 `<div className="min-h-0 h-full bg-slate-950 flex flex-col">`이 `h-full`을 명시하고 있으나, Grid의 직계 자식이 `h-full`을 사용할 때 상위 Grid 컨테이너에 명시적인 높이 한계가 정의되어 있지 않거나 Flex layout 높이 축소 정책(`min-h-0`)과 충돌하면서 최종 `textarea` 높이가 최대로 늘어나지 못하고 content가 없으면 0px에 수렴하며 붕괴하는 현상이 발생합니다.

### 3.2 AI Assistant 채팅 대화창 시인성 저하
- **현상**: "이전 대화가 잘 보이지 않고, UI 요소(박스, 버튼 등)와 폰트 크기가 너무 커서 대화창 면적이 좁다"는 불만이 있습니다.
- **원인 분석**:
  1. 추천 질문(`QUICK_PROMPTS`) 영역이 큰 카드 형태로 고정되어 화면의 절반 가까이 차지합니다.
  2. 대화 말풍선의 폰트 크기가 기본 `text-xs`(12px) 및 `text-sm`으로 설정되어 있고 패딩이 넓어 한 화면에 몇 문장 표시되지 못합니다.
  3. "대상 파일 정보" 카드, "적용 대상" 알림판 등 부가 정보 컴포넌트의 수직 높이가 지나치게 큽니다.
