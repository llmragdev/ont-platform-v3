## 3. 핵심 모듈 설계

### 3.1 TenantContext (`models/tenant_context.py`)

```python
@dataclass
class TenantContext:
    user_id: str
    company_id: str
    project_id: str
    role: str
    permissions: dict[str, bool]

    def can(self, flag: str) -> bool:
        return self.permissions.get(flag, False)
```

**역할**: 요청 1건당 1개 생성. 모든 서비스가 이 컨텍스트만 받아 scope를 결정.  
FastAPI `Depends`로 주입 — 라우터는 TenantContext를 직접 생성하지 않는다.

### 3.6 FastAPI 의존성 연결 (`app/main.py`)

```python
# TenantContext 생성 Depends
def get_tenant_context(
    user_id: str = Depends(get_current_user),
    tm: TenantManager = Depends(get_tenant_manager),
) -> TenantContext:
    user = tm.get_user(user_id)
    return TenantContext(
        user_id=user_id,
        company_id=user["company_id"],
        project_id=...,   # 헤더 또는 기본값
        role=user["role"],
        permissions=tm.resolve_permissions(user),
    )

# 라우터 예시
@router.post("/api/documents/upload")
async def upload_document(
    file: UploadFile,
    ctx: TenantContext = Depends(get_tenant_context),
    svc: DocumentService = Depends(get_document_service),
):
    return svc.upload(await file.read(), file.filename, ctx)
```

## 4. 데이터 흐름

### 4.1 문서 업로드 흐름

```
POST /api/documents/upload (PDF)
  │
  ▼
get_tenant_context()
  company_id = "acme", project_id = "proj-001"
  │
  ▼
DocumentService.upload(bytes, filename, ctx, shard_id="default")
  │
  ├── ensure_project_dirs("acme", "proj-001")
  │     → storage/acme/proj-001/uploads/    ← PDF 저장
  │     → storage/acme/proj-001/vector_db/  ← 생성
  │
  ├── PyPDFLoader → 청크 분할
  │
  └── Chroma(persist_dir=storage/acme/proj-001/vector_db/Vdefault)
        .add_documents(chunks)
  │
  ▼
응답: {doc_id, chunk_count, shard_id: "default"}
```

### 4.2 벡터 검색 흐름 (전체 샤드)

```
POST /api/search  {"query": "...", "k": 5}
  │
  ▼
VectorSearchService.search(query, ctx, k=5, shard_id=None)
  │
  ├── list_shard_paths("acme", "proj-001")
  │     → [Vdefault, V5001, V5002]
  │
  ├── Chroma(Vdefault).similarity_search_with_score(query, k=5)
  ├── Chroma(V5001).similarity_search_with_score(query, k=5)
  └── Chroma(V5002).similarity_search_with_score(query, k=5)
        │
        ▼
  결과 합산 → score 내림차순 → 상위 5개
  │
  ▼
응답: [{text, score, doc_id, filename, page, shard_id}, ...]
```

### 4.3 온톨로지 저장 경로

```
POST /api/ontology/{doc_id}/entities
  │
  ▼
OntologyService.upsert_entity(doc_id, entity, ctx)
  │
  └── get_ontology_path("acme", "proj-001")
        → storage/acme/proj-001/ontology/
```

## 6. V-ID 샤딩 전략

### Sprint 07: Option C (단일 default 샤드)

```
문서 업로드 시 shard_id 결정:
  - 기본값: "default"
  - API 파라미터 target_v_id 지정 시 해당 값 사용

파일 경로:
  → storage/{company_id}/{project_id}/vector_db/Vdefault/

확장 시 (Sprint 08+):
  Option A: 사용자가 명시 (target_v_id 파라미터) — API 파라미터 이미 준비됨
  Option B: 문서 카테고리 기반 자동 배정
```

### V-ID 명명 규칙

| shard_id | 디렉토리 | 용도 |
|----------|----------|------|
| `default` | `Vdefault` | 단순 단일 샤드 프로젝트 |
| `5001` | `V5001` | 도메인 파티션 1번 |
| `5002` | `V5002` | 도메인 파티션 2번 |
