## 2. Phase 1 설계: LLM 엔진

### 2.1 LlmClient (`services/llm_client.py`)

**역할**: Gemini API 단일 진입점. 모든 LLM 호출은 이 클래스를 통함.

```python
class LlmClient:
    def __init__(self, api_key: str | None):
        self._enabled = bool(api_key)
        # google-generativeai 또는 langchain_google_genai 사용

    def generate(
        self,
        prompt: str,
        *,
        model: str = "gemini-1.5-flash",
        temperature: float = 0.2,
        max_tokens: int = 1024,
    ) -> str:
        """LLM 텍스트 생성. API 키 없으면 None 반환."""

    def classify(self, prompt: str) -> dict:
        """JSON 응답 기대 호출. 파싱 실패 시 {} 반환."""

    @property
    def enabled(self) -> bool:
        """API 키 있으면 True. Fallback 분기 판단에 사용."""
```

**설계 원칙**:
- `enabled=False`일 때 모든 메서드는 빈 값 반환 (예외 없음)
- 재시도: 최대 2회, 지수 백오프
- 타임아웃: 10초

### 2.2 HybridSynthesizer 재설계

**현재 (v2.0)**:
```python
def _answer(...) -> str:
    return f"Found {vector_count} document result(s)."
```

**v3.0**:
```python
def synthesize(self, question, plan, ontology_results, vector_results, trace) -> QueryResponse:
    if self._llm.enabled:
        context = self._build_context(ontology_results, vector_results)
        prompt = self._render_prompt("synthesizer.txt", question=question, context=context)
        answer = self._llm.generate(prompt)
    else:
        answer = self._fallback_answer(plan.intent, len(ontology_results), len(vector_results))
    ...
```

**프롬프트 템플릿** (`prompts/synthesizer.txt`):
```
당신은 기업 온톨로지 기반 AI 어시스턴트입니다.

질문: {question}

온톨로지 검색 결과 ({ontology_count}건):
{ontology_items}

문서 검색 결과 ({vector_count}건):
{vector_chunks}

위 정보를 바탕으로 질문에 답변하세요.
- 정보가 없으면 "관련 데이터를 찾지 못했습니다"라고 답하세요.
- 답변 마지막에 사용한 근거를 [출처: doc-xxx p.N] 형식으로 표시하세요.
- 한국어로 답변하세요.
```

### 2.3 QueryPlanner LLM 분류

**현재 (v2.0)**: 키워드 목록 매칭 → `DESCRIPTIVE / FILTER / HYBRID`

**v3.0**: LLM 우선, 실패 시 키워드 fallback

```python
def classify_intent(self, query: str, ctx) -> QueryPlan:
    if self._llm.enabled:
        result = self._llm.classify(self._render_prompt("classifier.txt", query=query))
        intent = IntentType(result.get("intent", "descriptive"))
    else:
        intent = self._heuristic_classify(query)  # 기존 로직 유지
    ...
```

**프롬프트 템플릿** (`prompts/classifier.txt`):
```
다음 질문의 의도를 분류하세요.

질문: {query}

의도 유형:
- filter: 특정 조건으로 데이터 필터링 ("~인 것 목록", "~가 X인 항목")
- descriptive: 설명/개념 질문 ("~란?", "~의 장점은?", "~가 왜?")
- hybrid: 필터 + 설명 복합 ("~인 항목의 특징은?")

JSON으로만 응답하세요:
{"intent": "descriptive", "reasoning": "설명 질문"}
```

## 3. Phase 2 설계: 데이터 모델

### 3.1 OntologyEntity Provenance 모델

**현재 (v2.0)** 구조:
```json
{
  "id": "E001",
  "type": "PRODUCT",
  "name": "Snowflake",
  "properties": {}
}
```

**v3.0** 구조 (`models/ontology.py`):
```python
class OntologyProvenance(BaseModel):
    source_doc_id: str | None = None      # 출처 문서 ID
    source_page: int | None = None         # 출처 페이지
    source_chunk_id: str | None = None     # 출처 청크 ID
    source_text: str | None = None         # 원문 (최대 500자)
    confidence: float = 1.0                # 추출 신뢰도 (0.0~1.0)
    extracted_by: str | None = None        # "llm" | "manual" | "import"

class OntologyEntityV3(BaseModel):
    id: str
    type: str
    name: str
    properties: dict = {}
    # v3.0 신규 필드 (모두 Optional → 하위 호환)
    provenance: OntologyProvenance | None = None
    status: Literal["active", "review", "deprecated"] = "active"
    version: int = 1
    created_by: str | None = None
    created_at: str | None = None
    updated_at: str | None = None
```

**하위 호환**: 기존 JSON 파일의 엔티티는 `provenance=None, status="active", version=1` 으로 자동 처리.

### 3.2 StructuredQueryPlan

**현재 (v2.0)** `QueryPlan`:
```python
class QueryPlan(BaseModel):
    intent: IntentType
    steps: list[QueryAction]
    schema_context: dict
```

**v3.0** 추가 필드:
```python
class OntologyFilter(BaseModel):
    entity_type: str | None = None
    property: str | None = None
    operator: Literal["eq", "contains", "gt", "lt"] = "eq"
    value: str | None = None

class QueryPlanV3(QueryPlan):
    # 기존 필드 유지 + 신규 추가
    ontology_filters: list[OntologyFilter] = []
    needs_vector: bool = True
    doc_ids: list[str] | None = None          # None = 전체 문서
    estimated_cost: str = "low"               # "low" | "medium" | "high"
    validated: bool = False
```

### 3.4 QueryPlanValidator

```python
# services/query_plan_validator.py
class QueryPlanValidator:
    def validate(self, plan: QueryPlanV3, ctx: TenantContext) -> ValidationResult:
        errors = []

        # 1. entity_type 존재 여부
        schema = self._get_schema(ctx)
        valid_types = {t["name"] for t in schema.get("entity_types", [])}
        for f in plan.ontology_filters:
            if f.entity_type and f.entity_type not in valid_types:
                errors.append(f"Unknown entity_type: {f.entity_type}")

        # 2. property 존재 여부
        for f in plan.ontology_filters:
            if f.property and f.entity_type:
                allowed = self._get_properties(ctx, f.entity_type)
                if f.property not in allowed:
                    errors.append(f"Unknown property '{f.property}' for {f.entity_type}")

        # 3. doc_ids tenant 범위 확인
        if plan.doc_ids:
            accessible = self._get_accessible_docs(ctx)
            for doc_id in plan.doc_ids:
                if doc_id not in accessible:
                    errors.append(f"Inaccessible doc_id: {doc_id}")

        return ValidationResult(valid=len(errors) == 0, errors=errors)
```

### 4.2 인증 미들웨어 (`middleware/auth.py`)

**v2.0**: `x-user-id: alice` 헤더를 그대로 신뢰  
**v3.0**: HMAC 서명 검증 (JWT는 Phase 3 후반)

```python
class HmacAuthMiddleware(BaseHTTPMiddleware):
    """
    요청 헤더:
      x-user-id: alice
      x-timestamp: 1716000000
      x-signature: HMAC-SHA256(secret, f"{user_id}:{timestamp}")
    """
    async def dispatch(self, request: Request, call_next):
        # /api/health 는 인증 제외
        if request.url.path in SKIP_AUTH_PATHS:
            return await call_next(request)

        user_id = request.headers.get("x-user-id", "")
        timestamp = request.headers.get("x-timestamp", "")
        signature = request.headers.get("x-signature", "")

        if not self._verify(user_id, timestamp, signature):
            return JSONResponse({"detail": "Unauthorized"}, status_code=401)

        return await call_next(request)
```

**주의**: Phase 3 초기에는 `JWT_SECRET` 미설정 시 미들웨어 비활성화 (하위 호환).

## 8. 설계 결정 사항 (ADR)

### ADR-001: LLM 클라이언트 직접 구현 vs LangChain

**결정**: 직접 구현 (`services/llm_client.py`)

**이유**:
- LangChain 의존성이 이미 `document.py`에서 임포트 에러를 일으킨 전례가 있음
- Gemini 직접 호출은 `google-generativeai` 패키지로 단순하게 가능
- LangChain은 벡터 저장소(Chroma)에만 유지

### ADR-002: Repository 패턴 도입 시점

**결정**: Phase 2에서 인터페이스만 도입, 구현체는 JSON 유지

**이유**:
- Phase 2에서 SQLite로 전환하면 리스크가 커짐
- 인터페이스 분리만으로 Phase 4에서 교체 가능한 구조 확보
- 기존 테스트를 JSON 구현체로 계속 실행 가능

### ADR-003: Gemini 모델 선택

**결정**: `gemini-1.5-flash` (기본), `gemini-1.5-pro` (선택)

**이유**:
- flash는 응답 빠름 (~1초), 비용 낮음 → 분류·합성에 적합
- pro는 복잡한 다단계 추론에 사용 (hybrid 질의 등)
- `LlmClient` 생성 시 모델명 주입 가능하게 설계
