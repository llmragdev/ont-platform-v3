# 하이브리드 질의 시스템 분석 및 고도화 제안 보고서

> **대상 프로젝트:** claud_통합  
> **분석 범위:** 온톨로지 + 벡터 DB 결합형 질의 시스템 (Hybrid Query)  
> **작성일:** 2026-05-13  

---

## 1. 개요
본 보고서는 `claud_통합` 프로젝트에 설계된 **하이브리드 질의(Hybrid Query)** 시스템에 대한 심층 분석과 엔터프라이즈급 성능 확보를 위한 고도화 방안을 제안합니다.

현재의 설계는 비정형 텍스트 검색(Vector RAG)과 정형 관계 검색(Ontology)의 장점을 결합하여, 기존 RAG가 처리하기 어려웠던 **필터링, 비교, 수치 계산** 문제를 해결하는 데 중점을 두고 있습니다.

---

## 2. 현 설계 분석 (Strengths & Weaknesses)

### ✅ 강점 (Strengths)
1. **유연한 스키마 전략:** Built-in(범용) 유형과 Domain-specific(도메인) 유형을 분리하여 하드코딩 없이 다양한 도메인에 대응 가능.
2. **인간 개입형 교정(HITL):** LLM 추출의 불완전성을 인정하고 사용자가 UI를 통해 데이터를 보정할 수 있는 관리 도구 설계.
3. **지능형 라우팅:** LLM을 이용해 질문 의도를 분류(Classification)하고 검색 경로를 동적으로 결정.

### ⚠️ 보완 필요 사항 (Weaknesses)
1. **추출 컨텍스트 한계:** 현재 12,000자 제한 방식은 대용량 기술 문서나 보고서 처리 시 정보 누락 가능성 존재.
2. **개별 문서 파편화:** 온톨로지가 문서별(doc_id) JSON으로 관리되어 여러 문서에 걸친 통합 비교 질의 시 추가 로직 필요.
3. **질의 엔진의 경직성:** 고정된 메서드 기반 검색은 복잡한 다중 조건(N-Hop) 질문 대응에 한계가 있음.

---

## 3. 고도화 제안 (Improvement Proposals)

### 3-1. 대용량 문서 추출 전략: Map-Reduce 방식 도입
긴 문서를 처리하기 위해 단순 절단 대신 **청크별 추출 후 병합** 프로세스를 제안합니다.
- **Map:** 각 페이지/청크별로 엔티티와 관계를 독립적으로 추출.
- **Reconcile (Reduce):** 추출된 엔티티 중 이름이 다르지만 동일 대상인 경우(예: 'Snowflake Inc', '스노우플레이크')를 LLM이 식별하여 하나의 노드로 병합.

### 3-2. 지능형 질의 플래너 (Text-to-GraphQuery)
고정된 API 호출 대신, 질문을 **정형 질의 계획(JSON Query Plan)**으로 변환하는 엔진을 구축합니다.
- 질문: *"2024년 매출 지표가 있는 통신사 고객 목록을 알려줘"*
- 플랜 생성: `[Find: ORGANIZATION(type=통신사)] -> [Link: HAS_METRIC] -> [Filter: METRIC(name=매출, year=2024)]`

### 3-3. 가상 통합 그래프 (Virtual Merged Graph)
질의 시점에 선택된 여러 문서의 JSON을 메모리상에서 하나의 그래프(NetworkX 등 활용)로 결합하여 **문서 간 비교 및 크로스 참조**가 가능하도록 확장합니다.

### 3-4. 하이브리드 답변 합성 (Context-Aware Synthesis)
단순히 두 결과를 합치는 것이 아니라, LLM에게 전달하는 프롬프트에 **데이터 소스별 신뢰도 가이드**를 부여합니다.
- 온톨로지 결과 = **Fact (우선순위 높음)**
- 벡터 청크 결과 = **Context (서술적 보완)**

## 4. 향후 구현 로드맵 추천

1.  **Phase 1 (추출 고도화):** `ontology_extractor.py`에 대용량 문서 대응 로직(Map-Reduce) 추가.
2.  **Phase 2 (동적 질의):** `ontology_query_engine.py` 구현 시 LLM 기반 Query Planning 도입.
3.  **Phase 3 (통합 아키텍처):** `app_context.py`에 `ask_hybrid` 메서드를 구현하여 분류-검색-합성 파이프라인 완성.
