# 벡터DB + 온톨로지 하이브리드 질의 요건

> 작성일: 2026-05-12  
> 목적: Snowflake 소개서 PDF 기준, 순수 벡터 RAG로 답변 불가한 구조형 질문을 온톨로지와 결합하여 처리

---

## 배경 — 벡터 RAG의 한계

| 질문 유형 | RAG | 온톨로지 |
|-----------|-----|---------|
| 서술형 설명 | 잘 됨 | 과잉 |
| 필터/분류 | 불안정 | 정확 |
| 엔티티 간 관계 비교 | 불안정 | 정확 |
| 수치 계산/집계 | 불가 | 정확 |
| 다중 조건 교차 | 불안정 | 정확 |

---

## 1. 백엔드 — 온톨로지 자동 구축 (PDF → Graph)

| # | 요건 |
|---|------|
| B-01 | PDF 업로드 시 벡터 임베딩과 동시에 **엔티티 추출** 옵션 제공 (LLM 기반) |
| B-02 | 추출 엔티티 유형: `회사`, `인물`, `기능`, `과금방식`, `고객사`, `클라우드제공자`, `데이터공유방식`, `아키텍처계층` |
| B-03 | 엔티티 간 관계 추출 및 저장 (예: `창립자→소속회사`, `기능→과금유형`, `고객사→산업군`) |
| B-04 | 온톨로지 저장소: JSON 파일 or in-memory dict (Chroma와 별도) |
| B-05 | **하이브리드 ask()**: 질문 유형 자동 판별 → 서술형은 벡터, 구조형은 온톨로지, 복합은 둘 다 |
| B-06 | 온톨로지 질의 지원 유형: 필터링, 엔티티 비교, 수치 계산, 카테고리 탐색 |

---

## 2. 백엔드 — 질문 유형 분류기

| # | 요건 |
|---|------|
| B-07 | 질문 입력 시 `descriptive` / `filter` / `compare` / `calculate` / `hybrid` 중 하나로 분류 |
| B-08 | 분류 결과에 따라 검색 경로 분기 (벡터만 / 온톨로지만 / 둘 다) |

---

## 3. 프론트엔드 — 통합 질의 화면 (현재 "준비중" 메뉴)

| # | 요건 |
|---|------|
| F-01 | 현재 placeholder인 `통합 질의` 메뉴를 실제 화면으로 구현 |
| F-02 | 질의 입력창 1개 (자유 질문 — 유형 자동 감지) |
| F-03 | 질문 유형 감지 결과 배지 표시 (예: `필터형`, `비교형`, `서술형`) |
| F-04 | 답변 영역: **서술형 답변** + **구조형 결과 (표/목록)** 동시 표시 |
| F-05 | 근거 출처: 벡터 청크 근거 + 온톨로지 노드 경로 각각 표시 |
| F-06 | PDF 업로드 시 "온톨로지 추출 포함" 체크박스 추가 (RAG 문서 질의 화면) |

## 5. 설계 시 판단 필요한 포인트

- 온톨로지 추출을 **업로드 시 자동**으로 할지 vs **별도 버튼**으로 할지
- 온톨로지 저장을 **JSON 파일**로 할지 vs **SQLite/NetworkX 그래프**로 할지
- LLM 엔티티 추출을 **청크별**로 할지 vs **전체 문서 요약본**으로 할지
