# v4 RDF 성능 기준선

본 문서는 Phase 4 Week 4 성능 최적화(Performance) 설계의 일환으로, `ont_platform/v4`에서 활용되는 RDF 그래프 저장소, SPARQL 질의 및 외부 온톨로지(DBpedia, Wikidata, 로컬 RDF 파일) 임포트 프로세스의 성능 기준선(Baseline)과 성능 SLA를 정의합니다.

---

## 1. RDF 그래프 저장소 성능

v4 RDF 모듈은 메모리 기반 인메모리 RDF 그래프 저장소(rdflib InMemory Graph 또는 Oxigraph 등)를 백엔드로 사용함을 전제로 설계되었습니다. 트리플(Triple, 주어-술어-목적어 관계의 쌍) 규모 증가에 따른 예상 성능 메트릭은 다음과 같습니다.

### Triple 저장소 규모별 성능
*   **10K 트리플 (소형 온톨로지/단일 서브그래프)**:
    *   **로드 시간**: < 100ms
    *   **메모리 사용**: < 50MB (인메모리 그래프 로드 후 상주 메모리 기준)
    *   **쿼리 응답**: < 50ms
*   **100K 트리플 (중형 온톨로지/통합 스키마)**:
    *   **로드 시간**: < 500ms
    *   **메모리 사용**: < 200MB
    *   **쿼리 응답**: < 150ms
*   **1M 트리플 (대형 온톨로지/전체 도메인 모델)**:
    *   **로드 시간**: < 2초
    *   **메모리 사용**: ~1GB
    *   **쿼리 응답**: < 500ms (적절한 트리플 인덱스 활용 시)

---

## 2. SPARQL 쿼리 성능

SPARQL 질의는 관계형 데이터베이스와 달리 그래프 패턴 매칭 방식으로 작동하므로 질의의 복잡도와 조인(JOIN, 즉 공유 변수 매칭) 및 OPTIONAL 패턴 수에 따라 성능이 크게 좌우됩니다.

### 쿼리 유형별 성능 기준선

*   **SELECT 쿼리 (단순 패턴 매칭 및 필터링)**:
    *   `10K 트리플`: < 20ms
    *   `100K 트리플`: < 50ms
    *   `1M 트리플`: < 200ms
*   **CONSTRUCT 쿼리 (그래프 변환 및 신규 그래프 빌딩)**:
    *   `10K 트리플`: < 30ms
    *   `100K 트리플`: < 100ms
    *   `1M 트리플`: < 400ms
*   **복합 SPARQL (다중 JOIN / Multi-Hop 관계 탐색)**:
    *   `2-hop 관계` (e.g., `?x :knows ?y . ?y :knows ?z`): < 100ms
    *   `3-hop 관계`: < 300ms
    *   `5-hop 관계`: < 800ms
*   **선택적 패턴 (OPTIONAL 질의)**:
    *   `제약 없음 (기본 패턴)`: < 100ms
    *   `1개 OPTIONAL 패턴`: < 150ms
    *   `3개 OPTIONAL 패턴`: < 300ms
    *   *(주의: 1M 트리플 이상에서 중첩 OPTIONAL 패턴은 쿼리 플래너의 카티션 곱 유발로 기하급수적 성능 저하 우려가 있으므로 FILTER나 UNION 결합을 권장)*

## 3. 외부 소스 Import 성능

외부 온톨로지 소스(DBpedia, Wikidata) 또는 로컬 RDF/XML, Turtle, N-Triples 파일 포맷을 파싱하고 로컬 RDF 저장소에 수입(Import)할 때의 네트워크 및 파일 I/O 기준 성능입니다.

### DBpedia Import
*   **리소스당 쿼리 시간**: < 500ms (DBpedia 공개 SPARQL 엔드포인트 응답 지연 기준)
*   **속성 처리 속도**: 속성(Property)당 < 50ms
*   **배치 처리 (100개 리소스)**: < 30초 (네트워크 스로틀링 및 병렬 커넥션 제어 포함)

### Wikidata Import
*   **아이템 JSON 처리**: < 100ms
*   **Claim 파싱 속도**: Claim(명제/속성 값)당 < 20ms
*   **배치 처리 (100개 리소스)**: < 10초

### 로컬 RDF 파일 Import (파싱 및 로딩)
*   **10K 트리플 파일**: < 200ms
*   **100K 트리플 파일**: < 1초
*   **1M 트리플 파일**: < 5초

## 4. 캐싱 전략

대량의 그래프 질의와 빈번한 탐색으로 인한 백엔드 CPU 부하를 완화하기 위해 Redis 및 메모리 캐시를 이중으로 구성합니다.

### 4.1 SPARQL 쿼리 캐시
*   **Key 포맷**: `sparql:{query_hash}` (SPARQL 질의 문자열과 매개변수를 해싱하여 키 구성)
*   **TTL (Time-To-Live)**: 5분 (정적이며 자주 변경되지 않는 RDF 메타데이터 조회에 최적화)
*   **Hit Rate 목표**: ≥ 80% (반복 질의 및 대시보드 뷰어 기준)
*   **Cache 무효화(Invalidation) 트리거**:
    *   새로운 온톨로지 Import 발생 시 (해당 그래프 세그먼트 전체 캐시 무효화)
    *   SPARQL UPDATE 질의 등을 통한 그래프 구조/트리플 변경 시
    *   정해진 TTL 만료 시

### 4.2 RDF 그래프 인덱스 캐시
*   **Key 포맷**: `rdf:index:{graph_id}`
*   **TTL (Time-To-Live)**: 1시간
*   **Index 캐싱 대상 구조**:
    *   `SPO (Subject-Predicate-Object)` 인덱스 캐시
    *   빈번하게 검색되는 Triple 패턴의 캐시화
    *   노드 및 엣지별 Degree(차수) 정보 및 메타 정보 사전 로드 데이터

## 5. 성능 SLA (v4 RDF)

시스템의 성능 안정성을 담보하기 위해 설정한 핵심 지표 SLA(Service Level Agreement)는 다음과 같이 3개 Tier로 구성됩니다.

### Tier 1: Critical (시스템 구동 및 핵심 사용자 경험 필수의 마지노선)
1.  **SPARQL SELECT 쿼리**: < 200ms (100K 트리플 규모 그래프 조회 시)
2.  **외부 리소스 Import**: < 500ms (단일 엔티티 조회 및 파싱 완료)
3.  **RDF 그래프 로드**: < 500ms (100K 트리플 바이너리/캐시 로딩 완료)

### Tier 2: Important (체감 성능 향상을 위해 충족해야 할 중요 지표)
4.  **SPARQL CONSTRUCT**: < 300ms (100K 트리플 기반 신규 뷰 그래프 생성)
5.  **배치 Import**: < 30초 (100개 리소스 외부 API 병렬 호출 수입 완료)
6.  **복합 SPARQL (3-hop 관계)**: < 500ms (조인 경로 탐색 지연 목표)

### Tier 3: Goal (최적 성능 상태에서 지향하는 최상위 목표)
7.  **SPARQL 캐시 히트율**: ≥ 80% (동일 대화 또는 대시보드 반복 조회 기준)
8.  **Import 중복 제거**: 100% (네트워크 중복 요청 방지 및 로컬 캐시 사용)
9.  **RDF 인덱스 효율**: ≥ 95% (쿼리 계획 수립 시 인덱스 적중 비율)

## 6. PostgreSQL vs RDF 저장소 비교

| 메트릭 | PostgreSQL (관계형/JSONB) | RDF (메모리 기반 그래프) | 성능/효율 우위 및 분석 |
| :--- | :--- | :--- | :--- |
| **SPARQL 쿼리** | 지원 불가 (SQL/JSON 파싱 필요) | < 200ms (기본 지원) | **RDF 우수** (그래프 매칭 최적화) |
| **단순 관계형 쿼리** | < 100ms (B-Tree 인덱스) | < 300ms (그래프 횡단 검색) | **PostgreSQL 우수** (특정 테이블 스캔) |
| **그래프 추적 (Hop)** | < 500ms (Recursive CTE 조인) | < 200ms (포인터 체이싱) | **RDF 우수** (다중 홉 탐색 시 조인 비용 무시 가능) |
| **메모리 효율** | 우수 (디스크 기반 캐싱) | 보통 (전체 그래프 메모리 상주) | **PostgreSQL 우수** (가용 메모리 제한 시) |
| **외부 매핑 및 확장** | 복잡 (스키마 변경/조인 필요) | 간단 (URI 링크 및 동적 트리플 추가) | **RDF 우수** (데이터 연계 및 스키마 유연성) |
