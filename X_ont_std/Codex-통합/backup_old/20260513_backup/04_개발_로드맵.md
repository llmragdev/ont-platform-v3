# 개발 로드맵

## Phase 0. 문서와 설계 고정

- 프로젝트 방향 문서
- 온톨로지 중심 요건
- 화면 기획
- API 초안
- 참조 구현 목록 정리

## Phase 1. 읽기형 온톨로지 엔진

- `backend/config/ontology.default.json`
- ObjectType/RelationshipType 로더
- 객체/관계 인스턴스 로더
- 범용 `get_object_context`
- 기본 테스트

완료 조건:
- Customer/Order/Product가 설정에서 로드된다.
- 관계 타입이 설정에서 로드된다.
- 객체 컨텍스트 API가 incoming/outgoing 관계를 반환한다.

## Phase 2. 온톨로지 관리 읽기 화면

- 온톨로지 관리 메뉴
- 개요 탭
- 객체 타입 탭
- 관계 타입 탭
- 객체 데이터 탭
- 관계 데이터 탭

완료 조건:
- 코드 수정 없이 설정 파일 변경이 화면에 반영된다.

## Phase 3. 관계 인스턴스 추가

- 관계 생성 API
- 관계 삭제 API
- 관계 데이터 관리 UI
- 검증 로직

완료 조건:
- 화면에서 새 관계를 추가하면 객체 상세와 AI 컨텍스트에 반영된다.

## Phase 4. Action Type

- `actions.default.json`
- 액션 타입 조회
- 액션 실행
- WorkflowGraph 팔레트 자동 반영

완료 조건:
- 도메인 액션 노드가 코드 하드코딩 없이 생성된다.

## Phase 5. 정책/뷰/검증

- 권한 규칙 설정화
- Object View 설정화
- Validate/Publish/Rollback
- 감사 로그

완료 조건:
- Admin이 온톨로지 변경을 검증 후 게시할 수 있다.
