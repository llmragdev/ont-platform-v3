# 01. 통합 요건 정의서 (Enterprise Hybrid RAG & Ontology)

## 1. 프로젝트 개요
본 프로젝트는 비정형 문서(PDF 등)에서 지식을 추출하여 **온톨로지(구조형 지식)**와 **벡터(비구조형 지식)**를 결합한 하이브리드 질의 시스템을 구축하는 것을 목표로 합니다. 단순히 답변을 생성하는 데모 수준을 넘어, 기업 내 실운영이 가능한 보안성, 확장성, 신뢰성을 확보합니다.

## 2. 핵심 요건 (Core Requirements)

### 2.1 멀티테넌트 및 권한 격리 (Multi-tenancy & Isolation)
- **테넌트 격리**: 모든 데이터(문서, 온톨로지, 벡터)는 `company_id`와 `project_id` 기반으로 물리적/논리적으로 격리되어야 함.
- **역할 기반 권한 제어 (RBAC)**: 
    - `Admin`: 전체 관리, 프로젝트 생성, 사용자 관리.
    - `Editor`: 문서 업로드, 온톨로지 편집, 질의.
    - `Viewer`: 단순 질의 및 조회 전용.
- **API 수준 보안**: 프론트엔드 UI 제어뿐만 아니라, 모든 백엔드 엔드포인트에서 JWT 기반의 테넌트/권한 검증 수행.

### 2.2 온톨로지 범용화 (Generic Ontology Management)
- **도메인 독립성**: `Customer`, `Order`와 같은 특정 도메인 코드를 배제하고, JSON 스키마 설정만으로 임의의 객체(Entity)와 관계(Relationship)를 생성할 수 있어야 함.
- **Dynamic CRUD**: 정의된 스키마에 따라 UI 화면과 API가 자동으로 대응하여 인스턴스를 관리할 수 있어야 함.
- **데이터 무결성**: 객체 삭제 시 연결된 관계 처리 정책(Cascade Delete 또는 Tombstone) 반영.

### 2.3 하이브리드 질의 고도화 (Advanced Hybrid Query)
- **Query Planning**: 질문을 분석하여 실행 계획(Plan)을 먼저 수립하고, LLM이 아닌 시스템 코드가 구조형 쿼리(Filter, Join, Aggr)를 실행함.
- **근거 기반 답변 (Grounding)**: 답변 생성 시 참조된 벡터 컨텍스트(문서 페이지)와 온톨로지 경로(노드/관계)를 명확히 제시함.
- **신뢰성 가드레일**: 답변의 할루시네이션 여부를 체크하고, 근거가 부족할 경우 "모름"을 반환하는 신뢰성 로직 포함.

### 2.4 운영 안정성 및 품질 (Operational Excellence)
- **통합 테스트 자동화**: API, 시나리오, E2E 테스트가 CI/CD 환경에서 자동으로 실행되어야 함.
- **관측성 (Observability)**: 모든 질의와 데이터 변경은 Audit Log로 남으며, LLM 사용량(Cost/Latency)을 추적함.

## 3. 성공 기준 (Acceptance Criteria)
1. 타 회사의 사용자가 URL 직접 호출로 다른 회사의 데이터를 조회할 수 없음 (403 반환).
2. 새로운 데이터 타입(예: 'Equipment')을 JSON에 추가하면 즉시 관리 화면에 나타남.
3. "X 회사의 2023년 총 매출은 얼마인가?"와 같은 구조형 질문에 대해 LLM이 계산 실수를 하지 않고 코드가 정확한 값을 반환함.
4. 모든 코드는 `pytest` 통과율 100%를 유지함.
