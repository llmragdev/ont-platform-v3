# Antigravity Architecture Evolution Review

작성일: 2026-05-14 00:56 KST  
작성자: Antigravity  
대상: `claud_v1_legacy` 기반 엔터프라이즈 표준화 (`X_rag_std`) 전환 전략  

## 1. 총평: "MVP의 틀을 깨고 자율형 AI 에이전트 표준으로 도약할 시점"

Codex의 `Production Readiness Review`가 운영 안정성(Reliability)과 데이터 신뢰성(Provenance)의 간극을 훌륭하게 짚어냈다면, 저(Antigravity)는 **'구조적 모듈화'**와 **'AI 자율 운영(Agentic Automation)'** 관점에서 현재의 상태와 나아갈 방향을 평가하고자 합니다.

현재 `claud_v1_legacy`는 RAG, Ontology, Workflow라는 세 가지 강력한 무기를 하나로 묶어낸 훌륭한 '단일 애플리케이션(Monolithic MVP)'입니다. 하지만 엔터프라이즈급 "표준 아키텍처"로 자리 잡기 위해서는 강하게 결합된 코드들을 분리하고, AI 에이전트가 스스로 판단하고 복구할 수 있는 '자율적 통제 시스템'으로 진화해야 합니다.

```text
현재 아키텍처: 강결합된(Tightly-coupled) 하이브리드 RAG MVP
목표 아키텍처: 모듈화된(Modular), 이벤트 기반(Event-driven)의 자율형 멀티 에이전트 플랫폼
핵심 과제: 책임의 분리(Decoupling), 선언적 인프라 구성, 자율 복구형 에이전트 루프 구축
```

## 2. Antigravity의 시각: 현재 아키텍처의 한계와 진화 방향

### 2.1 정적인 워크플로우에서 '자율적 에이전트 루프'로
현재 워크플로우는 그래프(Graph) 기반으로 잘 설계되어 있으나, 사전에 정의된 노드를 순차적으로 실행하는 **정적 파이프라인(Static Pipeline)**에 가깝습니다.

*   **한계**: 예외 상황(예: 온톨로지 추출 결과가 모호할 때)이 발생하면 파이프라인이 중단되거나 단순 에러를 반환합니다.
*   **진화 방향 (Agentic Workflow)**: 에이전트가 스스로 **Query Plan**을 세우고, 실행 결과를 평가(Self-Reflection)하여 필요시 스스로 재검색(Re-search) 하거나 다른 노드에 도움을 요청하는 **동적 루프(Dynamic Loop)**로 발전해야 합니다. 이를 위해 LangGraph나 자체 State Machine 기반의 자율 에이전트 아키텍처 표준이 필요합니다.

### 2.2 하드코딩된 로직의 '선언적(Declarative)' 전환
현재 코드의 일부는 여전히 특정 도메인 로직이나 프롬프트가 코드 레벨에 강하게 묶여 있습니다.

*   **한계**: 새로운 도메인(예: 법률 → 인사)으로 확장할 때마다 코드를 수정하고 배포해야 합니다.
*   **진화 방향 (Schema-Driven)**: 온톨로지 메타데이터뿐만 아니라, **인텐트(Intent), 프롬프트 파이프라인, 검증 규칙(Validation Rules)**까지 모두 외부화된 JSON/YAML 스키마로 관리되어야 합니다. 코드는 오직 이 스키마를 해석하고 실행하는 '범용 엔진' 역할만 수행해야 합니다.

### 2.3 단순 통합을 넘어선 'Micro-Agent' 아키텍처
RAG, 온톨로지, 권한 관리 로직이 `app/` 하위에 혼재되어 있습니다.

*   **진화 방향**: 
    1.  `Ingestion Agent` (문서 처리 및 온톨로지 추출 전담)
    2.  `Retrieval Agent` (하이브리드 검색 및 컨텍스트 구성 전담)
    3.  `Generation Agent` (환각 검증 및 최종 응답 생성 전담)
    4.  `Guardrail Agent` (권한 검증, 보안 마스킹, 데이터 출처 확인 전담)
    이처럼 역할을 세분화하고 각 에이전트 간의 명확한 인터페이스(API/Event) 표준을 정의하는 것이 이번 `X_rag_std`의 핵심 과제가 되어야 합니다.

## 3. X_rag_std 표준화를 위한 Antigravity Action Items

Codex가 제안한 데이터 모델과 운영 요건을 수용하면서, 아키텍처 레벨의 모듈화를 위해 다음 작업들을 `X_rag_std` 표준 문서 및 레퍼런스 구현에 반영할 것을 제안합니다.

1.  **AI Agent Interface Standard 제정**
    *   단일 API 호출이 아닌, 에이전트 간 비동기 메시지(또는 상태 공유) 교환 표준 정의
    *   에이전트의 입력/출력 규격에 대한 JSON Schema 표준화

2.  **프롬프트 및 컨텍스트 관리의 형상화 (Prompt as Code)**
    *   프롬프트 버저닝, 도메인별 프롬프트 분리를 위한 디렉토리 구조 및 관리 표준 수립
    *   A/B 테스트 및 평가가 가능한 구조 확보

3.  **VibeCoding 친화적 구조 마련**
    *   AI 코딩 어시스턴트(저와 같은)가 코드를 쉽게 읽고 리팩토링할 수 있도록 파일 단위의 역할 명확화 (예: `*_router.py`, `*_service.py`, `*_agent.py`의 엄격한 분리)
    *   `README.md` 및 `ARCHITECTURE.md`를 통해 AI가 시스템 컨텍스트를 즉시 파악할 수 있는 메타-문서 표준화

## 4. 결론

Codex의 검토가 **"이 시스템이 프로덕션에서 죽지 않고 돌아갈 수 있는가?"**에 대한 훌륭한 해답을 주었다면, 저의 검토는 **"이 시스템이 다양한 엔터프라이즈 환경에 얼마나 유연하게 적응하고, 확장될 수 있는가?"**에 집중했습니다.

`claud_v1_legacy`는 이미 훌륭한 기반을 다졌습니다. 이제 이 자산들을 해체하여 각각을 견고한 모듈로 재조립하고, 명확한 인터페이스와 자율적인 에이전트 흐름을 부여하여 진정한 **Enterprise AI Agent Standard (`X_rag_std`)**로 완성할 준비가 되었습니다. 함께 이 표준의 디테일(04. 운영 표준, 05. 에이전트 표준 등)을 채워나가시죠!
